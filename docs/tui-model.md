# TUI model

Pure data under `crates/workspace-status/src/tui/` (tree, fold, flatten, keymap, live refresh). The event loop is `Action` → `AppState::dispatch` → `Effect`. `tui/effect.rs` turns that `Effect` into Scheduler jobs and applies results. Autoload, commit-files, commit-diff, stash / branch / graph-focus picker, and compare-picker jobs carry a generation plus an immutable target. Compare picker uses `request_prepare_compare`, separate from `b` / `o` branch gens. Compare-file diffs keep a latest request id per tab (`CompareTab.diff_req`). Autoload captures `GraphIdentity` (repo + head) at enqueue; the others capture at spawn (`(repo, source)`, `(repo, source, path)`, or focused checkout / picker request). Apply drops a result when that gen is stale or the live drill / identity / focused checkout no longer matches, the same way a right-pane load drops a stale `req_id` or target. A right-pane Graph replace bumps the autoload generation and clears `graph_loading_older`, so a late older page cannot merge into the new window when repo+HEAD are unchanged (graph `o` / `O`). Esc Diff→Files bumps the commit-diff generation so a late result cannot reopen Diff. The live TTY loop (`tui/event_loop.rs`) spawns those jobs on a `JoinSet`.

A component that paints on more than one surface (tab kind, drill depth, pane, boxed or flat look) keeps the same features on each. [parity.md](./parity.md) lists every surface per component, the features each has, the recorded `n/a` reasons, and the open gaps.

## Node kinds

`NodeKind` in `tui/tree.rs` is a seven-member enum. Five of them are structural; `Group` and `Section` are chrome.

| Kind        | Id                           | Children                    | Notes                                                                                                                                                                                                                                                          |
| ----------- | ---------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Workspace` | `workspace` (literal)        | repos + at most one group   | Single root. Carries `change_count` and `sync_summary`. Root label is rendered as provided (natural case), not uppercased.                                                                                                                                     |
| `Repo`      | `repo:<repoPath>`            | dirs/files **or** checkouts | Flat when the primary has no linked worktrees (branch text on the same row; the hidden glyph, branch glyph, merge mark, and PR badge lead the trailing run before `ICON_REPO`). With linked worktrees → **family container**: path + trailing hidden glyph / `ICON_REPO` / `N wt` / change count; branch omitted; `merged_into_default: None`; sync is worst-of-family (a force-pushed upstream rides along with the worst member). A diverged branch whose upstream was force-pushed (`NodeChrome.upstream_rewrite`) paints its diverged mark followed by the short text ` force-pushed · N dropped, K yours` (`icons::upstream_rewrite_short_text`, so a narrow pane keeps the repo name); the sync popover shows the full `<upstream> was force-pushed · N dropped, K yours` (`icons::upstream_rewrite_text`) in its `sync` field. The watch signature includes it.                |
| `Checkout`  | `checkout:<repoPath>`        | dirs/files                  | Nested under a family container only. Primary uses `ICON_BRANCH` + branch (never `ICON_LINKED_WORKTREE`) and the merged-into-default check when HEAD is a strict ancestor of the default tip. Open-vs-default stays linked-only. Linked extras use `ICON_LINKED_WORKTREE` + branch (or short path when detached). The label ends at the branch: the merge mark (its own tagged segment, `Added` merged, `Muted` open) and the PR badge lead the right-aligned trailing run, then sync / counts; comment / viewed marks go first. Checkmark only when HEAD is a strict ancestor of the default tip; HEAD equal to that tip is open. Files live here, not on the container. |
| `Group`     | `group:no-updates` (literal) | repos                       | Holds every repo with **no** updates (clean worktree, default branch, up-to-date with upstream, no attention sync note). Only ever one, only present when at least one such repo exists.                                                                       |
| `Section`   | `section:<repoPath>:staged` / `section:<repoPath>:changes` | dirs/files for that side | Present when the checkout has any staged path (empty side omitted). `repo` is the checkout path; `file` is `None`. Paint is 1-col glyph + `Staged` / `Changes`. Not `Group` (`in_no_updates` stays false). Foldable. |
| `Dir`       | `dir:<repoPath>:<fullPath>`  | dirs/files                  | Tree mode only. Single-child chains are collapsed (`apps/web/packages/ui` as one node). Every Changes-section dir uses `dir:<repoPath>:<fullPath>#unstaged`. Staged dirs stay unsuffixed. `dir_path_from_id` strips `#unstaged` before the filesystem path. |
| `File`      | `file:<repoPath>:<path>`     | —                           | Leaf. Carries the originating `FileChange` (one git side when sections are on). MS dual rows keep this id under Staged and use `file:<repoPath>:<path>#unstaged` under Changes. Space-reviewed uses the snapshot `FileChange` (both git sides) so the mark survives reconcile; both dual ids light. |

`Group` exists so clean repos collapse into one line by default instead of padding the tree. `Section` splits a checkout's dirty files into Magit-style **Staged** then **Changes** trees when **any** path is staged. No staged paths → today's file/dir ids directly under the repo or checkout. Each section is a normal path tree (`t` still toggles tree vs flat inside it). Split `FileChange` clones keep only that side, so trailing badges are `S` / `A` / `M`, not `MS` on a split row. Anything that switches on `kind` — `node_segments`, fold walks, `has_children`, `repo_path_of` — must handle `Checkout` and `Section`. `repo_path_of` / graph drill: checkout → its path; family container → primary checkout path; file/dir/section → `repo`. Returns `None` for `Group` and `Workspace`, which is what makes `r` on either of them refresh the whole workspace. Section `r` reloads that checkout.

## Ids

Ids are stable path-derived strings, never indices. Three things depend on that:

- After a refresh the cursor is restored by id, so a new file appearing above the cursor does not shift the selection. When the focused id is hidden under a folded ancestor (typical: repo moved into folded `group:no-updates` after pull), ancestors are unfolded so the same entry stays selected. If the id is gone even after unfold (file committed/stashed, ghost expired), ancestor walk uses parent `dir:` prefixes then `repo:` / `checkout:` parsed from the id string.
- The fold set is a set of ids that survives tree rebuilds.
- `watch.rs` attributes file flashes with file node ids and op-row flashes with repo node ids. Chrome flashes walk the tree and skip file nodes — files stay on status+mtime signatures. Chrome identity includes path / branch / sync enum / **sync note** / **HEAD** / change count / fold, so a new local commit on a clean branch or ahead 2→3 is a real update (status, graph, and right pane reload without `r`). Graph and commit-file rows use separate identity maps (`{repo}#{kind}:{id}` and `{repo}#{source}#{row_id}`) so a repo switch is a new list, not a mass flash. Add/update/remove flash the same row only. Classification is `Add` (id in after only), `Update` (signature changed), or `Remove` (id in before only). Fetch / pull / push / default-branch chrome stamps `Update`. Removals keep a ghost row for the 800ms fade. Each kind uses its own four-step background ramp (`flash` / `flash_update` / `flash_remove`). Flash background wins over cursor and search. The cursor bar stays. Status letter colours stay. The live poll is due from the start of `WS_STATUS_WATCH_MS`, not after collect finishes.

## `build_tree` → flatten → `VisibleRow`

`build_tree` groups snapshots by `primary_repo` when set, otherwise `repo`. A sole primary → flat `Repo` (today). Primary + linked → family container with `Checkout` children (primary first, then linked by path). Family attention if **any** checkout needs attention; containers with linked children start **expanded**. Within each attention bucket, families sort by primary path.

The tree paints `visible_for_tree` (`visible_workspace_snapshot`). Hidden repos stay out unless `.` / `-a` shows them, or a named filter names that checkout or names the primary (linked children included, except those at or under an `ignoredPaths` entry, which discovery never returns). Hidden includes a linked worktree whose primary is under `hiddenPaths`, even when that linked row is `hidden=false`. They return with `.` / `-a` as a nested family, not a workspace-root orphan. A linked row whose primary is absent from the snapshot still paints (linked-only). A standalone hidden linked path stays hidden until shown.

A checkout needs attention when it has file changes, is not on its effective default branch (`main` / `master` / `develop`, or a sole `defaultBranches` override when configured), has a non-idle sync (`behind` / `ahead` / `diverged`), **or** has an attention sync note (`no commits yet` / `status failed`). Only default-branch checkouts that are clean, up-to-date with upstream, and free of those notes land under `group:no-updates`. Workspace `sync_summary` counts those attention notes (`N attention`) so an attention-only workspace is not reported as `all current`. Empty discovery yields `no repos` (not `all current`).

Per checkout (or flat repo), children are either flat file nodes or a directory trie (tree mode). When that checkout has any staged path, those children sit under `Section` nodes (`Staged` then `Changes`; hide empty) instead of directly under the repo or checkout.

Flatten walks depth-first, emitting a `VisibleRow` per node: `id`, `depth`, `node`, styled segments / trailing, and a plain `label` (used for pane `/` search). Children are omitted when the node's id is in `folds`.

## Fold state

Default folds: hidden repos with children + the `no-updates` group. Non-hidden repos with changes start expanded. `z` toggles immediately and arms a 400ms `zz` window. Second `z` applies that same fold to foldable descendants.

## ViewStack / Enter / Esc

`DrillView` in `tui/drill.rs` is the depth stack (`Graph` = 0, `Files` = 1, `Diff` = 2). `FocusPane` is left or right. Together they are the ViewStack.

| Depth | Left | Right |
| --- | --- | --- |
| 0, repo/dir focused | Workspace tree | Graph |
| 0, file focused | Workspace tree | Worktree `DiffPane` |
| 1 `Files` | Graph list | Commit-file tree |
| 2 `Diff` | Commit-file list + commit-details footer | Commit-scoped `DiffPane` |

`list_focus_target` (`tui/state/`) is the focused list: depth 0 left → tree; depth 0 right / depth 1 left → graph; depth 1 right / depth 2 left → commit files; depth 2 right (and depth 0 file diffs) → none (file-diff focused row). Compare left is commit files. Compare right is none (file-diff). `j`/`k`, `gg` / `G` / Home / End, fold, search, click, and vertical wheel follow that target, not a parked Workspace `drill`. The selected row on an unfocused list still paints a weaker marker (`▏` / `cursorBgInactive`); only keys follow `list_focus_target`. The viewport keeps the focused row near the vertical middle (same rule as the workspace tree). On a focused file diff, `gg` / `G` (and Home / End) move to the first / last row. On a focused commit-file list, `gg` / Home use the first file row (`commit_file_cursor_index` with no path), not flattened row 0 when that row is a directory. `G` / End stay on the last visible row. CSI-u key release does not move and does not clear the `gg` pending (`GPending`). Mouse horizontal wheel (and Shift-wheel) pans the pane under the pointer without moving the focused row. The workspace tree matches the right pane. Trackpad hscroll is SGR `66`/`67`. When a file diff has long lines, that report over the left pane pans the diff. Short tree paths still pan the tree when the painted diff fits. Click still selects. Unshifted `h` / `l` still fold the tree and a focused commit-file folder row (`AppState::hl_folds`).

| Focus / depth | Enter | Esc |
| --- | --- | --- |
| Left (any depth) | Focus right (same stack) | Pop one depth; stay on left (no-op at depth 0) |
| Right, depth 0 | Push commit files when a graph row can drill; stay on right | Unfocus → left |
| Right, depth 1 | Push commit diff; stay on right | Unfocus → left |
| Right, depth 2 (leaf) | No-op | Unfocus → left |

Enter that deepens the stack keeps **right** focus. A pinned icon popover is its own input mode, so Esc closes it before any of this (see **Icon popovers**). Esc cancels visual-line highlight (`V`) first, then an armed search. Esc that pops a depth keeps **left** focus and sets no status. Esc never quits. Right-click is the same step back (`BackClick`).

The status row's Enter / Esc chips follow this table (`chrome::nav_chrome_hint_segments`). `Enter drill` shows only when `AppState::nav_enter_drills` holds: right focus, no compare tab, and a graph commit / stash / uncommitted row at depth 0 or a commit-file (not directory) row at depth 1. Esc reads `clear` while a search is armed, `← <left pane>` from the right pane, `↑ files` / `↑ graph` when it pops depth 2 / 1, and is absent where it does nothing.

`/` saves the bound pane's cursor, scroll, and folds (`SearchOrigin`). Esc while typing (`SearchCancel`) restores them; Enter keeps them until the jump has run, then drops them. The search steps with a direction `dir`. `dir == 0` (each typing keystroke, and Enter) anchors on the `SearchOrigin` cursor and takes the first match after it, so typing recomputes from the origin and never walks on; no hit leaves the cursor at the origin. `n` / `N` anchor on the pane's active cursor row: first match strictly after (`n`) or strictly before (`N`), skipping a cursor row that is itself a match. "After" follows the pane's search order: tree flatten order including folded rows, graph visible rows, commit-file painted order including folded folders, painted diff rows (compare-tab diffs too). Past the last or first match the step wraps and sets info `search wrapped to top` (forward) or `search wrapped to bottom` (backward); landing back on the only match counts as a wrap, and no matches at all say `no match` with no wrap notice. Both notices also show on the typing line before Enter. `AppState::search_match_position` gives the `3/7` count for the armed-search pill for the landed match.

## Compare tabs

Compare is a session tab, not a `DrillView` depth and not a `NodeKind`. `tui/tabs.rs` keeps a permanent Workspace tab plus compare and Explorer tabs (`SessionTab`, see **Explorer tabs**) in one creation order with one id counter. Identity is `(checkout_path, base_ref, head_ref, worktree_file)`; `worktree_file` is set only on a commit-vs-working-tree tab (see below). `head_ref` is `HEAD` (`COMPARE_HEAD_REF`) on a live tab (Diff vs default / branch / commit), which diffs against the checkout's HEAD at each load. A full commit id pins the head (Diff commit vs parent). The same base with another head is a second tab; the same identity focuses the existing tab. The strip label is `<checkout-leaf> ↔ <base-ref>` (bidirectional arrow; left is the checkout leaf, right is the base ref). `tabs::short_rev` shortens a leading 40- or 64-hex object id to 7 chars and keeps any suffix (`abc1234^`); branch names and `HEAD` pass through. The strip label, the range header and `short_label` (`main...HEAD`, or `abc1234^...abc1234` on a pinned tab), and the empty / error copy (`No committed changes vs …`, `Base ref not found: …`, `No merge base between … and …`) use it. Workspace cannot close. Click `[✗]` on a compare tab to close that tab. Workspace never paints a close control. Close activates the tab to the left. Tabs are session-only.

A compare tab is depth 0. Left is the committed `base...head` file list. Right is `DiffPane`. There is no graph and no nesting. Opening Diff vs * from a Files or Diff drill keeps that `drill` parked for Workspace restore. Workspace park also stores that session's commit-file folds and trie mode. Each compare tab stores its own folds and trie mode. The compare tab still paints DiffPane on the right. It does not persist `drill` on the tab and does not paint the parked Files view. New tab: left focus, first file selected, that diff loads. Enter left → right. Enter right is a no-op. Tab switches panes. After overlay cancel, Esc on compare right focuses left. Esc on compare left does nothing (the tab stays; close it with the `[✗]` click or the `:` Close tab command). Esc on Workspace while a compare-picker job is in flight (picker not open yet) abandons that job so a late result cannot open the overlay.

`CommitFileSource::Compare { base_ref, head_ref, base_tip, merge_base, head }` is the immutable load key. `base_ref` and `head_ref` are the tab key; `head` is `head_ref` resolved. `Effect::LoadCompareRange` and `Effect::ProbeCompareTab` carry `head_ref`, and `compute_compare_range` / `probe_compare_range` resolve it instead of a literal `HEAD`. An unborn live HEAD is `HEAD has no commit`; a pinned head that does not resolve is `Head ref not found: <short sha>`. File list and diff reuse the commit-file / `DiffPane` paint path (`E`, `Ctrl-o`, `/`, selection, external diff). The diff section label is `COMMITTED`. `e` / `E` / `Ctrl-o` on a compare tab use that tab's committed file only. They do not fall through to a parked Workspace dirty file. Empty list or a dir row: `focus a file to edit` / `focus a file to diff`. Space marks that committed file reviewed with the workspace-tree eye. The mark lives in session-only `CompareTab.reviewed` (path → that file's patch key at mark time). The range load fills `CompareTab.patch_keys` from `list_compare_patch_keys` (blob pair, modes, status, paths). It never writes `viewed-files.json` and does not change Workspace marks. The mark paints while the file's current key equals the marked key, so new commits or a moved base that leave the file's diff unchanged keep it. A stale mark stays in the map, so a later identical diff paints it again. A listed file with no key cannot be marked. Empty list or a dir row: `focus a file to mark reviewed`.

Palette commands (Quick Open commands only: `:`, or `>` first in files mode; the four Diff rows and Shorter / Taller commit message paint no key chip, Close tab paints `Ctrl-w`): Diff vs default in new tab, Diff vs branch in new tab…, Diff vs commit in new tab…, Diff commit vs parent in new tab, Close tab. The filters `vs default`, `vs branch`, `vs commit`, `vs parent`, `new tab`, and the alias `compare` find the open rows. Concrete checkout for Diff vs default / branch / commit: flat repo / checkout / section / dir / file, or the checkout that owns the active graph / drill, or the active compare tab. Not Workspace, No-updates, or a family container. Unborn HEAD disables all three. Missing default disables Diff vs default. Diff commit vs parent needs the graph pane to focus a commit row (`AppState::graph_commit_focused`); uncommitted, stash, and worktree rows, the tree, and a compare tab refuse with `focus a commit to diff`. A root commit refuses with `root commit has no parent`. It opens `<sha>^...<sha>` with the head pinned to `<sha>` on the repo that owns the loaded graph (the repo graph `b` / `m` act on), labelled `<checkout-leaf> ↔ abc1234^`. `^` is the first parent, so a merge shows its changes against its first parent. It never checks anything out and does not change Enter or the commit drill. One gate, `AppState::compare_refusal` (`tui/state/dispatch.rs`), refuses on dispatch and in the palette with the same copy. It checks the open commands above on every tab first, then refuses compare-tab actions. Stage and Unstage (whole file or highlighted lines) show `cannot stage a compare diff` / `cannot unstage a compare diff`. Fetch / pull / push, default branch, branch actions (including `BranchSubmit`, which also runs the picker create row), create-branch, the stash menu, graph writes and graph focus, and worktree remove show `Switch to Workspace tab`. `x` (whole file, or highlighted lines) reverts to the compare **merge base** in the worktree, and runs only while `AppState::compare_revert_target` holds: the tab and the open diff are loaded for the current range and path (`CompareTab::loaded_diff_path`, keyed by `CompareTab.content_for`, because `tab.path` moves when a diff load is queued), the snapshot HEAD of the checkout equals the compare head, and neither the file nor a rename's old path has a change against HEAD. A tab with a pinned head refuses first with `cannot revert a committed diff`. Otherwise `x` and both palette Revert rows show that reason (`compare diff still loading`, `compare is stale: HEAD moved`, `<path> has uncommitted changes`, `focus a file to revert`). Whole-file `x`, its hint chip, and the palette Revert row also refuse a status other than `M` / `A` / `D` / `R` (`cannot revert a <status> change`, `AppState::compare_file_revert_refusal`). Compare `x` also runs from the focused diff with no highlight (the open file), which Workspace `x` does not. It opens `PendingConfirm::CompareRevertRange` or `CompareRevertFile` (`y` confirms, Enter names the key that does, `n` / Esc cancels, `Y` keeps it open). Confirm `y` / `Y` on a compare tab accept only those compare-owned variants; any other pending confirm shows `Switch to Workspace tab`. A compare confirm that somehow reaches another tab is cancelled, not run. `y` emits `Effect::CompareRevertPatch` or `Effect::CompareRevertFile`; the write worker checks HEAD and cleanliness again with git before it writes (see [git-operations.md](./git-operations.md)). The compare diff does not change; the status points to the Workspace tab. The hint row on a compare tab reads the compare tab, not the parked Workspace tree row. Outside highlight it can show only `x` / `e` / `space` / `Ctrl-o` (`COMPARE_HINT_ACTIONS` in `tui/chrome.rs`), and `x revert to merge base` only while `AppState::compare_file_revert_refusal` is `None` (the compare gate, then a file status of `M` / `A` / `D` / `R`). The VISUAL row drops `s u` and shows `x revert to merge base` only while `AppState::highlight_revert_refusal` is `None`. `V` visual highlight, copy entity reference (`'`, with the range while highlighted), line comments (`;`, overlay Ctrl-r resolve), and comment export (`y`) are allowed and act on the compare tab's own file (see the comment paragraph below). Switching or closing a tab (keys, palette, or a mouse click on the strip) clears the visual highlight and any pending confirm, so neither follows onto another tab's diff. A late Workspace branch-picker or stash-menu prepare that finishes after a tab switch does not open.

`GPending` before `normal_key`: `g` → `MoveToStart`, `t` → `NextTab`, `T` → `PreviousTab`, `1`…`9` → `JumpToTab` (`1` is Workspace), `x` → `OpenPullRequest`, `w` → `ViewRemotely` (no Ctrl / Alt / Super / Hyper / Meta; those fall through to `normal_key`), Esc no-op. Bare `t` stays tree/flat. Bare `T` does nothing. Bare `x` stays revert. Bare `w` does nothing. `gg` stays start. Watch ticks, mouse move (`None`), and key Release do not clear `GPending`. A typeless CSI-u Press of the same `g` / `t` / `T` / `1`–`9` key inside a few milliseconds (`G_CHORD_PROTOCOL_ECHO_MS`) is the release of that tap and is dropped. VTE often reports that release as Press when event types are missing. A later typeless `g` (one CSI-u per tap), including a fast human `gg` under 80ms, completes `gg`. A completing `g` does not eat the next `g` of `gt` after that burst. A raw-byte second `g` also completes `gg`. When the `g` pending expires, the echo for that arming `g` is cleared. A real Release also clears the echo. That keeps `gt` / `gT` as tab actions on compare tabs. Tab actions are `BusyAction::Handle`. Bare `t` on a compare tab toggles that tab's commit-file trie and keeps the focused file row. It does not change the parked Workspace trie.

The compare picker is `InputMode::ComparePicker` (`AppState.compare_picker`, a `tabs::ComparePickerState`). Diff vs branch lists local + `origin/*`. It drops `origin/HEAD` and the current local branch. Empty copy is `No branches to compare` (no branches) or `no branch matches <filter>`. Diff vs commit lists HEAD's ancestors newest first, HEAD excluded, including merge-side ancestors, capped at the 10,000 newest (`git::COMPARE_PICKER_COMMIT_LIMIT`). Its title reads `Compare vs commit <checkout>`; rows paint `<short sha>  <subject>`. The filter is a case-insensitive substring of the full sha, short sha, or subject. Empty copy is `No commits to compare` (no ancestors, for example a root HEAD) or `no commit matches <filter>`. Enter opens or focuses a live tab with `base_ref` = the picked full sha and `head_ref` = `HEAD`, labelled `<checkout-leaf> ↔ abc1234`. Both kinds share the one overlay and its key rule (printable keys filter; ↑/↓, Ctrl-n / Ctrl-p, Ctrl-j / Ctrl-k move; Backspace edits; Enter submits). No create, checkout, or fetch. Esc sets `compare cancelled` (info). `Effect::PrepareComparePicker` carries the kind (`ComparePickerKind`); both kinds share `request_prepare_compare`, so a newer request drops an older result of either kind. Apply also requires `compare_picker_pending` to still match that checkout.

A commit-vs-working-tree tab (`Blame: diff commit to working tree`) diffs one file at a commit against that file on disk now. `CompareTab.worktree_file` (`tabs::WorktreeFile { path, old_path }`: the path on disk, and the path at the commit when it differs) is part of the identity, so it never shares a tab with Diff vs commit's `<sha>...HEAD`. `base_ref` is the full commit id and `head_ref` stays `HEAD`; no revision stands for the working tree. The strip label is `<file-leaf> ↔ abc1234` (the file name); the range header reads `abc1234 ↔ working tree` and `short_label` `abc1234 vs working tree`. The range job (`Effect::LoadCompareRange` copies the tab's file into it) runs `compute_worktree_compare_range`: resolve the base (`Base ref not found: …`), then list the one path into `CommitFileSource::CommitVsWorktree { base, path, old_path }`. The diff runs `git diff -M <base> -- [<old>] <path>`, and its section label is `WORKING TREE` (`DiffContent.vs_worktree`). Empty copy is `No changes` / `No changes vs abc1234`. Refusals, on a key and in the palette alike: `x` shows `cannot revert a working-tree compare` (first in `compare_revert_target`); Space shows `reviewed marks need a commit range`; `;`, `'`, `y`, and `E` show `not available on a working-tree compare` (`compare_refusal`); stage / unstage refuse as on every compare tab, and `build_partial_patch` refuses the section as a backstop. Line comments do not paint (the source has no line commit). The HEAD probe below skips this tab. Instead, each checkout status load calls `AppState::worktree_compare_reload` for the active tab of that checkout. It builds a stamp from loaded state only: the checkout HEAD, plus the snapshot change row and tree row signature (status, size, mtime) of the path and old path. When the stamp differs from the one stored at open or at the last reload, it reloads the range with `LoadCompareRange` (forced), so the file row follows the disk; the range apply keeps the open path and reloads its diff in place (viewport kept). Only the active tab reloads on a status load; a tab that becomes active again (tab switch, or the blame action focusing it) runs the same check. `E` has no LEFT / RIGHT pair here (`external_diff_kind` is `None`). No git runs on the event thread.

A background probe reloads a compare tab only when that tab already recorded both SHAs and the head or the base-tip SHA then changed. The probe resolves the tab's `head_ref`, so a pinned tab (head `<sha>`, base `<sha>^`) never reloads when HEAD moves. Missing SHAs (first load) and tabs still `loading` are not a change. Dirty-only ticks do not reload. **Refresh** forces. Apply is generation-safe and does not steal focus. A late compare-file diff whose request id is not that tab's latest is dropped. Queueing a file diff records that path on the tab so a return trip queues a new request. Workspace pane loads (`LoadRightPane`, graph autoload, commit-files apply) do not run while a compare tab is active. Write and merge completion do not recapture the right pane. Parked Workspace `drill` / graph stay until the Workspace tab is active again.

Left-pane `j`/`k`, click, vertical wheel, and search next/prev load the matching right pane through `Effect::LoadRightPane` (TTY: `spawn_blocking` + coalesced request id). Mouse horizontal wheel over the workspace tree pans without `LoadRightPane` (SGR `66`/`67`). Depth 1 graph rows load that commit / stash / worktree's files. Depth 2 file rows load that file's commit diff. A depth-2 or compare-tab directory row shows a folder summary in the right pane: every changed file under that folder (files under folded subfolders too), each with its status badge and `+added −deleted` line counts. Moving onto a file loads its diff. The file that was open before repaints with no reload. While a folder summary shows, keys that act on a file diff refuse with their existing copy (`e`, `E`, `Ctrl-o`, `V`, space, stage / unstage / revert, right-pane `;` / `'` / `y`). A background reload, or a right-pane `j` / `k` or `gg` / `G`, behind the summary resets the hidden diff to its first row. Esc/back and the depth stack stay unchanged. A focused-repo watch/status result that changes checkout or file identity enqueues `LoadRightPane` immediately — it does not wait for the rest of the workspace.

## Explorer tabs

An Explorer tab is the third tab kind (`SessionTab::Explorer`, `tabs::ExplorerTab`): a VS Code-style file tree of one checkout beside the files open in it, as inner file tabs (see **Inner file tabs**). It is the only place a file opens: there is no top-level file tab. Identity is the checkout (the snapshot `repo` string): one Explorer tab per checkout (`TabStrip::open_or_focus_explorer`). It shares the strip, creation order, and id counter with compare tabs. The strip label is `Explorer · <checkout leaf>`; the tree pane title is the checkout path.

`-` (`Action::ExplorerReveal`) opens it. On the Workspace tab with the tree focused and a focused row that belongs to a checkout, `-` opens or focuses that checkout's Explorer tab (`AppState::open_explorer_tab`). The checkout is `focused_checkout_path`, the Quick Open rule: a family's repo row is its primary checkout, a linked worktree row (or a row under it) is that worktree. A file row expands its parent folders and puts the cursor on the file (`ExplorerTree::reveal`); a folder row expands that folder with the cursor on it; a repo, checkout, or section row opens at the root. On a reused tab, a folder on the path whose cached listing lacks the next step (a file or folder created since it was listed) lists again (`ExplorerTree::stale_on_path`); the cursor waits on the target and lands on it when that listing arrives. `-` previews the revealed file (it does not pin it). One gate, `AppState::explorer_open_target`, decides: any tab but Workspace (a compare or Explorer tab) refuses with `Switch to Workspace tab`; on the Workspace tab, a pane other than the tree, or a workspace or group row, refuses with `focus a checkout, folder, or file in the tree` (`tabs::FOCUS_A_TREE_ROW_TO_EXPLORE`). A refusal is a warning on the status line; `-` never resizes the commit message. The Open in Explorer palette row (`-` chip, MOVE, `NoHighlight`) runs the same action, and `palette_disabled_reason` checks that gate first on every tab, so the row shows the same copy; on an Explorer tab it is off with `Switch to Workspace tab`, because `-` there is the parent folder. On an Explorer tab `-` moves the cursor to the parent folder (`ExplorerTree::cursor_to_parent`); it never opens a second tab.

The tree (`tui/explorer.rs`, `ExplorerTree`) lists a folder only when it is expanded (at first only the root). Each listing is `Effect::LoadExplorerDir { tab_id, req, repo, rel_dir, parent_ignored }` on the blocking pool (`UserTag::QuickOpen` → `explorer::list_dir`: `read_dir` plus one `git check-ignore -z --stdin` for the folder's children; a folder under an ignored folder skips git). It lands through `AppState::apply_explorer_dir`, which drops it unless `req` is the folder's newest request on the tab (`ExplorerTab::dir_reqs`); a read error lists the folder empty and says why. Ignored entries (`node_modules/`, `target/`, `.next/`, …) are always listed and paint dim; there is no `.` toggle. `file_index` is not used (it drops ignored paths). Status letters and folder marks come from the live snapshot's `changes` for the checkout at paint time (`AppState::explorer_status` → `ExplorerStatus::from_changes`), so they follow every status reload; files that git reports deleted still show as rows. The index is memoized per checkout and a fingerprint of its changes, and paint walks the rows once per frame (the breadcrumb reads the painted cursor row, `ExplorerTab::painted_rel`). Listings follow new status paths on the watch poll: after each checkout status load (`AppState::explorer_status_relist`, next to the inner file live reload), every Explorer tab of that checkout lists again each open, visible folder whose cached listing lacks a path the status now reports (a new untracked file or folder; deleted paths are skipped, since they already merge in). A folder with a listing in flight is not asked twice, and a status path that sent a re-list sends no other while it stays in the status (`ExplorerTab::status_relisted`); only the path that first finds a folder stale is marked, so many new files in one folder send one listing and mark one path. A poll with nothing new sends nothing, and the check is linear in the status (set lookups against each listing's name index) and skipped entirely when the checkout has no Explorer tab. The cursor keeps its rel.

Both panes go through the shared pane chrome (`render::draw_pane_chrome`): boxed with `viewDefaults.background` `"terminal"`, flat in paint mode (tree on `sidebar`, file pane on `surface`, focus shown by the title row's rule colour). `LayoutHit.explorer_tree` / `explorer_preview` hold the content rects (the file pane's rect starts under the inner tab row). Clicks and the wheel use the full-width `explorer_tree_rows` / `explorer_preview_rows` rects (pad cells included); text selection uses the content rects.

### Inner file tabs

The right pane holds the tab's open files (`ExplorerTab::files`, `tabs::InnerFile`, in paint order) and paints the active one (`ExplorerTab::active_file`; `None` exactly when `files` is empty). `render::draw_explorer_file_tabs` paints one tab row on the first row of the right pane: each file name between blanks, `│` between tabs, the active one in the top strip's active style, the preview tab italic and dim, and the strip's `‹n` / `n›` overflow markers. A click on that row does nothing. Under it a changed file paints its worktree diff through the diff pane (pane title `diff`), and a clean file its body (`read_text_file`, 2 MiB cap; text, binary notice, or too-large notice; pane title the file path). With no inner tab the title is `preview`, and a folder cursor row shows a short folder hint.

VS Code preview rules (`AppState::explorer_sync_preview` → `explorer_show_file`):

- A tree move onto a file (`j` / `k`, page and edge moves, a click, a `/` hit, the `-` reveal) shows it as the preview tab. There is at most one preview tab (`InnerFile::pinned == false`). A file that is already an inner tab (pinned or the preview) is shown again, with no reload and no duplicate. Otherwise the preview tab is replaced in place, or, with none, a new one goes right after the active tab.
- A folder row, or a cursor row whose listing has not landed yet (the stored cursor rel is not the resolved row), changes nothing: the tabs and the right pane stay as they are.
- Enter on a file pins it (a kept tab). An explicit open from another tab also pins: Quick Open files mode and a search-in-files hit call `AppState::open_file_in_explorer`, which opens or focuses that checkout's Explorer tab, reveals the file in the tree (cosmetic: the pin does not wait for the listing), and pins it as an inner tab (an existing preview of it is promoted). A search-in-files hit sets `InnerFile::pending_line`; when the load lands, a clean file puts its line cursor on that line and a changed file its diff cursor on the row whose new line number is that line (the unstaged section first, then staged), and the query arms `n` / `N` there.
- After a preview or a pin (a tree move, Enter, `-`), focus stays on the tree. An explicit open (`open_file_in_explorer`: Quick Open files mode, a search-in-files hit) focuses the file pane, from any tab and also when the file is already an inner tab; the focus is parked with the tab (`focus_preview`) like a Tab to it. Tab (or a click in the file pane) focuses the file.
- `[` / `]` (`Action::PreviousFileTab` / `NextFileTab`, also palette rows) activate the previous / next inner tab, wrapping, and reveal and select that file in the tree. They do not change which tab is the preview. Off an Explorer tab they warn `[ ] switch Explorer file tabs`; with no inner tab, `no file tabs open`.
- `Ctrl-w` (`Action::CloseTab`, also the palette Close tab row and `:`) closes the active inner tab first, preview or pinned; the neighbour to the left (else the first tab) becomes active and is revealed in the tree. With no inner tab left it closes the Explorer tab. The `[✗]` on the top strip always closes the whole Explorer tab.

A changed file always loads with `FULL_DIFF_CONTEXT_LINES` (`Effect::LoadExplorerPreview { change: Some(..) }` → `diff::load_file_diff`): the whole file, with added and removed lines inline, as if `Ctrl-o` were always on (the diff header shows the full-context marker). A clean file loads its body (`change: None`). Each load takes a new generation from the tab-wide `ExplorerTab::preview_gen` into `InnerFile::gen`; a clean view also stores it as `FileTab::generation`. `AppState::apply_explorer_preview` finds the inner tab by generation and drops a result for a closed tab, a replaced or reloaded load, or the other body kind. The interpreter queue (`effect.rs`) drops queued loads no inner tab waits for, then replaces a queued load of the same `(tab, path)` or appends: a held `j` reads only the last file, and a pinned tab's queued load still runs.

Switching the active inner tab parks the live `diff_cursor` / `diff_scroll` / `diff_col_offset` in the old `InnerFile` and loads the new tab's values; a clean view keeps its own cursor, scroll, and pan in its `FileTab`. It also clears a `V` highlight and a `File` / `Diff` search (a tree search stays).

Live reload (`AppState::explorer_live_reload`): each load records `InnerFile::stamp`, the file's disk token (`size:mtimeMs`, or `gone`; one `stat`, no git) plus its snapshot change. After each checkout status load of the watch poll, when an Explorer tab becomes active, when an open inner tab shows again (`[` / `]`, Ctrl-w, a tree move onto it, Quick Open), and when a TTY editor returns from that file, the active inner tab of the active Explorer tab compares its stamp and loads again only when it moved. Background tabs are not checked. A reload of the same kind is silent: the old content stays painted until the new load lands, and a failed read keeps it. A file that turned changed (or clean) swaps to a loading view of the other kind and resets its viewport. A deleted file keeps the last content and warns `file deleted`. While an overlay holds input (`overlay_blocks_background_ticks`), nothing is checked or recorded, so the next poll catches the change. A save that keeps both the size and the millisecond mtime is missed, on the poll and on the editor return alike. `r` always reloads the active inner tab (new generation; a clean view keeps its line cursor, a diff starts at the top).

### Session state, keys, and refusals

Session state: the tree (expanded set, listings, cursor), `dir_reqs`, the inner file tabs (with the active one's parked diff view), `tree_scroll`, the parked pane focus (`focus_preview`), and the parked `/` search, saved by `park_active_session` and restored by `apply_active_session`. Tabs are session-only (`persist.rs` stores only the comment and reviewed stores). It never writes or takes the Workspace park. `/` binds `SearchPane::ExplorerTree` with the tree focused (listed rows, matched by name; a hit moves the cursor and previews like a tree move; Esc restores the cursor), else the active inner file's `File` / `Diff` pane. The `/` state is parked on the tab (`ExplorerTab::search`) and restored on activation. A search step that leaves the cursor where it was opens no preview. `zz` matches the folder's subtree to the folder: closed collapses every open descendant, open expands cached descendants and lists the next level. Quick Open and search in files (`Ctrl-p` / `F` / `:` / `Ctrl-f`) scope to its checkout (`quick_open_scope`).

Keys (`AppState::dispatch_explorer_tab`): in the tree `j` / `k`, PgUp / PgDn, Ctrl-u / Ctrl-d, `gg` / `G`, Home / End move the cursor (placeholder rows are skipped); `l` opens a folder; `h` closes an open folder, and on a file or a closed folder jumps to the parent folder (a root-level row stays); Enter (or `z`) opens or closes a folder, and Enter on a file pins it; `[` / `]` and `Ctrl-w` act on the inner tabs; Tab switches panes. In the file pane the same move keys move the diff cursor or the file line cursor, Shift-←/→ and the horizontal wheel pan (not while `\` wrap is on), and `h` or a right click give focus back to the tree. Esc first clears an armed search, then gives focus back to the tree. `r` re-lists the visible open folders (`ExplorerTree::invalidate`; the old rows stay until the new listing lands) and reloads the active inner file. `e` opens a file in the editor: with the file pane focused, the active inner file (at the line cursor of a text body, or the new-side line of the diff cursor row); with the tree focused, the tree's file row (at the line cursor when it is the active inner file; a folder says `focus a file to edit`). When a TTY editor returns, the live-reload check runs on the active inner file (`AppState::reload_explorer_after_edit`): a save reloads it quietly and keeps the painted view and the file or diff cursor, and an exit without a save reloads nothing. `'` copies a file entity reference (the active inner file with the file pane focused, else the tree's file row; a focused inner diff copies its line reference and a `V` range on a clean file its line span). `\` and `i` act on the file pane. Mouse: a click on a tree row moves the cursor there and previews it (a folder also opens or closes), a click in the file pane focuses it, and the wheel moves the cursor of the pane under the pointer; nothing reaches the hidden Workspace tree. `<` / `>` resize the tree (the shared `tree_fraction`). `t`, `.`, `M` warn `Switch to Workspace tab`. `[✗]` closes the Explorer tab; `Ctrl-w` and `:` Close tab close it once no inner tab is left. Closing activates the tab to the left.

Refusals (`AppState::explorer_tab_refusal`, checked first in `dispatch` and in `palette_disabled_reason`): stage, unstage, revert (`s` / `u` / `x`), stash, fetch / pull / push / default branch, branch and worktree writes, graph actions, the Diff … in new tab commands, and `y` / `Y` on a late confirm warn `Explorer tab is read-only · switch to Workspace tab`. `Ctrl-o` warns `Explorer diffs always show the whole file` and never changes `full_context`. The Workspace view rows (Flat / tree, Show hidden, commit message rows) refuse with `Switch to Workspace tab`, on a key press and in the palette; Narrow / Widen tree, Search, and Fold subtree run. The file keys act on the active inner file, never the parked Workspace row: space toggles the reviewed mark of a changed file (`toggle_viewed_for`), `E` opens a changed file's worktree diff in the diff tool, `y` exports the file's comments; these three work with either pane focused, and space and `E` on a clean file warn `focus a file to mark reviewed` / `focus a file to diff`. `list_focus_target` is `None` while the right pane has focus and an inner file shows, else `Tree`; there `;` comments the cursor line as a `WorktreeLine` (a File view's `V` anchor is a file line index, and a clean file paints the comment mark in its always-reserved gutter column), line blame shows on the cursor line (on by default, as on the Workspace diff; `B` toggles it), and `A` runs the blame actions. With the tree focused, `;`, `V`, and the blame actions warn `Tab to the file pane first`.

## App state

`AppState` in `tui/state/` holds restorable view state: cursor row id, folds, filter, diff mode (`viewDefaults` seed the launch values of `tree_mode`, `commit_tree_mode`, `diff_mode`, `diff_wrap`, `commit_msg_expand`, `commit_msg_lines`, `line_blame`, and `background` once in `AppState::apply_view_defaults`, called from `run_tui` after `AppState::new`; `commit_tree_mode` is also kept as `TabStrip::commit_tree_default`, the mode each new compare tab opens in; toggles never write them back), `diff_wrap` (`\` soft word-wrap on file diffs; on by default, `viewDefaults.wrap` sets the launch state; the toggle changes this session only and nothing writes a pref file), `commit_msg_expand` (on by default, `viewDefaults.commitMessage` sets the launch state; session toggle only: the selected commit / stash message wraps in the graph footer and commit-files footer; `M` collapses; graph list rows stay one line), `commit_msg_lines` (N, the fixed message rows of the expanded graph footer and commit-files footer; default `COMMIT_MSG_LINES_DEFAULT` (4), clamped to 1–20; the Shorter / Taller commit message palette rows (`Action::ResizeCommitMsg`; no key, `+` and `=` are unbound) change it for this session only with status `msg lines <N>` and save nothing; a mouse drag of the graph footer's top rule (`SplitDrag::CommitMsg`) changes it with the same status and saves it on release (see **Resize-edge hover**); `M` and a change of N re-run `sync_graph_scroll` so the focused graph row stays in view), `line_blame` (`LineBlameState`: the `B` toggle, on by default, `viewDefaults.lineBlame` sets the launch state, session only; plus a cache of focused-line blame answers keyed by `BlameKey` (checkout, revision, path, line, content epoch), capped at 512 entries and cleared when the toggle goes off) and `commit_msg_scroll` (wheel over an overflowing graph footer or depth-2 commit-files footer; one entry keyed by graph row identity, so another commit starts at the top and the last-scrolled commit keeps its offset, the same in both footers), full-context ids, tree mode, mouse enabled, theme, `background` (`BackgroundMode` in `tui/theme.rs`: `Paint`, the launch default, fills panes and chrome rows with theme colours; cleared by any press, a splitter drag, a modal open, `m`, and resize). The file-diff viewport (`diff_cursor` / `diff_scroll` / `diff_col_offset`) belongs to one view identity: a workspace `repo`+`path`, or a commit `repo`+source+`path`. A new identity resets those fields to the origin and clears highlight. A same-view reload keeps the viewport. Highlight also drops when the painted row list changes (watch reload, split/inline, resize). Graph window default is 300. Graph branch focus (`o` / `O`) is session-only (`graph_branch_focus`): a per-repo list of local names whose ancestors the graph shows, or `None` for `--all`. Fold, split ratios, pan offsets, graph focus, Quick Open, and search in files reset on the next launch. Tree mode, diff mode, diff wrap, and commit-message expand return to their `viewDefaults` (or in-app) values; commit-message rows do too unless a footer-rule drag saved them. The theme, the activity sparkline, and the commit-message rows a footer-rule drag set persist in `ui-state.json` (`tui/ui_state_store.rs`, `WS_STATUS_UI_STORE` overrides): `AppState::set_theme` (`Action::SetTheme`, Enter on a palette `Theme: <name>` row) saves the theme; a failed save sets `theme save failed` plus a short IO error and keeps the new theme. `AppState::activity_sparkline` (off by default) is the paint switch; palette `Toggle activity sparkline` (`Action::ToggleActivitySparkline`) flips it, saves it at once, and on a failed save sets `sparkline save failed` plus a short IO error and keeps the flip. `AppState::finish_commit_msg_drag` (the release of a footer-rule drag) saves `commitMessageLines` when the rows differ from the press; a failed save sets `commit message lines save failed` plus a short IO error and keeps the rows. Like the theme and sparkline saves, it is one small locked file write from the reducer, not an `Effect`. Each save changes only its own field. A saved `commitMessageLines` that is not an integer from 1 to 20 loads as not saved and does not stop the theme or sparkline from loading (`StoreFile` reads that key as a raw JSON value and `load_ui_state` checks it); a save of another key keeps it as is. A palette preview never saves. Reviewed marks persist in `viewed-files.json`. Line and object comments persist in `comments.json` (`tui/comments/`, `WS_STATUS_COMMENT_STORE` overrides). Version 2 namespaces both files by workspace identity (SHA-256 hex of the canonical cwd). GC and save replace only the current workspace bucket. A version-1 file keeps its records under `__legacy__`. Load uses that map when the current workspace bucket is missing. GC of one cwd does not drop `__legacy__`. A missing store file starts empty. A present file that is not valid v1/v2 UTF-8 JSON is left unchanged and persist returns an error. A failed persist sets `comment save failed` or `viewed save failed` plus a short IO error on the breadcrumb trailing slot (never `comment saved` / `comment deleted`). Refresh GC uses snapshot `local_branches` and checkout paths (no git on apply or `;`). A primary detached HEAD is a worktree path key, not `HEAD (detached)` as a branch. Commit comments stay while that repo identity is still in the snapshot. Branch and working-tree line comments stay when `git status` fails (`status failed`, empty `local_branches`) only if every checkout of that identity has an empty counted list. A successful sibling's live names win. The GitHub Release startup prompt (`update_check.rs`) runs in the CLI **before** `AppState` exists; it is not session state. `status` is a `StatusMessage` (`tui/status.rs`): text plus a `StatusKind` (info / progress / ok / warn / error) that picks the color and the expiry (info / ok clear after `STATUS_TTL_MS`; the others stay until replaced). `toasts` (`ToastStack` in `tui/toast.rs`) holds the one-shot acks painted bottom-right: `draw()` first calls `AppState::route_ack_to_toast`, which moves an ok `status` into a new toast and clears the slot, unless an overlay paints `status` as its own row (`status_uses_status_text`). Dispatch therefore still sets `StatusMessage::ok(…)`, and a state test that reads `status` right after dispatch still sees the ack. A toast lives `TOAST_TTL_MS` (2500 ms), fades in its last `TOAST_FADE_MS` (= `FLASH_MS`), and the stack keeps the newest `TOAST_MAX` (3). A plain `String` / `&str` assigned to it is info. A note that a reload or background job writes goes through `StatusMessage::offer_info`, which leaves a progress / warn / error in place. Set a refusal with `StatusMessage::warn(…)` and a git or IO failure with `StatusMessage::error(…)`. `remote_activity` (`tui/anim.rs` `RemoteActivity`) is a read-only copy of the remote queue for paint: `running` (checkouts with a fetch / pull / push in flight; their rows spin) and `batch` (`BatchProgress` done / total / failed of a key-started wave over two or more repos; `None` for one repo and for the background fetch tick). The interpreter rewrites it after each spawn and each applied result. `anim_epoch` (set at launch) is the spinner clock: every spinner frame counts from it. `no_color` comes from `NO_COLOR` (`Settings::no_color`) and only the new visuals read it. `undercurl` (`Settings::undercurl`, resolved once at launch) turns the curly-underline writer on. `smooth_scroll` (`Settings::smooth_scroll`) gates the Ctrl-d / Ctrl-u glide, `scroll_glide` holds the live glide (see the Ctrl-d / Ctrl-u paragraph below), and `frame_now` is the clock of the frame being drawn, so one frame uses one instant (`draw_at` pins it in render tests). `activity` (`HashMap<String, [u32; 14]>`, `tui/activity.rs`) holds the commit counts per day of the last 14 days (today last) for each repo row's sparkline, keyed by the primary checkout path (`row_activity_key`). It starts empty, so the first frame paints no bars; the interpreter fills it from the `JobOutcome::Activity` of the low-priority `Effect::LoadActivity` worker jobs, one per repo (queued only while `activity_sparkline` is on: after the first frame, after a Pull wave for the repos it touched, when a full reload `r` lands, and for every repo when the toggle turns it on) and never runs git for it on the loop thread.

Full-context membership means unlimited unified context (`FULL_DIFF_CONTEXT_LINES`) for that file id — toggled by `Ctrl-o`, cleared by `Esc` or a second `Ctrl-o`. After a full-file toggle, scroll recenters on the prior hunk/change anchor.

Current-line blame (`B`) asks git only for a focused line: the cursor line of an Explorer file with the file pane focused, or the focused file-diff row while the right pane drives the diff (`ListFocusTarget::None`, no folder summary). Moves in the tree, graph, or file lists never blame. `AppState::line_blame_want` (`tui/state/line_blame.rs`) maps that line to a `BlameKey` per surface: a worktree diff context line blames the working tree, a deleted line in UNSTAGED the index (or `HEAD` when nothing is staged), a STAGED context or deleted line `HEAD`; an added line reads `You · uncommitted` / `You · staged` with no git call; NEW asks nothing. A commit drill blames the commit (new side) or `<sha>^` under the old path (deleted line); a stash `stash@{n}` / `stash@{n}^1`; a compare tab its head / merge base; a commit-vs-working-tree tab the working tree (new side) or the base commit under the file's path there (deleted line). The interpreter reads that key after every `schedule` and `apply` (`Interpreter::maybe_queue_line_blame`). A cache hit runs nothing. Otherwise the key goes into a latest-only slot and one `UserTag::LineBlame` job runs `git blame` on the blocking pool. While it runs, more cursor moves only replace the slot; the apply fills the cache for its key, marks a paint only when that key is still focused, and the hook then asks for the newest line. So at most one job is in flight and one waits. Toggling off clears the cache and drops late answers.

Blame actions (palette GIT rows, right before the Diff … in new tab rows; no key chip): `Blame: open commit changes` (`Action::BlameCommitVsParent`), `Blame: open previous line change` (`BlamePreviousChange`), `Blame: diff commit to working tree` (`BlameCommitVsWorktree`), and `Blame: show commit in graph` (`BlameRevealGraph`). They act on the focused line's cached blame and run on the Workspace, compare, and Explorer tabs (on an Explorer tab with the tree focused they warn `Tab to the file pane first`). One gate, `AppState::blame_refusal` (`tui/state/line_blame.rs`), refuses on dispatch (next to `compare_refusal`) and in `palette_disabled_reason` with the same copy: `line blame is off (B)`, `focus a diff or file line`, `line blame still loading` (no answer yet, or the Explorer file is still loading), `line is not committed yet` (a `You · uncommitted` / `You · staged` line, or an all-zero sha), `no blame for this line` (git had none: untracked, binary, hunk header, failed run). Open commit changes opens or focuses the pinned `<sha>^...<sha>` compare tab through the same `open_compare_tab` as Diff commit vs parent, in the surface's checkout; a root (`boundary`) commit refuses with `root commit has no parent`. It never checks anything out. Diff commit to working tree opens or focuses the commit-vs-working-tree tab (see **Compare tabs**) of the blame commit in the surface's checkout: the old path is the line's `filename` at that commit, the disk path is the Explorer file's path or the open diff's path. A root commit is allowed. Open previous line change emits `Effect::LoadBlamePrevious` with a session generation (`finding previous change…`); the interpreter keeps the latest request in one slot on `UserTag::Prepare` and runs `git::previous_line_change` on the blocking pool. `AppState::apply_blame_previous` drops a stale generation. An earlier commit opens its own pinned `<prev>^...<prev>` tab and the apply returns that tab's `LoadCompareRange`, which the interpreter schedules. A line the commit added warns `line was added in abc1234`; an earlier change in a root commit warns `earlier change abc1234 is the root commit`. Show commit in graph goes to the Workspace tab, leaves a commit drill (`drill = Graph`, `Effect::DropCommitDiff`), puts the tree cursor on the checkout's `checkout:` (else `repo:`) row with its ancestors unfolded, focuses the graph pane, and loads it (`LoadRightPane`) unless the action ran on the Workspace tab with that repo's graph already loaded and the cursor there. From a compare or Explorer tab it always reloads: the Workspace graph does not reload while another tab is active, so the parked graph can miss newer commits. `AppState.graph_reveal` (`GraphReveal { repo, sha, pages, seen_load }`) then selects the row whose `graph_row_id` is `commit:<sha>`, or a stash row with that id, and scrolls to it: at once when that repo's graph is on screen (even while a reload is queued), and after every `set_graph` (pane load or older-page merge). It widens or gives up only after `seen_load`: a `set_graph` since the reveal started, or a graph already shown with no load queued, so a stale graph never ends it early. A graph of another repo, or focus leaving the Workspace graph pane, drops the reveal. While it is still pending, the same post-`schedule` / post-`apply` hook (`Interpreter::after_change`) asks for one older page (`queue_autoload`, the second half of `maybe_queue_autoload`) when the graph has more and no older page is on its way, up to `GRAPH_REVEAL_MAX_PAGES` (10) pages. Past that, or at the end of history, it warns `abc1234 is not in the loaded graph`, plus ` (graph focus on, O clears)` while a graph branch focus is set. The graph selection footer is the commit's details.

`A` opens the blame-actions menu (`AppState.blame_menu`, `InputMode::BlameMenu`, ranked right after the stash menu; `DialogKind::BlameMenu`). It goes through the same `blame_refusal` as the four actions, so it opens only on a committed blamed line and refuses with their copy otherwise (a root commit opens it; `c` then refuses). The header is the focused line's annotation from `painted_line_annotation`, the accessor the pane paints with. Rows are `BLAME_MENU_ROWS` (`tui/line_blame.rs`): `c` open commit changes, `p` open previous line change, `w` diff commit to working tree, `g` show commit in graph. A row key (Enter runs the first) closes the menu and dispatches that blame action, which runs its own gate; other keys do nothing and Esc / `q` close it. Opening it ends a drag text selection, which would hide the annotation. While it is open, keys and mouse input do not reach the panes, background ticks stay off (`overlay_blocks_background_ticks`), and a blame answer that lands does not close it. During a busy write its keys stay live (`BusyAction::Handle`): every row only reads git.

## Graph list

Graph rows come from `workspace-status-graph` `GraphModel::visible_rows`. Graph `o` (graph list or highlighted repo / worktree) can restrict the loaded window to ancestors of selected local branches (`git log <branches>` instead of `--all`); overlay Enter applies visible marks or the cursor row (hidden pre-marks do not leak through a filter). Unmarking every `[x]` then Enter, or `O`, restores `--all`. Stashes park immediately above `stash^1`. Pane `/` matches a graph row on subject, body, author, painted relative date or local `YYYY-MM-DD HH:MM`, UTC `YYYY-MM-DD HH:MM`, branch and tag names, and full or short sha (stash / worktree rows use those fields when present). Graph pane chrome: selection footer when height ≥ 3 (`graph_chrome_budget_for` / `selection_detail_lines` / `selection_detail_parts`; footer preferred, header drops first). The footer height is fixed: `graph_footer_request(commit_msg_expand, commit_msg_lines)` asks for the rule row plus the body: N + 2 rows expanded (N message rows, the meta row), 3 collapsed, never the selected message's line count, so moving between commits never changes the list height. `AppState::graph_chrome_in` and the `GraphWidget` (`.commit_msg_lines(N)`) both use that request, so layout and paint agree. `graph_chrome_budget_for` caps the rows under the rule at half the pane (never under 2) and adds the rule row on top, and it keeps at least one list row. By default (`commit_msg_expand`; `M` collapses) that footer wraps subject plus body (`selection_footer_parts`), and so does the commit-files footer. That footer sits at the bottom of the depth-2 left (commit-files) pane under the file list. It is fixed too (`AppState::commit_detail_footer_request`): expanded is title, meta, then N message rows (a short message leaves the unused rows blank; a longer one scrolls in those rows), collapsed is title plus subtitle (2 rows). The request is the painted height, not a line count: `AppState::commit_detail_footer_lines` returns the title and meta, then only the real message lines. It wraps the whole message one column short of the width (the scrollbar column) with no line cap and no blank padding, like `selection_footer_parts`, so only real message lines scroll; unused rows stay blank in paint. `commit_detail_footer_height` adds the rule row on top of `commit_detail_footer_request` (N + 3 expanded, 3 collapsed), and draw and layout size the footer with it, and the list keeps at least one row; a click on it does not pick a file (`LayoutHit::files_list_height`). The graph footer's meta row stays on its bottom row and a short message leaves blank rows above it. The wheel over an overflowing graph footer scrolls the message (`commit_msg_scroll`, `LayoutHit::graph_footer_*`; `graph_footer_line_count` only sizes that scroll) without moving the graph cursor; a 1-column footer scrollbar shows, and while lines are hidden below, the last message row ends with a muted `<more-below><K>` (`GlyphSet::more_below`: U+F103, `v<K>` in ASCII). The commit-files footer scrolls the same way: the wheel over it (`AppState::scroll_commit_detail_msg`, `LayoutHit::commit_detail_footer_*`, recorded only while the message overflows) scrolls the message without moving the file cursor, changing focus, or loading another diff, and its message rows get the same scrollbar and hint. Both footers paint their message rows through one function, `workspace_status_graph::paint_footer_message` (offset clamp, lines, scrollbar, hint; it returns `FooterMessagePaint::scroll_max` and `more_below`), and share `commit_msg_scroll`: it is keyed by the graph row identity of the commit or stash (`AppState::commit_detail_msg_identity` builds the same key for the depth-2 source), so another commit starts at the top and the last-scrolled commit keeps its offset when you return to it, the same offset in both footers. Graph list rows stay one line. Bodies come from git `%b`, capped at 8 KiB. Uncommitted: `Working tree clean` / `Uncommitted changes` + HEAD commit ref chips, or `worktree · not a commit` when HEAD has none. Spacer: `…` + `connector · not selectable`. Stash: subject + `stash@{n} ·` hash `·` date. Commit: subject + ref chips (or `(no refs)`) `·` hash `·` parents (`parent <id>`, `parents <id> <id>` in git order for a merge, or `root commit`) `·` author `·` date. Empty: `no selection`. Footer chips use the same `LabelKind` palette as the row (HEAD / default / feature / remote / tag), not a flat wash. Graph PageUp/PageDown move in painted list space (`visible − 1` painted lines, snap to selectable); `j`/`k`, click, and vertical wheel stay on selectable `visible_rows`. The viewport keeps the focused row near the vertical middle. The 1-column scrollbar thumb is painted whenever the list overflows, at the top too; the horizontal bar only after the viewport leaves the left edge. Both are mouse-draggable through the same `hit_split` / `SplitDrag` stack as the pane and in-diff splitters (`SplitDrag::GraphScrollbar` / `GraphHScrollbar`); a track click jumps toward that position without moving the graph cursor. File-diff horizontal thumbs use that stack too (`SplitDrag::DiffHScrollbar`) and do not move `diff_cursor`. Tree and commit-file lists pan with the wheel and keys only; they do not paint an h-bar. Horizontal mouse wheel (and Shift-wheel) pans the pane under the cursor without changing keyboard focus (SGR `66`/`67`).

Same-checkout graph reloads (`set_graph`, including a watch HEAD move) keep the focused row by `graph_row_id` (commit sha, stash ref, worktree path, or uncommitted). If that row is gone, the cursor clamps to `min(old_index, n-1)`. A different checkout, a first load, or graph `o` / `O` (new log window) reset cursor and scroll to the top. Branch pickers, the stash menu, Quick Open, and the graph-focus overlay open at row 0. Those lists are new overlays, not in-place watch reloads. Commit-file and compare lists restore by path; a gone path clamps to `min(old_index, n-1)`. File-diff viewports stay on the same identity. A new path or commit-file resets to the origin.

See [git-graph-topology.md](./git-graph-topology.md) and [graph.md](./graph.md).

## Actions and gates

`tui/action.rs` is the single source of truth for which actions exist. `tui/tty.rs` enables mouse (click + button-event + any-event DECSET 1003 + SGR) and decodes TTY SGR reports (`66`/`67` → `ScrollWheel { horizontal: true }`; motion-bit wheel `96`–`99` decodes as the plain wheel; buttonless motion → `PointerMove`). The live loop handles `PointerMove` before busy gating and dispatch: it stores `AppState::pointer`, arms or drops the icon peek timers, and redraws only when the hovered tab `[✗]`, the hovered icon, or the hovered resize edge (`AppState::hovered_resize_edge`) changes. `dispatch(PointerMove)` is a no-op that keeps `g` / `z` chords. `m` clears the pointer. `tui/keys.rs` maps crossterm events to `Action`. `<` / `>` are `Action::ResizeTree(-1 / 1)`: `split::step_tree_fraction` moves the session `tree_fraction` by 5% of the terminal width with the divider drag's clamp. A left press with Ctrl held is `Action::CtrlClick { col, row }`; every other mouse report keeps its action (Ctrl+drag is still `Drag`). `CtrlClick` runs the same path as `Click` (`AppState::ctrl_click` calls `click` first), and opens a PR only when it lands on a painted PR badge; see **Pull request badge and open**. A right-button press is `Action::BackClick` in Normal and `V` modes; a pending `z` / `g` chord maps it like Esc (overlays drop every mouse event); dispatch runs `DiffVisualCancel` in highlight, otherwise `NavEsc`, and nothing while mouse capture is off. Keyboard enhancement reports Shift-letter as the unshifted codepoint plus SHIFT; the keymap folds that to the uppercase binding (`O` / `S` / `E` / `/` capitals) so it matches a raw `'O'` byte. `E` is `Action::ExternalDiff`. `e` stays `Action::Edit`. `tui/state/dispatch.rs` routes `Action` to session updates and `Effect`. List keys live in `tui/state/dispatch_keymap.rs`. Pan / wheel live in `tui/state/pan.rs`. Enter / Esc live in `tui/state/dispatch_drill.rs`. Git writes live in `tui/state/dispatch_write.rs`. `mouse_pan` routes a long file-diff pan when the pointer is over the left pane and the painted diff can pan; otherwise the left list pans. Painted horizontal thumbs (graph and file-diff) drag through `hit_split` (`SplitDrag::GraphHScrollbar` / `DiffHScrollbar`). A track click jumps the pan offset. `tui/gates.rs` hides writes that the focused row / depth / pane must not run. `tui/ops.rs` resolves stage / unstage / revert file lists (`collect_write_files`) and bulk git targets (`op_targets` / `push_targets`).

Resize-edge hover: `AppState::hovered_resize_edge()` returns `Option<split::ResizeEdge>` (`Pane`: the tree / right divider; `DiffSplit`: the side-by-side RULE; `CommitMsg`: the top rule of the expanded graph commit-message footer, recorded per frame as `LayoutHit::commit_msg_rule_y` / `_x` / `_width` with the pane fit `commit_msg_lines_fit`). An active pane, RULE, or commit-message drag (`SplitDrag::resize_edge`) wins. Otherwise it is `hit_split` at `pane_pointer` on the last paint's layout (`SplitHit::resize_edge`); scrollbar hits and `Other` are not edges. It is `None` while mouse capture is off, on an Explorer tab (no pane or RULE drag there), below the minimum terminal size, in an input mode whose clicks do not reach the panes (dialogs, prompts, help, Quick Open, the pinned popover, search-in-files), with the pointer inside a hover popover, and on a painted tab label or `[✗]` (`click_at` gives the press to the tab first). A resize drag stores each drag cell as the pointer, so after the release the edge stays lit only while the pointer is still on it. `render::paint_resize_edge_hover` paints the highlight after both panes and the icon popover, so it reads the same layout (popover rect included) as the OSC 22 pointer shape after the draw; it leaves the cells of a hover popover as painted. A commit-message drag moves `commit_msg_lines` by the row delta from the press (`commit_msg_lines_from_drag`: up adds, down removes, clamped to 1–20 and to the pane fit, `origin_lines` again on the press row). Release saves it to the UI-state store when it changed; `cancel_mouse_drag` keeps the live rows and saves nothing.

`;` opens a boxed comment overlay on a numbered file-diff line (working-tree, commit, or compare) or on a commit / non-default branch / worktree row. The overlay is a multiline caret editor (`tui-textarea`): Shift-Enter inserts a newline; Enter saves; empty Enter deletes. Left / Right / Home / End move the caret (Home / End are the current line). Ctrl-a / Ctrl-e are line start / end. Ctrl-Left / Ctrl-Right move by word. Insert, Backspace, and Delete apply at the caret. Overlay Ctrl-r toggles resolved. Enter persists body and resolve state. A failed write sets `comment save failed` plus a short IO error on the breadcrumb trailing slot instead of `comment saved` / `comment deleted`. The idle status row is replaced. Hint chips do not paint inside the box. `V` on a focused file diff starts visual-line highlight; `j` / `k`, arrows, `gg` / `G` / Home / End, PgUp / PgDn, and Ctrl-u / Ctrl-d move the head (extend or shrink the range); `?`, `q`, `m` act as in normal mode; any other key (`T` included) sets warn `Esc exits highlight` (`Action::DiffVisualUnmapped`). Highlight has no `GPending` mode: the second `g` of `gg` dispatches `ArmGChord`, which moves to the top while the first `g` is still pending; `;` then attaches the comment to that line span; on a working-tree file diff `s` / `u` stage / unstage the highlighted add/del lines (or the hunk covering that range) and do not whole-file stage. `x` builds a reverse patch of the highlighted unstaged lines, clears the highlight, and opens `PendingConfirm::RevertRange`; `y` emits `Effect::RevertPatch` (worktree only), `n` / Esc sets `revert cancelled`. On a commit / stash / worktree drill diff, `s` / `u` / `x` refuse with a breadcrumb (no `git apply`). On a compare diff `s` / `u` refuse, and `x` builds the reverse patch from the COMMITTED section (`PartialPatchKind::RevertCommitted`) and opens `PendingConfirm::CompareRevertRange` (see Compare tabs). Without highlight, `;` opens the stored span that covers the focused line (smallest inclusive span, then lowest start line, then key order). A compare diff line (or highlighted span) is keyed `CommitLine { repo, sha: <compare head>, path, line, end_line }` (`CommitFileSource::line_commit`): the new-side numbers are the head blob's, the same key a commit drill of that head uses, so the store format does not change. Delete-only rows fall back to the merge-base line number, as on a commit diff. After HEAD moves and the tab reloads, those comments stay in the store but no longer paint on that compare diff. On a compare tab the comment target, diff line marks, commit-file row marks, and `y` scope come only from the tab's checkout, file, and range (`AppState::open_diff_target` / `commit_drill_source`), never from the parked Workspace diff, so a Workspace worktree comment does not paint on a compare diff line with the same number. A compare file-list row has no line target (`no comment target`), the same as a commit-file row. Empty Enter deletes that span. Esc leaves highlight without commenting. `:` opens Quick Open commands over the range (see Keymap). Watch reload, split versus inline, or a painted-row change drops highlight. The diff gutter reserves a comment-mark column on every numbered cell so the line numbers do not shift when a comment appears. Open comments paint `ICON_COMMENT` (`"` / nf-fa-comment). Resolved comments paint `ICON_COMMENT_RESOLVED` (`'` / nf-fa-comment-o). Workspace, group, section, dir, file, and default-branch rows are not object-comment targets. If a repo has exactly one non-default branch, a comment that would have attached at repo scope attaches to that branch. A primary detached HEAD is a worktree path key. Graph rows paint the comment glyph when the row has an object comment or a file-line comment (resolved glyph when every comment on the row is resolved). Commit-file rows paint the same trailing mark when that file has a line comment. `y` copies live comments as markdown after GC for the **focused** tree / graph / commit-file / diff row and descendants under that row (a file copies that path only; a folder copies files under it). Unrelated siblings stay out. The workspace row copies every live comment. A family row copies Worktree object comments for every checkout of those identities, plus comments keyed by the identity path. A linked-worktree row copies Worktree comments keyed by that family identity and by this checkout path. Branch and commit comments keep identity matching. Matching uses `repo_identity` and snapshot checkout paths, not a path prefix. Unrelated repos stay out. Family and linked-worktree comment marks use the same rule. Resolved comments stay in that copy and carry `[resolved]`. A line comment with a newline stays one markdown bullet. Continuation lines are quoted. Confirm-mode `y` is still revert-yes. `'` copies a pasteable entity reference for the focused tree / graph / commit-file / numbered-diff row. Status is `copied` when the copy succeeds. Status is `copy failed` when OSC 52 and the host tool both fail. No overlay. No comment store write. Search still types `'`. `;` is unchanged.

`stage` / `unstage` / `revert` resolve targets through `collect_write_files` (file / dir / section / checkout / flat repo). Visual-line `s` / `u` bypass that list and emit `Effect::ApplyCachedPatch`. Visual-line `x` bypasses it too and confirms `Effect::RevertPatch`. Section headers take every dirty file on that side of the checkout; dirs under a section stay on that side. Family containers, workspace, and group yield no files. Revert opens a counted confirm that offers only the keys `RevertScope` allows for the tracked / untracked mix: tracked only `y`; mixed `y` discards tracked only, `Y` also deletes untracked via per-file `remove_untracked_file`; one untracked file `y` deletes it; several untracked files `Y` deletes them. A key the box does not show keeps it open. `r` reloads one checkout unless the focused row is workspace or `group:no-updates`.

Write scope for bulk git (`f` / `p` / `P` / `d`): primaries on workspace/family rows; a linked worktree only when that row is focused; hidden-list paths omitted even if focused. When hidden repos are shown (`.` / `-a`), they follow the same primary / focused-worktree rule. Background fetch uses `background_fetch_targets` and skips hidden repos.

Independent checkouts run fetch / pull / push in parallel (`FETCH_CONCURRENCY` = 10) on the per-gitdir remote queue in `tui/effect.rs`. Occupy key is `primary_repo` when set, else the checkout path. A second `f` / `p` / `P` enqueues. Pending jobs coalesce on that checkout. `Fetch` / `Pull` / `Push` / `FetchTick` are `BusyAction::Handle`. Exclusive writes are Ignore only while exclusive write or default-branch is busy.

`InputMode::Confirm` maps `y` → `ConfirmYes`, `Y` → `ConfirmYesClean`, `n` / Esc → `ConfirmNo`, and Enter → `ConfirmEnter`, which writes nothing and names the accept key (`PendingConfirm::accept_key`). `d` whose targets hold more than one repo off default opens `PendingConfirm::SwitchToDefault`; its Yes emits the same `Effect::DefaultBranch`, and Confirm Yes keeps that overlay while any of those gitdirs is busy. `P` (key and palette Push) does not push at once. With a push target it returns `Effect::PreparePush { repo }`; the worker runs `git::push_plan` and returns `JobOutcome::PreparePush`, and `open_push_confirm` opens `PendingConfirm::Push { repo, branch, remote, publish, ahead_behind }` when focus is still on that checkout (a stale result is dropped; a detached HEAD sets the error status instead). The box is `Push <branch> → <remote> (N commits)?` (count from the snapshot sync note, none on first publish). Its Yes emits `Effect::Push { repos: [repo] }` with status `Pushing 0/1…`; `Y` is not offered; No sets `push cancelled`. Without a target the status is `focus a repo or checkout to push` (workspace, group, file rows) or `nothing to push`. `p` with nothing behind and exactly one diverged target whose snapshot `upstream_rewrite` has `yours == 0` opens `PendingConfirm::ResetToUpstream { repo, branch, upstream, tip, dropped }` (`<repo>: <u> was rewritten. Move <b> to <u>?`); its Yes emits `Effect::ResetToUpstream { repo, branch, upstream, tip }` with status `moving <b> to <u>…`, an exclusive write on the gitdir (Confirm Yes keeps the overlay while that gitdir is busy); `Y` is not offered; No sets `pull cancelled`. Several such targets, or one with `yours > 0`, set a warn and write nothing ([git-operations.md](./git-operations.md)).

An exclusive write on an occupied gitdir still dispatches. Then `schedule` refuses with breadcrumb `busy`. Confirm Yes, stash create/apply/pop, and create-branch submit keep the overlay in that case. Branch-picker create from a new name keeps the picker. Status is `busy`. A free gitdir may write while other repos fetch. If `p` lands during an inflight fetch on that gitdir, Pull still queues when dispatch set `nothing behind to pull`, a diverged line, or a no-write upstream-rewrite warn (several rewritten targets, or the rebase command), or when `p` opened `PendingConfirm::ResetToUpstream` (whatever the status line held). Diverged targets stay out of that Pull. Right-pane, compare, and drill `Effect::None` Pull do not follow.

Mixed kinds paint `Fetching 1 · Pulling 1…` or `Fetching 1/2 · queued 1`. After those ops finish, `status` is a count (`Fetched N repos`), with ` (N failed: <first repo> — <git reason>, +N more)` and ` (N skipped: dirty)` when they apply; a pull whose auto-stash conflicted leads with `<repo>: pulled, but restoring local changes conflicted — …`. Repos that worked are not listed.

Graph pane writes (`graphCheckout` / `graphCreateBranch` / `graphMerge` / stash apply / drop / pop) gate on graph-list focus (depth 0 right or depth 1 left). Graph `m` is `graphMerge` (always confirms). Graph `o` / `O` are view filters (focus branches / clear), not writes. They open from the graph list or a highlighted repo / worktree. Inside the `o` overlay `O` types; Ctrl-o clears. The tree `b` picker and the graph `b` picker share `BranchPickerState` (with `creates` set; the compare picker has none): a valid filter that is not an exact listed name adds a create row after the branches (`BranchPickerState::create_name` / `on_create_row`). `BranchSubmit` on it emits `Effect::CreateBranch` (tree: create and check out at HEAD) or `Effect::CreateBranchAt` (graph picker: at its commit, no checkout). The create-branch name prompt (`InputMode::CreateBranch`) is graph `c` only. Leftover branch/tag chips on a commit spacer: truncate the next name with `…` (keep brackets) when part of it fits; bold `[+N]` counts only chips fully hidden after that (omit `[+N]` when the last painted chip is merely truncated) so the row does not grow.

## Pull request badge and open

`Action::OpenPullRequest` (`gx`, palette Open PR) and `Action::CtrlClick` on a badge share one target rule and one effect. `AppState::pr_target_for_focus` (`tui/state/pull_request.rs`) returns the checkout path and branch to look up:

- Tree: the focused `NodeKind::Repo` or `NodeKind::Checkout` row with a branch (primary or linked). A repo row that groups several checkouts (`chrome.is_family`) has no target.
- Graph: the focused `GraphRow::Worktree` row with a branch.
- No target: a commit, stash, uncommitted, dir, file, workspace, or group row, commit files, a diff, a file or compare tab, and a detached or unknown HEAD. The status is `no PR for this row` (warn) and nothing runs. The same text covers a Ctrl+click on a badge whose checkout no longer has a branch.

A target becomes `Effect::OpenPullRequest { repo, branch }`. A Ctrl+click on a badge returns `Effect::Batch([<click effect>, OpenPullRequest])`, so the right pane still follows the selected row; it also clears `last_click`, so a second Ctrl+click opens again instead of drilling. The badge cells are icon hits (`LayoutHit.icon_hits`, `IconTarget::PullRequest(checkout)`), read as `PrBadgeHit { y, x, width, repo }` through `LayoutHit::pr_badge_hits`: each frame clears the list first, and the tree and graph painters push one entry per painted badge, so a hit is always a badge on screen. `draw` turns the same hits into OSC 8 links to the full PR URL in `LayoutHit.links` (`AppState::pr_badge_links`); a dialog or the popover drops the links under its box, then `draw_popover` adds the PR popover URL line (`PopoverLine::Field` with `link`, over the painted, possibly cut, value). Ctrl+click off every hit is a plain click and pins no popover; a plain click on a badge selects the row and pins its popover (see **Icon popovers**). An Explorer tab paints no badge, so both clicks behave alike there.

The PR cache (`PrCache` in `AppState`) holds, per checkout path, the branch it was looked up for and the remote URL the worker resolved, and, per (remote URL, branch), the forge's answer: a PR that counts, no PR, or a failed lookup. The remote URL is not in the snapshot, so it exists only after the worker answered. `AppState::pr_badge` gives a badge only for a ready answer that belongs to the checkout's current snapshot branch. In flight, failed, no PR, closed-unmerged, or another branch's answer: no badge.

The cache also holds the PR popover detail per (remote URL, branch): `PrDetailState::Loading`, `Ready(PullRequestDetail)`, or `Failed`. `request_popover_pr_details` marks a detail loading and returns `Effect::LookupPullRequestDetail { repo, branch, remote, number, request }` for each PR the open popover shows that has no detail yet; `request` is a new id per request, kept in `Loading(request)`. It runs when a peek opens (`expire_peek_with_details`, called by the event loop's `peek_remain` arm) and when a popover pins (a click on an icon, a click inside a peek, `gh`); a watch or fetch tick never calls it, so each PR is asked once and later hovers and pins read the cache. A failed detail is not asked again until it is dropped. The detail is dropped when the checkout leaves the branch (pruned with the answer), on `r` and on a full reload, when the checkout vanishes, and when a new badge or `gx` answer for the branch differs from the cached one (`PrCache::set_answer`). `apply_pr_detail` drops a result whose checkout is on another branch, was forgotten, resolves another remote, whose answer names another PR, or whose detail no longer waits for that request id. So after `r`, a late answer to the old request (a hung CLI that times out) cannot replace the answer to the new one. When a detail lands under a pinned popover, the focus stays on the line it was on (same section, same field label or action title), since the new fields push Open PR and the URL down. A pin picks its landing line after the request, so it counts the `loading…` line.

A badge lookup is due (`due_pr_lookups`) when a checkout shows a branch it has no record for: first sight, or a changed branch. It is not due for the same branch on a watch tick, which keeps `gh` / `glab` out of the 3 s poll. `r` (`ReloadRepo` for the focused repo) and a full reload (`ReloadSnapshot`) forget the records, so the next applied status looks up again. A lookup for a branch the checkout has left is dropped on arrival. Detached checkouts and hidden repos are not looked up. A background lookup never writes `status`. `gx` and Ctrl+click always run a fresh lookup in the open job, then update the cache, and set one status: `opened PR #<n>` (ok), `no PR for <branch>` (warn), `could not look up PR for <branch>` (error), or `could not open PR` (error). Worker rules: [tui-rust.md](./tui-rust.md) → **Pull request jobs**. Forge calls: [git-operations.md](./git-operations.md) → **Pull request lookup**.

## View remotely

`Action::ViewRemotely` (`gw`, palette View remotely) opens the forge web page of the focused entity. `AppState::remote_target_for_focus` (`tui/state/remote_view.rs`) names the entity as a `RemoteFocus`: `View { checkout, target }` with a `RemoteTarget`, or `Refuse(text)`. A target becomes `Effect::ViewRemotely { checkout, target }`; a refusal sets a warn status and runs nothing. The worker then checks that the entity is on the remote and opens the page (`remote_view::resolve`, `page_url`; commands and URLs: [git-operations.md](./git-operations.md) → **View remotely**).

| Focus | `RemoteTarget` |
| --- | --- |
| Tree repo row (a family row too) | `Repo` (repository home) |
| Tree checkout row, graph worktree row | `Branch(<branch>)`; detached: `Commit(<HEAD>)` |
| Tree file or dir row | `File { rev: <checkout rev>, path, line: None, dir }` |
| Graph commit row | `Commit(<id>)` |
| Commit-file list row (commit, stash, or worktree drill; compare tab left pane) | `File { rev: <source rev>, path, line: None, dir }`; a folder row is a dir page |
| File diff (Workspace, drill, compare tab, Explorer inner diff) | `File { rev: <source rev>, path, line: <new-side line>, dir: false }`; a folder summary opens that folder |
| Explorer tree file or folder row | `File { rev: <checkout rev>, path, line: None, dir }` |
| Explorer clean-file view | `File { rev: <checkout rev>, path, line: cursor + 1, dir: false }` |

**Revision rule.** `<checkout rev>` is the checkout branch, or the HEAD commit when the checkout is detached (`AppState::checkout_rev`). `<source rev>` (`AppState::source_rev`) is the commit of a commit drill or a compare tab (`CommitFileSource::line_commit`: the commit, or the compare head), so those files open at that commit. A worktree drill, a Workspace or Explorer diff (source `None`), and a commit-vs-working-tree tab use `<checkout rev>`. A stash source refuses.

**Line rule.** The anchor is the new-side line of the focused diff row only (`new_side_line`): an added or context line, in split or inline layout. A row that shows only a deleted line, and a section, hunk, or meta row, opens the file with no anchor. `row_line_number` (copy reference) is not used, because it falls back to the old side.

**Refusals.** `stash@{n} is local only` (a graph stash row, a stash drill file or diff), `uncommitted changes are local only` (the graph uncommitted row), and `nothing to view remotely on this row` (workspace, group, and section rows; a compare tab before its range loads; an Explorer tab with no row or file; a detached checkout with no known HEAD). `AppState::view_remotely_refusal` gives the same text to the palette row; it skips the line anchor, so the gate builds no diff rows (the line never decides a refusal). A popover View remotely line resolves its own section instead of the focus (see **Icon popovers**). The worker result (`AppState::apply_remote_view`) sets `opened <url>` (ok), a remote refusal such as `branch <b> is not on <remote>` (warn), or `could not open browser` (error). Worker rules: [tui-rust.md](./tui-rust.md) → **Pull request jobs**.

## Icon popovers

Model and content: `tui/popover.rs`. State, keys, and clicks: `tui/state/popover.rs`. Paint: `render::draw_popover`.

- **Hit registry.** `LayoutHit.icon_hits` holds one `IconHit { y, x, width, kind: IconKind, target: IconTarget }` per painted icon. Each frame clears it. Tree paint records every segment with a catalog tag (`TextSeg.icon`, set by `tree.rs`: on workspace, repo, checkout, and group rows every glyph and indicator, `ChangeCount` and `WorktreeCount` included; the PR badge in `with_pr_badge`, after the merge mark in the trailing run); graph paint records the `GraphWidget::render_with_icon_spans` icons (node cells, the comment mark, the uncommitted and worktree glyphs, spacer worktree marks, ref chips on spacers and in the selection footer, the sync header, the footer more-lines hint) and the worktree PR badge. `IconTarget::TreeRow(row id)`, `IconTarget::CommitFileRow(row id)`, `IconTarget::GraphRow(graph_row_id)` (nodes, uncommitted glyph, comment mark), `IconTarget::GraphWorktree(path)` (worktree glyph on a row or a spacer mark), `IconTarget::GraphChip { row, chip }` (a ref chip, mark run, `[HEAD]`, or `[+N]` painted for row `graph_row_id`; `chip` is the graph crate's `PartTarget`), `IconTarget::GraphSync` (the sync header), `IconTarget::GraphMoreLines(graph_row_id)` (the footer hint), `IconTarget::CommitDetailMoreLines(identity)` (the depth-2 commit-files footer hint, keyed by `AppState::commit_detail_msg_identity`; `draw_commit_detail` records it), or `IconTarget::PullRequest(checkout)`. One hit can open more than one section: `popover::icon_targets` turns a checkout mark run that also holds the sync mark into a checkout section and a sync section. A span is the glyph columns only, clipped to what is on screen (a trailing run too wide for the pane is cut from the left).
- **`PopoverState`** (`AppState.popover`): `origin` (`Peek` / `Pinned`), `targets` (one `(IconKind, IconTarget)` per section, in paint order), `anchor` (icon cells; `None` from `gh` hangs it from the first painted icon of its targets, else the focused row), `focus_line` (index into the flat lines of all sections), and `owner` (`PopoverOwner`: active tab, `list_focus_target`, focused tree row id, focused commit-file row id, or the focused graph row's `graph_row_id`: `uncommitted`, `commit:<id>`, `stash:<id>`, or `worktree:<path>`). The commit-file row id makes a cursor move in a commit-file or compare file list close the popover. The graph row id makes a cursor move, or a reload that leaves another row under the cursor, close it; a reload that keeps the cursor on the same row keeps it.
- **Content** is rebuilt every frame (`popover::popover_sections`), so it follows watch ticks and a section whose icon went away drops. A builder is a pure function of `AppState` and one target. A tree or commit-file target's section exists while its row still paints that kind (a sync mark stands for every sync kind, a merge mark for both, a status letter for every letter, and a comment mark for open and resolved, so a tick that flips the mark keeps the section). `IconTarget::CommitFileRow(id)` names a row of the shown commit-file or compare file list; its sections use the same file-level builders as a workspace file row. A graph chip section exists while its row is visible and its commit still holds the refs the chip names (the uncommitted row's footer chips are HEAD's); a ref chip's kind follows the refs. A `[+N]` target holds the hidden chips from its last paint (`PartTarget::Overflow`); its section lists only the ones still present (`[HEAD]` only while HEAD is detached) and goes when none is. One `popover_sections` call builds the commit-file rows and the graph's `visible_rows` at most once, however many sections read them. The sync header section follows `GraphModel::sync`; the more-lines section follows `AppState::graph_footer_lines_below` and the focused row (graph footer) or `AppState::commit_detail_footer_lines_below` and the shown commit-file source (depth-2 commit-files footer); both build it with `more_lines_section`, so the meaning, count, and actions match. Comment sections read `comments::tree_row_comments` / `commit_file_row_comments` (the same match as the mark). Fields read the row chrome, the snapshot row (`changes`, `local_branches`, `default_tip_ref`), and the tree node (family checkouts, No updates children). `PopoverSection { icon, role, target, lines }`; `PopoverLine::Text` (the catalog meaning, not focusable), `Field { label, value, role }` (`role` is the `SegRole` the value paints in, `File` when the pane gives it no colour), `Action(&PaletteCommand)` (from `command_palette::command_for`, which takes the plain row over a highlighted-lines row such as `Stage highlighted lines`).
- **Peek.** `set_pointer` arms a dwell for a new hovered icon (`PEEK_DWELL_MS` = 400) and a leave grace when the pointer is off both the peek and its icon (`PEEK_GRACE_MS` = 250). The event loop sleeps on `peek_remaining_ms` and calls `expire_peek`. A peek does not change `input_mode`. `sync_popover_with_layout` (paint) drops a peek whose icon no longer paints at the same cells or while an overlay is open; `m` drops it.
- **Pin.** A click on an icon hit runs the plain click (`click_at`, which selects the row), clears `last_click` (so it never counts toward a double-click), then pins. A click inside a peek selects the peek's row and pins it. `Action::PopoverOpenFocused` (`gh`, or the `:` palette row Icon popover) pins one section per icon of the focused row, read from the row's painted segments (`tree::painted_row_segments`, or `AppState::commit_file_row_paint_segments` on a commit-file or compare list row, so a clipped icon still lists) or, on a graph row, its node, comment mark, label glyph, PR badge, spacer worktree marks, and spacer ref chips (`LabelPart::icon` over the row's painted lines); no icon sets `no icons on this row`. Ctrl+click on a PR badge pins nothing.
- **`InputMode::Popover`** while a pinned popover's owner matches the focus (`popover_pinned`). `input_mode` ranks it after help and before the search prompt. `overlay_blocks_background_ticks` lets watch and fetch ticks run under it. Keys: `j` / `J` / Down → `PopoverMove(1)`, `k` / `K` / Up → `PopoverMove(-1)` (field and action lines only, stops at the ends), Enter → `PopoverRun`, `y` → `PopoverCopyLine` (`Effect::CopyClipboard`: a field's value, an action's title), Esc and right-click → `PopoverClose`. Any other key maps to `Action::None`. Mouse events keep their actions.
- **View remotely line** (`Action::ViewRemotely`, `gw`). It ends the action lines of these sections: the tree Repo, LinkedWorktree, and Branch glyphs; the file-type glyph (`file_fields`, on tree and commit-file rows); the graph commit and HEAD commit nodes; every ref chip (`PartTarget::Chip`: local, remote, or tag); the checkout mark; the sync mark when its branch is not checked out (with a checkout mark, the checkout section holds it); `[HEAD]`; and the graph sync header. On a graph worktree's own row with a branch it follows Open PR. No other section lists it: not the PR badge (Open PR only), a worktree mark on a commit spacer (no actions), `[+N]`, the stash, uncommitted, and comment glyphs, or the footer hint.
- **Section target rule.** A View remotely line opens the entity of its own section, not only the focused row: `AppState::remote_target_for_icon(section.icon, &section.target)` (`tui/state/remote_view.rs`). Per reachable section:
  - Tree Repo glyph: the repository home (`RemoteTarget::Repo`). Branch and LinkedWorktree glyphs on a repo row (a one-checkout repo row paints its checkout's glyphs too): that checkout's branch (`Branch`), or its HEAD commit (`Commit`) when detached, as a checkout row does. The same glyphs on a checkout row, and the file-type glyph on a tree or commit-file row: the focused row, `remote_target_for_focus` (the popover row is the focused row).
  - Graph commit and HEAD commit nodes: the focused row (that commit).
  - Ref chip: its tag (`Tag`), its remote-tracking branch (`RemoteBranch`), or its local branch (`Branch`), so a tag chip on a commit row opens the tag. Checkout and sync marks: their branch. `[HEAD]`: the commit of its row (`AppState::graph_row_commit`, which reads the model in place; HEAD on the uncommitted row). Graph chips use `focused_graph_repo` as the checkout.
  - Graph worktree row (`GraphWorktree(path)`): that worktree's branch (its HEAD commit when detached) in that checkout.
  - Sync header (`GraphSync`): HEAD's branch, or HEAD's commit when detached.

  The line's gate is `AppState::popover_line_refusal(command, section.icon, &section.target)`: the palette scope check, then `view_remotely_refusal_at`, so a chip in the uncommitted row's footer is not refused as an uncommitted row. Every other line uses `palette_disabled_reason`.
- **Run.** `PopoverRun` finds the line's section (`section_lines`; the clicked line, or `focused_line` for Enter) and checks `popover_line_refusal` for the line's palette row: a reason goes on the status line and the popover stays. Otherwise the popover closes. A View remotely line then runs `AppState::view_remotely_at(section.icon, &section.target)` (the section target rule above). Any other line runs `dispatch_palette_action` with its own `Action` through every gate, the same path as a Quick Open row (Fold subtree runs `FoldToggle` then `FoldToggleSubtree`, like `zz`; Fold row arms no `zz`). No new `Effect`. While a write runs, `classify_busy_dispatch` classifies Enter as that action (`AppState::popover_run_action`), and a left release on an action line (not a drag) as that line's action (`AppState::popover_release_action`), so a click cannot start a write that the key would not.
- **Mouse while pinned.** A press inside the box arms a `TextSelection` on its text area and focuses the line under it; the release runs an action line unless the press became a drag (the drag copies instead). A press outside closes it and does nothing else.
- **Close.** `PopoverClose`, a click outside, an owner mismatch (another row, pane, or tab; the row went away), or a dialog that opens (`chrome::open_dialog`, for example a picker that loads after the key or a confirm from an effect). Paint drops a stale popover.

## Doctor setup checkup

Check engine: `tui/doctor.rs`. Overlay state and keys: `tui/state/doctor.rs`. Paint: `render::draw_doctor`. User-facing rows and rules: [configuration.md](./configuration.md) → **Doctor setup checkup**.

- **Opener.** Palette row `Doctor: setup checkup` (`CommandGroup::View`, no key, aliases `doctor` / `checkup` / `setup` / `health`, `CommandScope::Any`) runs `Action::OpenDoctor`. No tab, compare, or Explorer gate names the Doctor actions, so it opens from every tab. They route through `AppState::dispatch_doctor`.
- **State.** `AppState.doctor: Option<DoctorOverlay>` with `gen` (the probe request whose answer may land), `checks` (`None` while the probe runs, painted as `checking…`), `cursor`, and `scroll` (the first body line the last paint showed). `AppState.doctor_gen` counts requests.
- **Probe request.** `OpenDoctor` and `DoctorRerun` bump `doctor_gen`, set `checks` to `None` (the cursor stays), and return `Effect::RunDoctor { gen }`. `apply_doctor` fills the rows only while `doctor_awaits(gen)`: an answer for a closed Doctor or an older request is dropped. The cursor clamps to the new row count.
- **`InputMode::Doctor`** while `doctor` is open. `input_mode` ranks it after help and before the pinned popover. `overlay_blocks_background_ticks` is true for it, as for help. Keys (`keys::doctor_key_action`): `j` / Down and `k` / Up → `DoctorMove(±1)`; PgDn / PgUp and Ctrl-d / Ctrl-u → `DoctorMove(±DOCTOR_PAGE_ROWS)` (5); `g` / Home → `DoctorTop`; `G` / End → `DoctorBottom`; `y` → `DoctorCopy`; `r` → `DoctorRerun`; Esc / `q` → `DoctorClose`; Ctrl-c stays `CtrlC`. Every other key, the Quick Open openers, and every mouse event (the wheel too) map to `Action::None`.
- **Copy.** `DoctorCopy` returns `Effect::CopyClipboard { text, announce: true }` with the focused row's `fix.copy` (the Copy entity reference path, toast `copied`). With no copy line, or while checking, it sets the warn `no fix to copy` and returns no effect.
- **Report only.** No Doctor action writes a file, a setting, or the UI-state store. The only effects are `RunDoctor` and the `y` copy.

## Editor

- **Detached GUI** (`cursor`, `code`, `code-insiders`, `codium`, `gvim`, including `--wait`): spawn detached while the TUI stays mounted. Fold, focus, scroll, search, and `show_hidden` stay in `AppState`. File-status updates come from the live watch poll.
- **TTY editor** (default `vim`): leave the alternate screen, spawn with inherited stdio in the file's repo cwd, restore raw mode, re-enter the alternate screen. Resume drains leftover bytes so the next keypress does not need an extra Enter.

`E` (`Action::ExternalDiff`) uses the same detached-name list. vimdiff takes the TTY like vim. Blob/temp prepare is `spawn_blocking`. Each `E` uses its own `$TMPDIR/workspace-status-ext-diff/<pid>-<nanos>/` directory. Detached tools wait for the child on a side thread and delete only that session. Cursor / VS Code samples use `--wait` so that child stays until the diff tab closes.

From the Explorer tree the jump focuses the file pane and lands in the active inner file. In `V` highlight the row still shows on a digits filter, and the jump moves the range end with the anchor kept, as `G` does. `AppState::go_to_line_refusal` is the row's whole gate (`palette_disabled_reason` asks only it): the Workspace tree, graph list, commit-file and compare file lists, and a folder summary say `focus a file diff`; a line view with no numbered line (loading, empty, binary, or failed body or diff; an Explorer tab with no inner file tab) says `no lines to go to`. `palette_disabled_reason` takes a catalog row and checks, in order: the Open in Explorer gate (`explorer_open_target`, only for that row, on every tab), compare-tab refusal (`compare_refusal`, so highlighted Stage / Unstage on a compare tab show the compare copy, not the range patch refusal), the blame gate (`blame_refusal`), scope (`exit highlight first (Esc)` or `highlight diff lines first (V)`), the range patch refusal for highlighted stage / unstage / revert, then the action gate. The gate copy comes from `gates::dispatch_noop_reason` (the same text a key press puts on the status line) and names the way back and the action: `focus the tree (Tab) to stage`, `Esc back to the tree to pull`, `focus the left pane (Tab) to stash`, `focus the tree or graph (Esc) to stash`, `focus a graph commit`, `focus a graph stash row`. Enter closes Quick Open (`quick_open = None`) then `AppState::dispatch` of the highlighted enabled command, so range writes run with the anchor still set. Disabled rows stay visible, dimmed, with their reason at the row's right edge when it fits (the highlighted row also repeats it in the footer), when the current gate would no-op (including Push off a repo or checkout row, fetch / pull / default-branch on a group, graph-focus, full-file context, and visual highlight when those actions cannot run); Enter on one keeps the palette open and puts the reason on its status line; closing the palette clears that reason. Confirm-gated revert / merge / worktree-remove stay enabled when the row is valid so the boxed confirm can open after the palette closes. Quick Open Actions: `ToggleQuickOpen(QuickOpenEntry)`, `QuickOpenMove`, `QuickOpenChar`, `QuickOpenBackspace`, `QuickOpenSubmit`, `QuickOpenEscape`. While an exclusive write or default-branch switch is in flight, palette Enter classifies as that mapped Action (`classify_busy_dispatch` in `tui/event_pump.rs`). Palette Fetch / Pull / Push stay Handle and enqueue on the per-gitdir remote queue. Palette Stage / Unstage / Revert (whole-file and highlighted) and Edit stay Ignore. Help / search from the palette stay Handle. Palette nav / typing stay Handle. `input_mode` ranks Quick Open after confirm / stash / blame menu / comment / create / branch / graph-focus and before help / search / chords.

`Ctrl-f` opens the search-in-files dialog (`InputMode::SearchFiles { results }`, `AppState.search_files`, `tui/search_files.rs`; dispatch in `tui/state/dispatch_search_files.rs`) from Normal / `ZPending` / `GPending` / `DiffVisual`, so from an Explorer or compare tab too; inside the dialog Ctrl-f closes it. Text prompts and pickers keep Ctrl-f as their own key, and other overlays drop it. Ctrl-Shift-F maps the same (it is the same byte without the kitty protocol); Alt, Super, Hyper, or Meta never match, and plain `f` stays fetch. The scope is `AppState::quick_open_scope()` at open, the same rule as Quick Open files mode, and the title is `Search · <checkout leaf>` or `Search · all repos`. Tab flips `SearchFilesState::widened` (all repos) for this dialog only: a Tab that changes the scope drops the hits and reloads the index, and with focus already on the workspace it does nothing. Ctrl-f closes the dialog at once and parks it in `search_files_parked`, typed query included. Esc closes and parks it only when the query is empty. With a typed query, Esc clears the query instead and the dialog stays open on the query zone (`Action::SearchFilesEscape`, `AppState::escape_search_files`); the clear goes through the same edit path as Backspace, so the hits, the due search, the running search, and the query error go too. Restore rule: on the next Ctrl-f, a parked dialog whose focused scope equals the new focused scope and whose results belong to it (`parked.scope() == focused`, so not left widened) comes back as it was (query, options, index, hits, highlighted row, `scroll`; the zone goes back to the query), and only work it had not finished runs again (an index still loading reloads; a search that was due or running starts again as a new generation). Otherwise the dialog opens fresh in the new focused scope with the parked query and options, loads a fresh index, and searches once it lands, so no hit from another scope shows. `widened` always starts false. Zones (`SearchZone`): the dialog opens in the query zone, where every printable key without a command modifier types and Backspace edits; ↑/↓, Ctrl-n / Ctrl-p, Ctrl-j / Ctrl-k (`list_overlay_move`) and PgUp / PgDn (the painted results height less one) move the highlight and switch to the results zone. There `j` / `k` also move and `e` edits; any other printable key or Backspace returns to the query zone and applies there. In both zones Enter opens, Tab toggles all repos, and Esc clears the query (or closes on an empty query). No key toggles a match option: Alt with a letter neither toggles nor types. So the chips need mouse capture on (`AppState.mouse_enabled`; `m` toggles it outside the dialog, inside it `m` types); with it off, `SearchFilesState::footer_hints` adds `mouse off: m outside to click chips` before the Esc chip. The Esc chip reads `Esc clear` while the query has text, else `Esc close`. A left click on an option chip (`Aa` case, `ab` whole word, `.*` regex) toggles it: `keys::event_to_action_with` maps the click to `Action::Click`, and `app::map_event` turns it into `SearchFilesToggleOption` when `AppState::search_option_at` finds a chip box painted last frame (`LayoutHit.search_option_hits`), else into `Action::None`, so a raw click never reaches the pane click handlers under the dialog. A query edit validates the query at once (`search_files::query_error`; an invalid regex shows `invalid regex: <error>`, keeps the previous list, and arms nothing), then arms the 150 ms debounce (`SearchFilesState::due`); an empty query drops the hits and stops the search. Option toggles, Tab, a restore with unfinished work, and the `#` hand-off search with no debounce. Enter (`SearchFilesSubmit`) parks the dialog and calls `AppState::open_file_in_explorer(checkout, rel, Some(line - 1), search)`: it pins the hit's file as an inner file tab of that checkout's Explorer tab with the file pane focused, and the cursor lands on the hit line once the file loads (`InnerFile::pending_line`, see **Inner file tabs**; a clean file clamps it to the loaded body). A literal search arms the in-file search on the text the shown hits came from (`search_active`, `search_query`, `SearchPane::File` on a clean file or `SearchPane::Diff` on a changed one, `search_hit` on the hit line), so `n` / `N` step it. That search keeps the pane's own rule (trimmed, case-insensitive substring), so the case and whole-word options do not carry over. A regex search arms nothing and clears a search the tab already had. `e` (`SearchFilesEdit`, results zone only) parks the dialog and returns `Effect::EditFile { line: Some(line) }`, the path `e` takes on an Explorer file. Enter or `e` with no hit keeps the dialog open and warns `no matches` (`search_files::NO_SEARCH_MATCHES`), unless a search is still due or running, or will run once the loading index lands (a non-empty query that compiles); a query, option, or scope change, or a search chunk with hits, clears that warning. Search-in-files Actions: `ToggleSearchFiles`, `SearchFilesChar`, `SearchFilesBackspace`, `SearchFilesMove`, `SearchFilesPage`, `SearchFilesToggleScope`, `SearchFilesToggleOption(SearchFilesOption)`, `SearchFilesEscape`, `SearchFilesSubmit`, `SearchFilesEdit`. The dialog only reads files, so all of them stay Handle while an exclusive write runs (`classify_busy_dispatch`), Enter included; `SearchFilesEdit` classifies like `Action::Edit`. Enter and `e` in the results zone do not repeat when held. Mouse rule inside the dialog: a left click on a chip toggles it; motion maps to `Action::PointerMove`, which the live loop stores in `AppState.pointer` for the chip hover (`AppState::hovered_search_option`; `set_pointer` reports a change of hovered chip so the loop redraws); any other mouse event (wheel, drag, release, right or Ctrl click) does nothing. While the dialog is open, `AppState::pane_pointer` is `None`, so the tab `[✗]` and pane icons under it do not hover and no icon peek arms. `overlay_blocks_background_ticks` holds watch and fetch ticks while it is open. `input_mode` ranks it right after Quick Open. Index, chunked search, cancel, debounce, and preview data flow: [architecture.md](./architecture.md).

Ctrl-d / Ctrl-u map to `Action::Move(5)` / `Move(-5)`: the cursor moves at once, glide or not. With `smoothScroll` on (the default), `handle_input` (`tui/event_loop.rs`) first calls `AppState::arm_scroll_glide` for a half-page chord (`keys::is_half_page_chord`, a Ctrl-d / Ctrl-u press or repeat) that maps to a `Move`. It records the focused pane (`anim::GlidePane`: workspace tree, graph list, file diff, or Explorer file view) and its painted top (`anim::ScrollGlide`, in `tui/state/scroll_glide.rs`). Each painter asks `anim::glide_step` for the top to paint: the jump top with no glide, else an ease-out cubic step from the old top over `GLIDE_MS` (48 ms), clamped so the cursor stays on screen, with `LayoutHit::gliding` set so the loop ticks at 16 ms. The graph paints the glided top and keeps `graph_scroll` at the jump top; `draw_graph` records the painted top in `LayoutHit::graph_painted_top`, and graph row clicks, the scrollbar bar, and the thumb hit test read it (`AppState::graph_painted_top`), as the tree reads `list_offset`, so a press mid-glide hits the rows on screen (a thumb grab keeps them); the file view keeps the file tab's `scroll` at the jump top. The file view's top is sticky (`j` / `k` move it only as far as the cursor needs), so a half-page `Move` there sets `FileTab::recenter` and the next paint puts the cursor near the middle (`file_view_middle_top`), as the other panes do; that gives the glide rows to cover. A step the cursor clamp already pins on the jump top ends the glide without a tick. Any other mapped input (`Action` other than `None`) drops a live glide (`cancel_scroll_glide`). The commit-file list and the Explorer tree do not glide. `smoothScroll: false` (`WS_STATUS_SMOOTH_SCROLL=0`) arms nothing, so the chord jumps.

Quit is a double **Ctrl-c** chord (`tui/ctrl_c_exit.rs`). First press paints `Press Ctrl-c again to exit` for `CTRL_C_EXIT_MS` (2s); second within that window exits. Overlay pickers (stash / branch / create-branch / Quick Open / search in files) show the copy inline; otherwise it is a pinned chrome row, never a breadcrumb toast. The chord is handled before overlay modes, so it does not close a picker. `q` also quits immediately (Rust extra), except while an exclusive write or default-branch switch runs: then `q` arms the same window with `git write running · press q again to exit`, and a second `q` or Ctrl-c quits. Quit drops remotes that have not started. In-flight git is stopped once the terminal is restored (`git::stop_running_git`: `SIGTERM`, then `SIGKILL` after 2 s). Esc never quits.
