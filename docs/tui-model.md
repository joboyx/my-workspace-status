# TUI model

Pure data under `crates/workspace-status/src/tui/` (tree, fold, flatten, keymap, live refresh). The event loop is `Action` → `AppState::dispatch` → `Effect`. `tui/effect.rs` turns that `Effect` into Scheduler jobs and applies results. Autoload, commit-files, commit-diff, stash / branch / graph-focus picker, and compare-picker jobs carry a generation plus an immutable target. Compare picker uses `request_prepare_compare`, separate from `b` / `o` branch gens. Compare-file diffs keep a latest request id per tab (`CompareTab.diff_req`). Autoload captures `GraphIdentity` (repo + head) at enqueue; the others capture at spawn (`(repo, source)`, `(repo, source, path)`, or focused checkout / picker request). Apply drops a result when that gen is stale or the live drill / identity / focused checkout no longer matches, the same way a right-pane load drops a stale `req_id` or target. A right-pane Graph replace bumps the autoload generation and clears `graph_loading_older`, so a late older page cannot merge into the new window when repo+HEAD are unchanged (graph `o` / `O`). Esc Diff→Files bumps the commit-diff generation so a late result cannot reopen Diff. The live TTY loop (`tui/event_loop.rs`) spawns those jobs on a `JoinSet`.

## Node kinds

`NodeKind` in `tui/tree.rs` is a seven-member enum. Five of them are structural; `Group` and `Section` are chrome.

| Kind        | Id                           | Children                    | Notes                                                                                                                                                                                                                                                          |
| ----------- | ---------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Workspace` | `workspace` (literal)        | repos + at most one group   | Single root. Carries `change_count` and `sync_summary`. Root label is rendered as provided (natural case), not uppercased.                                                                                                                                     |
| `Repo`      | `repo:<repoPath>`            | dirs/files **or** checkouts | Flat when the primary has no linked worktrees (branch on the same row). With linked worktrees → **family container**: path + trailing `ICON_REPO` / `N wt` / change count; branch omitted; `merged_into_default: None`; sync is worst-of-family.                |
| `Checkout`  | `checkout:<repoPath>`        | dirs/files                  | Nested under a family container only. Primary uses `ICON_BRANCH` + branch (never `ICON_LINKED_WORKTREE`) and the merged-into-default check when HEAD is a strict ancestor of the default tip. Open-vs-default stays linked-only. Linked extras use `ICON_LINKED_WORKTREE` + branch (or short path when detached) + merge mark. The merge mark is its own tagged segment after the branch (`Added` merged, `Muted` open). Trailing chrome is sync / counts / comment / viewed only. Checkmark only when HEAD is a strict ancestor of the default tip; HEAD equal to that tip is open. Files live here, not on the container. |
| `Group`     | `group:no-updates` (literal) | repos                       | Holds every repo with **no** updates (clean worktree, default branch, up-to-date with upstream, no attention sync note). Only ever one, only present when at least one such repo exists.                                                                       |
| `Section`   | `section:<repoPath>:staged` / `section:<repoPath>:changes` | dirs/files for that side | Present when the checkout has any staged path (empty side omitted). `repo` is the checkout path; `file` is `None`. Paint is 1-col glyph + `Staged` / `Changes`. Not `Group` (`in_no_updates` stays false). Foldable. |
| `Dir`       | `dir:<repoPath>:<fullPath>`  | dirs/files                  | Tree mode only. Single-child chains are collapsed (`apps/web/packages/ui` as one node). Every Changes-section dir uses `dir:<repoPath>:<fullPath>#unstaged`. Staged dirs stay unsuffixed. `dir_path_from_id` strips `#unstaged` before the filesystem path. |
| `File`      | `file:<repoPath>:<path>`     | —                           | Leaf. Carries the originating `FileChange` (one git side when sections are on). MS dual rows keep this id under Staged and use `file:<repoPath>:<path>#unstaged` under Changes. Space-reviewed uses the snapshot `FileChange` (both git sides) so the mark survives reconcile; both dual ids light. |

`Group` exists so clean repos collapse into one line by default instead of padding the tree. `Section` splits a checkout's dirty files into Magit-style **Staged** then **Changes** trees when **any** path is staged. No staged paths → today's file/dir ids directly under the repo or checkout. Each section is a normal path tree (`t` still toggles tree vs flat inside it). Split `FileChange` clones keep only that side, so trailing badges are `S` / `A` / `M`, not `MS` on a split row. Anything that switches on `kind` — `node_segments`, fold walks, `has_children`, `repo_path_of` — must handle `Checkout` and `Section`. `repo_path_of` / graph drill: checkout → its path; family container → primary checkout path; file/dir/section → `repo`. Returns `None` for `Group` and `Workspace`, which is what makes `r` on either of them refresh the whole workspace. Section `r` reloads that checkout.

## Ids

Ids are stable path-derived strings, never indices. Three things depend on that:

- After a refresh the cursor is restored by id, so a new file appearing above the cursor does not shift the selection. When the focused id is hidden under a folded ancestor (typical: repo moved into folded `group:no-updates` after pull), ancestors are unfolded so the same entry stays selected. If the id is gone even after unfold (file committed/stashed, ghost expired), ancestor walk uses parent `dir:` prefixes then `repo:` / `checkout:` parsed from the id string.
- The fold set is a set of ids that survives tree rebuilds.
- `watch.rs` attributes file flashes with file node ids and op-row flashes with repo node ids. Chrome flashes walk the tree and skip file nodes — files stay on status+mtime signatures. Chrome identity includes path / branch / sync enum / **sync note** / **HEAD** / change count / fold, so a new local commit on a clean branch or ahead 2→3 is a real update (status, graph, and right pane reload without `r`). Graph and commit-file rows use separate identity maps (`{repo}#{kind}:{id}` and `{repo}#{source}#{row_id}`) so a repo switch is a new list, not a mass flash. Add/update/remove flash the same row only. Classification is `Add` (id in after only), `Update` (signature changed), or `Remove` (id in before only). Fetch / pull / push / default-branch chrome stamps `Update`. Removals keep a ghost row for the 800ms fade. Each kind uses its own four-step background ramp (`flash` / `flash_update` / `flash_remove`). Flash background wins over cursor and search. The cursor bar stays. Status letter colours stay. The live poll is due from the start of `WS_STATUS_WATCH_MS`, not after collect finishes.

## `build_tree` → flatten → `VisibleRow`

`build_tree` groups snapshots by `primary_repo` when set, otherwise `repo`. A sole primary → flat `Repo` (today). Primary + linked → family container with `Checkout` children (primary first, then linked by path). Family attention if **any** checkout needs attention; containers with linked children start **expanded**. Within each attention bucket, families sort by primary path.

The tree paints `visible_for_tree` (`visible_workspace_snapshot`). Hidden ignored stay out unless `.` / `-a` shows them, or a named filter names that checkout or names the primary (linked children included). Hidden ignored includes a linked worktree whose primary is in `ignoredRepos`, even when that linked row is `ignored=false`. They return with `.` / `-a` as a nested family, not a workspace-root orphan. A linked row whose primary is absent from the snapshot still paints (linked-only). A standalone ignored linked path stays hidden until shown.

A checkout needs attention when it has file changes, is not on its effective default branch (`main` / `master` / `develop`, or a sole `defaultBranches` override when configured), has a non-idle sync (`behind` / `ahead` / `diverged`), **or** has an attention sync note (`no commits yet` / `status failed`). Only default-branch checkouts that are clean, up-to-date with upstream, and free of those notes land under `group:no-updates`. Workspace `sync_summary` counts those attention notes (`N attention`) so an attention-only workspace is not reported as `all current`. Empty discovery yields `no repos` (not `all current`).

Per checkout (or flat repo), children are either flat file nodes or a directory trie (tree mode). When that checkout has any staged path, those children sit under `Section` nodes (`Staged` then `Changes`; hide empty) instead of directly under the repo or checkout.

Flatten walks depth-first, emitting a `VisibleRow` per node: `id`, `depth`, `node`, styled segments / trailing, and a plain `label` (used for pane `/` search). Children are omitted when the node's id is in `folds`.

## Fold state

Default folds: ignored repos with children + the `no-updates` group. Non-ignored repos with changes start expanded. `z` toggles immediately and arms a 400ms `zz` window. Second `z` applies that same fold to foldable descendants.

## ViewStack / Enter / Esc

`DrillView` in `tui/drill.rs` is the depth stack (`Graph` = 0, `Files` = 1, `Diff` = 2). `FocusPane` is left or right. Together they are the ViewStack.

| Depth | Left | Right |
| --- | --- | --- |
| 0, repo/dir focused | Workspace tree | Graph |
| 0, file focused | Workspace tree | Worktree `DiffPane` |
| 1 `Files` | Graph list | Commit-file tree |
| 2 `Diff` | Commit-file list + commit-details footer | Commit-scoped `DiffPane` |

`list_focus_target` (`tui/state/`) is the focused list: depth 0 left → tree; depth 0 right / depth 1 left → graph; depth 1 right / depth 2 left → commit files; depth 2 right (and depth 0 file diffs) → none (file-diff focused row). Compare left is commit files. Compare right is none (file-diff). `j`/`k`, `gg` / `G` / Home / End, fold, search, click, and vertical wheel follow that target, not a parked Workspace `drill`. The selected row on an unfocused list still paints a weaker marker (`▏` / `cursorBgInactive`); only keys follow `list_focus_target`. The viewport keeps the focused row near the vertical middle (same rule as the workspace tree). On a focused file diff, `gg` / `G` (and Home / End) move to the first / last row. On a focused commit-file list, `gg` / Home use the first file row (`commit_file_cursor_index` with no path), not flattened row 0 when that row is a directory. `G` / End stay on the last visible row. CSI-u key release does not move and does not clear the `gg` pending (`GPending`). Mouse horizontal wheel (and Shift-wheel) pans the pane under the pointer without moving the focused row. The workspace tree matches the right pane. Trackpad hscroll is SGR `66`/`67`. When a file diff has long lines, that report over the left pane pans the diff. Short tree paths still pan the tree when the painted diff fits. Click still selects. Unshifted `h` / `l` still fold the tree and a focused commit-file folder row (`AppState::hl_folds`).

| Focus / depth | Enter | Esc |
| --- | --- | --- |
| Left (any depth) | Focus right (same stack) | Pop one depth; stay on left (no-op at depth 0) |
| Right, depth 0 | Push commit files when a graph row can drill; stay on right | Unfocus → left |
| Right, depth 1 | Push commit diff; stay on right | Unfocus → left |
| Right, depth 2 (leaf) | No-op | Unfocus → left |

Enter that deepens the stack keeps **right** focus. A pinned icon popover is its own input mode, so Esc closes it before any of this (see **Icon popovers**). Esc cancels visual-line highlight (`V`) first, then an armed search. Esc that pops a depth keeps **left** focus and sets no status. Esc never quits. Right-click is the same step back (`BackClick`).

The status row's Enter / Esc chips follow this table (`chrome::nav_chrome_hint_segments`). `Enter drill` shows only when `AppState::nav_enter_drills` holds: right focus, no compare tab, and a graph commit / stash / uncommitted row at depth 0 or a commit-file (not directory) row at depth 1. Esc reads `clear` while a search is armed, `← <left pane>` from the right pane, `↑ files` / `↑ graph` when it pops depth 2 / 1, and is absent where it does nothing.

`/` saves the bound pane's cursor, scroll, and folds (`SearchOrigin`). Esc while typing (`SearchCancel`) restores them; Enter keeps them until the jump has run, then drops them. The search steps with a direction `dir`. `dir == 0` (each typing keystroke, and Enter) anchors on the `SearchOrigin` cursor and takes the first match after it, so typing recomputes from the origin and never walks on; no hit leaves the cursor at the origin. `n` / `N` anchor on the pane's active cursor row: first match strictly after (`n`) or strictly before (`N`), skipping a cursor row that is itself a match. "After" follows the pane's search order: tree flatten order including folded rows, graph visible rows, commit-file painted order including folded folders, painted diff rows (compare-tab diffs too). Past the last or first match the step wraps and sets info `search wrapped to top` (forward) or `search wrapped to bottom` (backward); landing back on the only match counts as a wrap, and no matches at all say `no match` with no wrap notice. Both notices also show on the typing line before Enter. `AppState::search_match_position` gives the `3/7` count for the armed-search pill for the landed match.

## Compare tabs

Compare is a session tab, not a `DrillView` depth and not a `NodeKind`. `tui/tabs.rs` keeps a permanent Workspace tab plus compare, file, and Explorer tabs (`SessionTab`, see **File tabs** and **Explorer tabs**) in one creation order with one id counter. Identity is `(checkout_path, base_ref, head_ref, worktree_file)`; `worktree_file` is set only on a commit-vs-working-tree tab (see below). `head_ref` is `HEAD` (`COMPARE_HEAD_REF`) on a live tab (Diff vs default / branch / commit), which diffs against the checkout's HEAD at each load. A full commit id pins the head (Diff commit vs parent). The same base with another head is a second tab; the same identity focuses the existing tab. The strip label is `<checkout-leaf> ↔ <base-ref>` (bidirectional arrow; left is the checkout leaf, right is the base ref). `tabs::short_rev` shortens a leading 40- or 64-hex object id to 7 chars and keeps any suffix (`abc1234^`); branch names and `HEAD` pass through. The strip label, the range header and `short_label` (`main...HEAD`, or `abc1234^...abc1234` on a pinned tab), and the empty / error copy (`No committed changes vs …`, `Base ref not found: …`, `No merge base between … and …`) use it. Workspace cannot close. Click `[✗]` on a compare tab to close that tab. Workspace never paints a close control. Close activates the tab to the left. Tabs are session-only.

A compare tab is depth 0. Left is the committed `base...head` file list. Right is `DiffPane`. There is no graph and no nesting. Opening Diff vs * from a Files or Diff drill keeps that `drill` parked for Workspace restore. Workspace park also stores that session's commit-file folds and trie mode. Each compare tab stores its own folds and trie mode. The compare tab still paints DiffPane on the right. It does not persist `drill` on the tab and does not paint the parked Files view. New tab: left focus, first file selected, that diff loads. Enter left → right. Enter right is a no-op. Tab switches panes. After overlay cancel, Esc on compare right focuses left. Esc on compare left does nothing (the tab stays; close it with the `[✗]` click or the `:` Close tab command). Esc on Workspace while a compare-picker job is in flight (picker not open yet) abandons that job so a late result cannot open the overlay.

`CommitFileSource::Compare { base_ref, head_ref, base_tip, merge_base, head }` is the immutable load key. `base_ref` and `head_ref` are the tab key; `head` is `head_ref` resolved. `Effect::LoadCompareRange` and `Effect::ProbeCompareTab` carry `head_ref`, and `compute_compare_range` / `probe_compare_range` resolve it instead of a literal `HEAD`. An unborn live HEAD is `HEAD has no commit`; a pinned head that does not resolve is `Head ref not found: <short sha>`. File list and diff reuse the commit-file / `DiffPane` paint path (`E`, `Ctrl-o`, `/`, selection, external diff). The diff section label is `COMMITTED`. `e` / `E` / `Ctrl-o` on a compare tab use that tab's committed file only. They do not fall through to a parked Workspace dirty file. Empty list or a dir row: `focus a file to edit` / `focus a file to diff`. Space marks that committed file reviewed with the workspace-tree eye. The mark lives in session-only `CompareTab.reviewed` (path → merge base + HEAD). It never writes `viewed-files.json` and does not change Workspace marks. A new HEAD or merge base hides it. A moved base tip alone keeps it. Empty list or a dir row: `focus a file to mark reviewed`.

Palette commands (Quick Open commands only: `:`, or `>` first in files mode; the four Diff rows paint no key chip, Close tab paints `Ctrl-w`): Diff vs default in new tab, Diff vs branch in new tab…, Diff vs commit in new tab…, Diff commit vs parent in new tab, Close tab. The filters `vs default`, `vs branch`, `vs commit`, `vs parent`, `new tab`, and the alias `compare` find the open rows. Concrete checkout for Diff vs default / branch / commit: flat repo / checkout / section / dir / file, or the checkout that owns the active graph / drill, or the active compare tab. Not Workspace, No-updates, or a family container. Unborn HEAD disables all three. Missing default disables Diff vs default. Diff commit vs parent needs the graph pane to focus a commit row (`AppState::graph_commit_focused`); uncommitted, stash, and worktree rows, the tree, and a compare tab refuse with `focus a commit to diff`. A root commit refuses with `root commit has no parent`. It opens `<sha>^...<sha>` with the head pinned to `<sha>` on the repo that owns the loaded graph (the repo graph `b` / `m` act on), labelled `<checkout-leaf> ↔ abc1234^`. `^` is the first parent, so a merge shows its changes against its first parent. It never checks anything out and does not change Enter or the commit drill. One gate, `AppState::compare_refusal` (`tui/state/dispatch.rs`), refuses on dispatch and in the palette with the same copy. It checks the open commands above on every tab first, then refuses compare-tab actions. Stage and Unstage (whole file or highlighted lines) show `cannot stage a compare diff` / `cannot unstage a compare diff`. Fetch / pull / push, default branch, branch actions (including `BranchSubmit`, which also runs the picker create row), create-branch, the stash menu, graph writes and graph focus, and worktree remove show `Switch to Workspace tab`. `x` (whole file, or highlighted lines) reverts to the compare **merge base** in the worktree, and runs only while `AppState::compare_revert_target` holds: the tab and the open diff are loaded for the current range and path (`CompareTab::loaded_diff_path`, keyed by `CompareTab.content_for`, because `tab.path` moves when a diff load is queued), the snapshot HEAD of the checkout equals the compare head, and neither the file nor a rename's old path has a change against HEAD. A tab with a pinned head refuses first with `cannot revert a committed diff`. Otherwise `x` and both palette Revert rows show that reason (`compare diff still loading`, `compare is stale: HEAD moved`, `<path> has uncommitted changes`, `focus a file to revert`). Whole-file `x`, its hint chip, and the palette Revert row also refuse a status other than `M` / `A` / `D` / `R` (`cannot revert a <status> change`, `AppState::compare_file_revert_refusal`). Compare `x` also runs from the focused diff with no highlight (the open file), which Workspace `x` does not. It opens `PendingConfirm::CompareRevertRange` or `CompareRevertFile` (`y` confirms, Enter names the key that does, `n` / Esc cancels, `Y` keeps it open). Confirm `y` / `Y` on a compare tab accept only those compare-owned variants; any other pending confirm shows `Switch to Workspace tab`. A compare confirm that somehow reaches another tab is cancelled, not run. `y` emits `Effect::CompareRevertPatch` or `Effect::CompareRevertFile`; the write worker checks HEAD and cleanliness again with git before it writes (see [git-operations.md](./git-operations.md)). The compare diff does not change; the status points to the Workspace tab. The hint row on a compare tab reads the compare tab, not the parked Workspace tree row. Outside highlight it can show only `x` / `e` / `space` / `Ctrl-o` (`COMPARE_HINT_ACTIONS` in `tui/chrome.rs`), and `x revert to merge base` only while `AppState::compare_file_revert_refusal` is `None` (the compare gate, then a file status of `M` / `A` / `D` / `R`). The VISUAL row drops `s u` and shows `x revert to merge base` only while `AppState::highlight_revert_refusal` is `None`. `V` visual highlight, copy entity reference (`'`, with the range while highlighted), line comments (`;`, overlay Ctrl-r resolve), and comment export (`y`) are allowed and act on the compare tab's own file (see the comment paragraph below). Switching or closing a tab (keys, palette, or a mouse click on the strip) clears the visual highlight and any pending confirm, so neither follows onto another tab's diff. A late Workspace branch-picker or stash-menu prepare that finishes after a tab switch does not open.

`GPending` before `normal_key`: `g` → `MoveToStart`, `t` → `NextTab`, `T` → `PreviousTab`, `1`…`9` → `JumpToTab` (`1` is Workspace), `x` → `OpenPullRequest` (no Ctrl / Alt / Super / Hyper / Meta; those fall through to `normal_key`), Esc no-op. Bare `t` stays tree/flat. Bare `T` stays theme. Bare `x` stays revert. `gg` stays start. Watch ticks, mouse move (`None`), and key Release do not clear `GPending`. A typeless CSI-u Press of the same `g` / `t` / `T` / `1`–`9` key inside a few milliseconds (`G_CHORD_PROTOCOL_ECHO_MS`) is the release of that tap and is dropped. VTE often reports that release as Press when event types are missing. A later typeless `g` (one CSI-u per tap), including a fast human `gg` under 80ms, completes `gg`. A completing `g` does not eat the next `g` of `gt` after that burst. A raw-byte second `g` also completes `gg`. When the `g` pending expires, the echo for that arming `g` is cleared. A real Release also clears the echo. That keeps `gt` / `gT` as tab actions on compare tabs. Tab actions are `BusyAction::Handle`. Bare `t` on a compare tab toggles that tab's commit-file trie and keeps the focused file row. It does not change the parked Workspace trie.

The compare picker is `InputMode::ComparePicker` (`AppState.compare_picker`, a `tabs::ComparePickerState`). Diff vs branch lists local + `origin/*`. It drops `origin/HEAD` and the current local branch. Empty copy is `No branches to compare` (no branches) or `no branch matches <filter>`. Diff vs commit lists HEAD's ancestors newest first, HEAD excluded, including merge-side ancestors, capped at the 10,000 newest (`git::COMPARE_PICKER_COMMIT_LIMIT`). Its title reads `Compare vs commit <checkout>`; rows paint `<short sha>  <subject>`. The filter is a case-insensitive substring of the full sha, short sha, or subject. Empty copy is `No commits to compare` (no ancestors, for example a root HEAD) or `no commit matches <filter>`. Enter opens or focuses a live tab with `base_ref` = the picked full sha and `head_ref` = `HEAD`, labelled `<checkout-leaf> ↔ abc1234`. Both kinds share the one overlay and its key rule (printable keys filter; ↑/↓, Ctrl-n / Ctrl-p, Ctrl-j / Ctrl-k move; Backspace edits; Enter submits). No create, checkout, or fetch. Esc sets `compare cancelled` (info). `Effect::PrepareComparePicker` carries the kind (`ComparePickerKind`); both kinds share `request_prepare_compare`, so a newer request drops an older result of either kind. Apply also requires `compare_picker_pending` to still match that checkout.

A commit-vs-working-tree tab (`Blame: diff commit to working tree`) diffs one file at a commit against that file on disk now. `CompareTab.worktree_file` (`tabs::WorktreeFile { path, old_path }`: the path on disk, and the path at the commit when it differs) is part of the identity, so it never shares a tab with Diff vs commit's `<sha>...HEAD`. `base_ref` is the full commit id and `head_ref` stays `HEAD`; no revision stands for the working tree. The strip label is `<file-leaf> ↔ abc1234` (the file name, as on a file tab); the range header reads `abc1234 ↔ working tree` and `short_label` `abc1234 vs working tree`. The range job (`Effect::LoadCompareRange` copies the tab's file into it) runs `compute_worktree_compare_range`: resolve the base (`Base ref not found: …`), then list the one path into `CommitFileSource::CommitVsWorktree { base, path, old_path }`. The diff runs `git diff -M <base> -- [<old>] <path>`, and its section label is `WORKING TREE` (`DiffContent.vs_worktree`). Empty copy is `No changes` / `No changes vs abc1234`. Refusals, on a key and in the palette alike: `x` shows `cannot revert a working-tree compare` (first in `compare_revert_target`); Space shows `reviewed marks need a commit range`; `;`, `'`, `y`, and `E` show `not available on a working-tree compare` (`compare_refusal`); stage / unstage refuse as on every compare tab, and `build_partial_patch` refuses the section as a backstop. Line comments do not paint (the source has no line commit). The HEAD probe below skips this tab. Instead, each checkout status load calls `AppState::worktree_compare_reload` for the active tab of that checkout. It builds a stamp from loaded state only: the checkout HEAD, plus the snapshot change row and tree row signature (status, size, mtime) of the path and old path. When the stamp differs from the one stored at open or at the last reload, it reloads the range with `LoadCompareRange` (forced), so the file row follows the disk; the range apply keeps the open path and reloads its diff in place (viewport kept). Only the active tab reloads on a status load; a tab that becomes active again (tab switch, or the blame action focusing it) runs the same check. `E` has no LEFT / RIGHT pair here (`external_diff_kind` is `None`). No git runs on the event thread.

A background probe reloads a compare tab only when that tab already recorded both SHAs and the head or the base-tip SHA then changed. The probe resolves the tab's `head_ref`, so a pinned tab (head `<sha>`, base `<sha>^`) never reloads when HEAD moves. Missing SHAs (first load) and tabs still `loading` are not a change. Dirty-only ticks do not reload. **Refresh** forces. Apply is generation-safe and does not steal focus. A late compare-file diff whose request id is not that tab's latest is dropped. Queueing a file diff records that path on the tab so a return trip queues a new request. Workspace pane loads (`LoadRightPane`, graph autoload, commit-files apply) do not run while a compare tab is active. Write and merge completion do not recapture the right pane. Parked Workspace `drill` / graph stay until the Workspace tab is active again.

Left-pane `j`/`k`, click, vertical wheel, and search next/prev load the matching right pane through `Effect::LoadRightPane` (TTY: `spawn_blocking` + coalesced request id). Mouse horizontal wheel over the workspace tree pans without `LoadRightPane` (SGR `66`/`67`). Depth 1 graph rows load that commit / stash / worktree's files. Depth 2 file rows load that file's commit diff. A depth-2 or compare-tab directory row shows a folder summary in the right pane: every changed file under that folder (files under folded subfolders too), each with its status badge and `+added −deleted` line counts. Moving onto a file loads its diff. The file that was open before repaints with no reload. While a folder summary shows, keys that act on a file diff refuse with their existing copy (`e`, `E`, `Ctrl-o`, `V`, space, stage / unstage / revert, right-pane `;` / `'` / `y`). A background reload, or a right-pane `j` / `k` or `gg` / `G`, behind the summary resets the hidden diff to its first row. Esc/back and the depth stack stay unchanged. A focused-repo watch/status result that changes checkout or file identity enqueues `LoadRightPane` immediately — it does not wait for the rest of the workspace.

## File tabs

A file tab is the third tab kind (`SessionTab::File`, `tabs::FileTab`): a read-only viewer of one file of one checkout, opened from Quick Open files mode or from a search-in-files hit (see **Keymap**). Enter in Quick Open opens the highlighted file in a new tab at the end of the strip, or focuses the tab that already shows it: identity is `(checkout, rel)` (`TabStrip::open_or_focus_file`). Compare and file tabs share the strip in creation order and one id counter, so a file tab between two compare tabs closes without moving them. The strip label is the file name; the pane title is `<checkout>/<rel>`, where `<checkout>` is the snapshot `repo` path (unique per checkout, so two checkouts that share a folder name stay apart). Close it with the `[✗]` click, `Ctrl-w`, or the `:` Close tab command (`Action::CloseTab`, the same action that closes a compare tab); Esc does not close it. Closing activates the tab to the left, as for compare tabs. Opening a tab parks the active session first. A file tab keeps only its own search (`search_mode` / `search_active` / `search_query` / `search_hit`, bound pane `SearchPane::File`) plus its `cursor`, `scroll`, and `col_offset`; it never writes or takes the Workspace park, so closing it (or switching back with `gt` / `gT` / `g1`) restores Workspace focus, search, and diff viewport unchanged. The body loads on the blocking pool (`Effect::LoadFileTab` → `UserTag::QuickOpen` → `file_index::read_text_file`) on open, `r`, editor return, and live reload, and lands through `AppState::apply_file_tab`, which drops a result for a closed tab or an older load generation. The cursor and scroll keep their line numbers, clamped to the new line count. `r` reloads (new generation; the body shows loading until the read lands); `e` opens the file in the editor at the cursor line (`Effect::EditFile { line: Some(cursor + 1) }`, no line for a binary or too-large body) and a TTY editor that returns reloads the tab. Live reload (`AppState::file_tab_live_reload`): each load records the file's own disk token in `FileTab::disk_stamp` (`size:mtimeMs`, or `gone` when missing; one `stat`, no git). After each checkout status load of the watch poll, the active file tab of that checkout stats its file and reads it again only when the token moved. A clean, untracked, or ignored file works the same. A background file tab is not checked; when it becomes active again (`gt` / `gT` / `g<n>`, a tab click, closing the tab in front of it, or Quick Open on the open file) it checks once. The refresh is silent: no status, and the old body stays painted until the new read lands (`FileTab::bump_generation_keep_body`; search hits and line blame key on `FileTab::body_generation`, the generation of the painted body). A deleted file keeps the tab open on the last content and warns `file deleted`; a silent read that fails also keeps the old body. `r` on a deleted file drops the body and shows the read error. While an overlay holds input (`overlay_blocks_background_ticks`), a late status result neither reloads nor records the token, so the next poll catches the change. Keys: `j` / `k`, PgUp / PgDn, Ctrl-u / Ctrl-d, `gg` / `G`, Home / End, and the vertical wheel move the line cursor; `h` / `l`, arrows, and the horizontal wheel pan (not while wrap is on); `\` toggles wrap (the shared `diff_wrap`, so a file tab opens wrapped by default); `/`, `n`, `N` search the lines (case-insensitive substring; like the other panes, a step lands on the first match after the cursor, `N` the last one before it, and wraps with `search wrapped to top` / `search wrapped to bottom`); `'` copies a file entity reference (`kind: file`); click focuses a line and a drag copies the selection. Esc clears an armed search and otherwise does nothing; Enter, Tab, `t`, `.`, `i`, `M`, `-` / `+` / `=`, `<` / `>` do nothing; `z` says `z folds tree rows`. Git writes, comments, highlight, diff-only keys (`E`, `Ctrl-o`, space) and the Diff … in new tab commands refuse with `Switch to Workspace tab` on a key press and in the palette (`AppState::file_tab_refusal`, checked before the compare gate). So do `y` / `Y` on a confirm that a late checkout or merge result opened over the file tab (`n` / Esc still close it). The palette also disables the Workspace view rows that do nothing on a file tab (Flat / tree, Show ignored, Inline / split, Narrow / Widen tree, Other pane, Collapse / expand commit message) with that copy. Wrap paint counts at most one screen of rows per line (`search::wrap_col_starts_capped`), so a 2 MiB single-line file stays O(viewport). A file tab's Quick Open scope is its checkout. Workspace pane loads, graph autoload, and write completion do not recapture the right pane while a file tab is active (`!tabs.is_workspace()`), as on a compare tab.

## Explorer tabs

An Explorer tab is the fourth tab kind (`SessionTab::Explorer`, `tabs::ExplorerTab`): a VS Code-style file tree of one checkout beside a preview of the focused file. Identity is the checkout (the snapshot `repo` string): one Explorer tab per checkout (`TabStrip::open_or_focus_explorer`). It shares the strip, creation order, and id counter with compare and file tabs. The strip label is `Explorer · <checkout leaf>`; the tree pane title is the checkout path.

`-` (`Action::ExplorerReveal`) opens it. On the Workspace tab with the tree focused and a focused row that belongs to a checkout, `-` opens or focuses that checkout's Explorer tab (`AppState::open_explorer_tab`). The checkout is `focused_checkout_path`, the Quick Open rule: a family's repo row is its primary checkout, a linked worktree row (or a row under it) is that worktree. A file row expands its parent folders and puts the cursor on the file (`ExplorerTree::reveal`); a folder row expands that folder with the cursor on it; a repo, checkout, or section row opens at the root. On a reused tab, a folder on the path whose cached listing lacks the next step (a file or folder created since it was listed) lists again (`ExplorerTree::stale_on_path`); the cursor waits on the target and lands on it when that listing arrives. A workspace or group row, another focused pane (where the commit message shows), and compare and file tabs keep today's `-` (`ResizeCommitMsg(-1)`; a file tab ignores it, as it ignores the other commit-message keys), with no refusal. On an Explorer tab `-` moves the cursor to the parent folder (`ExplorerTree::cursor_to_parent`); it never resizes the commit message or opens a second tab.

The tree (`tui/explorer.rs`, `ExplorerTree`) lists a folder only when it is expanded (at first only the root). Each listing is `Effect::LoadExplorerDir { tab_id, req, repo, rel_dir, parent_ignored }` on the blocking pool (`UserTag::QuickOpen` → `explorer::list_dir`: `read_dir` plus one `git check-ignore -z --stdin` for the folder's children; a folder under an ignored folder skips git). It lands through `AppState::apply_explorer_dir`, which drops it unless `req` is the folder's newest request on the tab (`ExplorerTab::dir_reqs`); a read error lists the folder empty and says why. Ignored entries (`node_modules/`, `target/`, `.next/`, …) are always listed and paint dim; there is no `.` toggle. `file_index` is not used (it drops ignored paths). Status letters and folder marks come from the live snapshot's `changes` for the checkout at paint time (`AppState::explorer_status` → `ExplorerStatus::from_changes`), so they follow every status reload; files that git reports deleted still show as rows. The index is memoized per checkout and a fingerprint of its changes, and paint walks the rows once per frame (the breadcrumb reads the painted cursor row, `ExplorerTab::painted_rel`). Listings follow new status paths on the watch poll: after each checkout status load (`AppState::explorer_status_relist`, next to the file-tab live reload), every Explorer tab of that checkout lists again each open, visible folder whose cached listing lacks a path the status now reports (a new untracked file or folder; deleted paths are skipped, since they already merge in). A folder with a listing in flight is not asked twice, and a status path that sent a re-list sends no other while it stays in the status (`ExplorerTab::status_relisted`); only the path that first finds a folder stale is marked, so many new files in one folder send one listing and mark one path. A poll with nothing new sends nothing, and the check is linear in the status (set lookups against each listing's name index) and skipped entirely when the checkout has no Explorer tab. The cursor keeps its rel.

The preview follows the cursor row (`explorer_preview_effect`). A file with a snapshot change loads its worktree diff (`Effect::LoadExplorerPreview { change: Some(..) }` → `diff::load_file_diff`, the Workspace diff pane's load and `-U` context) and paints through the diff pane. A clean file loads its body (`read_text_file`, 2 MiB cap) and paints like a file tab (text, binary notice, too-large notice). A folder row clears the preview to a short hint. Both panes go through the shared pane chrome (`render::draw_pane_chrome`): boxed with `viewDefaults.background` `"terminal"`, flat in paint mode (tree on `sidebar`, preview on `surface`, accent line under the focused title). `LayoutHit.explorer_tree` / `explorer_preview` hold the content rects, so clicks and the wheel hit the painted rows in both modes. Each new pick bumps `ExplorerTab::preview_gen`, and the interpreter keeps one queued preview per tab (latest-only); `AppState::apply_explorer_preview` drops a result for a closed tab, an older generation, or the other body kind.

Session state: the tree (expanded set, listings, cursor), `dir_reqs`, the preview, `tree_scroll`, and the parked pane focus and diff view (`focus_preview`, `diff_cursor`, `diff_scroll`, `diff_col_offset`), saved by `park_active_session` and restored by `apply_active_session`. It never writes or takes the Workspace park. The Explorer has no `/` search: `/` says `no search on the Explorer tab · Ctrl-f searches files`. Quick Open and search in files (`Ctrl-p` / `F` / `:` / `Ctrl-f`) scope to its checkout (`quick_open_scope`).

Keys (`AppState::dispatch_explorer_tab`): in the tree `j` / `k`, PgUp / PgDn, Ctrl-u / Ctrl-d, `gg` / `G`, Home / End move the cursor (placeholder rows are skipped); `l` opens a folder; `h` closes an open folder, and on a file or a closed folder jumps to the parent folder (a root-level row stays); Enter (or `z`) opens or closes a folder and on a file moves focus to the preview; Tab switches panes. In the preview the same move keys move the diff cursor or the file line cursor, Shift-←/→ and the horizontal wheel pan, and Esc, `h`, or a right click give focus back to the tree. `r` re-lists the visible open folders (`ExplorerTree::invalidate`; the old rows stay until the new listing lands) and reloads the preview. `e` opens the focused file in the editor (at the preview's line for a text body; a folder says `focus a file to edit`), and a TTY editor that returns reloads the preview. `'` copies a file entity reference of the focused file. `\` and `i` act on the preview. Mouse: a click on a tree row moves the cursor there (a folder also opens or closes), a click in the preview focuses it, and the wheel moves the cursor of the pane under the pointer; nothing reaches the hidden Workspace tree. `t`, `.`, `M`, `+` / `=`, `<` / `>` do nothing. Close with `[✗]`, `Ctrl-w`, or `:` Close tab (`Action::CloseTab`); closing activates the tab to the left.

Refusals (`AppState::explorer_tab_refusal`, checked first in `dispatch` and in `palette_disabled_reason`): stage, unstage, revert (`s` / `u` / `x`), stash, fetch / pull / push / default branch, branch and worktree writes, graph actions, comments, highlight, `E`, `Ctrl-o`, space, the Diff … in new tab commands, the blame actions, and `y` / `Y` on a late confirm warn `Explorer tab is read-only · switch to Workspace tab`. The palette also disables the Workspace view rows (Flat / tree, Show ignored, Narrow / Widen tree, commit message rows) with `Switch to Workspace tab`. No line blame paints in the preview.

## App state

`AppState` in `tui/state/` holds restorable view state: cursor row id, folds, filter, diff mode (`viewDefaults` seed the launch values of `tree_mode`, `commit_tree_mode`, `diff_mode`, `diff_wrap`, `commit_msg_expand`, `commit_msg_lines`, `line_blame`, and `background` once in `AppState::apply_view_defaults`, called from `run_tui` after `AppState::new`; `commit_tree_mode` is also kept as `TabStrip::commit_tree_default`, the mode each new compare tab opens in; toggles never write them back), `diff_wrap` (`\` soft word-wrap on file diffs; on by default, `viewDefaults.wrap` sets the launch state; the toggle changes this session only and nothing writes a pref file), `commit_msg_expand` (on by default, `viewDefaults.commitMessage` sets the launch state; session toggle only: the selected commit / stash message wraps in the graph footer and commit-files footer; `M` collapses; graph list rows stay one line), `commit_msg_lines` (N, the fixed message rows of the expanded graph footer and commit-files footer; default `COMMIT_MSG_LINES_DEFAULT` (4), clamped to 1–20; `viewDefaults.commitMessageLines` sets the launch value; `-` / `+` (`=` is `+`, `Action::ResizeCommitMsg`) change it for this session only with status `msg lines <N>`; `M` and a change of N re-run `sync_graph_scroll` so the focused graph row stays in view), `line_blame` (`LineBlameState`: the `B` toggle, on by default, `viewDefaults.lineBlame` sets the launch state, session only; plus a cache of focused-line blame answers keyed by `BlameKey` (checkout, revision, path, line, content epoch), capped at 512 entries and cleared when the toggle goes off) and `commit_msg_scroll` (wheel over an overflowing graph footer; keyed by graph row identity, so another selection starts at the top), full-context ids, tree mode, mouse enabled, theme, `background` (`BackgroundMode` in `tui/theme.rs`: `Paint`, the launch default, fills panes and chrome rows with theme colours; `Terminal` keeps boxed panes on the terminal background; `viewDefaults.background` sets it, no session toggle; the `#[cfg(test)]` `AppState::new` fixture pins `Terminal` so render tests keep the boxed look), nav (focus pane + drill depth), `diff_cursor`, `diff_col_offset`, `left_col_offset`, `right_col_offset`, session-only `tabs` (Workspace plus compare and file tabs, with per-tab compare reviewed marks and per-file-tab search, cursor, and scroll), session-only `quick_open` (`:` commands / `Ctrl-p` or `F` go to file overlay), session-only `search_files` and `search_files_parked` (the open Ctrl-f search-in-files dialog and the last closed one, kept for the restore rule), session-only `diff_visual_anchor` (`V` visual-line highlight on a focused file diff), and the transient mouse `text_selection` (press in a pane body, drag, release copies; cleared by any press, a splitter drag, a modal open, `m`, and resize). The file-diff viewport (`diff_cursor` / `diff_scroll` / `diff_col_offset`) belongs to one view identity: a workspace `repo`+`path`, or a commit `repo`+source+`path`. A new identity resets those fields to the origin and clears highlight. A same-view reload keeps the viewport. Highlight also drops when the painted row list changes (watch reload, split/inline, resize). Graph window default is 300. Graph branch focus (`o` / `O`) is session-only (`graph_branch_focus`): a per-repo list of local names whose ancestors the graph shows, or `None` for `--all`. Fold, split ratios, pan offsets, theme cycle, graph focus, Quick Open, and search in files reset on the next launch. Tree mode, diff mode, diff wrap, commit-message expand, and commit-message rows return to their `viewDefaults` (or in-app) values. Reviewed marks persist in `viewed-files.json`. Line and object comments persist in `comments.json` (`tui/comments/`, `WS_STATUS_COMMENT_STORE` overrides). Version 2 namespaces both files by workspace identity (SHA-256 hex of the canonical cwd). GC and save replace only the current workspace bucket. A version-1 file keeps its records under `__legacy__`. Load uses that map when the current workspace bucket is missing. GC of one cwd does not drop `__legacy__`. A missing store file starts empty. A present file that is not valid v1/v2 UTF-8 JSON is left unchanged and persist returns an error. A failed persist sets `comment save failed` or `viewed save failed` plus a short IO error on the breadcrumb trailing slot (never `comment saved` / `comment deleted`). Refresh GC uses snapshot `local_branches` and checkout paths (no git on apply or `;`). A primary detached HEAD is a worktree path key, not `HEAD (detached)` as a branch. Commit comments stay while that repo identity is still in the snapshot. Branch and working-tree line comments stay when `git status` fails (`status failed`, empty `local_branches`) only if every checkout of that identity has an empty counted list. A successful sibling's live names win. The GitHub Release startup prompt (`update_check.rs`) runs in the CLI **before** `AppState` exists; it is not session state. `status` is a `StatusMessage` (`tui/status.rs`): text plus a `StatusKind` (info / progress / ok / warn / error) that picks the color and the expiry (info / ok clear after `STATUS_TTL_MS`; the others stay until replaced). A plain `String` / `&str` assigned to it is info. A note that a reload or background job writes goes through `StatusMessage::offer_info`, which leaves a progress / warn / error in place. Set a refusal with `StatusMessage::warn(…)` and a git or IO failure with `StatusMessage::error(…)`.

Full-context membership means unlimited unified context (`FULL_DIFF_CONTEXT_LINES`) for that file id — toggled by `Ctrl-o`, cleared by `Esc` or a second `Ctrl-o`. After a full-file toggle, scroll recenters on the prior hunk/change anchor.

Current-line blame (`B`) asks git only for a focused line: the active file tab's cursor line, or the focused file-diff row while the right pane drives the diff (`ListFocusTarget::None`, no folder summary). Moves in the tree, graph, or file lists never blame. `AppState::line_blame_want` (`tui/state/line_blame.rs`) maps that line to a `BlameKey` per surface: a worktree diff context line blames the working tree, a deleted line in UNSTAGED the index (or `HEAD` when nothing is staged), a STAGED context or deleted line `HEAD`; an added line reads `You · uncommitted` / `You · staged` with no git call; NEW asks nothing. A commit drill blames the commit (new side) or `<sha>^` under the old path (deleted line); a stash `stash@{n}` / `stash@{n}^1`; a compare tab its head / merge base; a commit-vs-working-tree tab the working tree (new side) or the base commit under the file's path there (deleted line). The interpreter reads that key after every `schedule` and `apply` (`Interpreter::maybe_queue_line_blame`). A cache hit runs nothing. Otherwise the key goes into a latest-only slot and one `UserTag::LineBlame` job runs `git blame` on the blocking pool. While it runs, more cursor moves only replace the slot; the apply fills the cache for its key, marks a paint only when that key is still focused, and the hook then asks for the newest line. So at most one job is in flight and one waits. Toggling off clears the cache and drops late answers.

Blame actions (palette GIT rows, right before the Diff … in new tab rows; no key chip): `Blame: open commit changes` (`Action::BlameCommitVsParent`), `Blame: open previous line change` (`BlamePreviousChange`), `Blame: diff commit to working tree` (`BlameCommitVsWorktree`), and `Blame: show commit in graph` (`BlameRevealGraph`). They act on the focused line's cached blame and run on the Workspace, compare, and file tabs. One gate, `AppState::blame_refusal` (`tui/state/line_blame.rs`), refuses on dispatch (next to `compare_refusal`) and in `palette_disabled_reason` with the same copy: `line blame is off (B)`, `focus a diff or file line`, `line blame still loading` (no answer yet, or the file tab is still reading), `line is not committed yet` (a `You · uncommitted` / `You · staged` line, or an all-zero sha), `no blame for this line` (git had none: untracked, binary, hunk header, failed run). Open commit changes opens or focuses the pinned `<sha>^...<sha>` compare tab through the same `open_compare_tab` as Diff commit vs parent, in the surface's checkout; a root (`boundary`) commit refuses with `root commit has no parent`. It never checks anything out. Diff commit to working tree opens or focuses the commit-vs-working-tree tab (see **Compare tabs**) of the blame commit in the surface's checkout: the old path is the line's `filename` at that commit, the disk path is the file tab's file or the open diff's path. A root commit is allowed. Open previous line change emits `Effect::LoadBlamePrevious` with a session generation (`finding previous change…`); the interpreter keeps the latest request in one slot on `UserTag::Prepare` and runs `git::previous_line_change` on the blocking pool. `AppState::apply_blame_previous` drops a stale generation. An earlier commit opens its own pinned `<prev>^...<prev>` tab and the apply returns that tab's `LoadCompareRange`, which the interpreter schedules. A line the commit added warns `line was added in abc1234`; an earlier change in a root commit warns `earlier change abc1234 is the root commit`. Show commit in graph goes to the Workspace tab, leaves a commit drill (`drill = Graph`, `Effect::DropCommitDiff`), puts the tree cursor on the checkout's `checkout:` (else `repo:`) row with its ancestors unfolded, focuses the graph pane, and loads it (`LoadRightPane`) unless the action ran on the Workspace tab with that repo's graph already loaded and the cursor there. From a compare or file tab it always reloads: the Workspace graph does not reload while another tab is active, so the parked graph can miss newer commits. `AppState.graph_reveal` (`GraphReveal { repo, sha, pages, seen_load }`) then selects the row whose `graph_row_id` is `commit:<sha>`, or a stash row with that id, and scrolls to it: at once when that repo's graph is on screen (even while a reload is queued), and after every `set_graph` (pane load or older-page merge). It widens or gives up only after `seen_load`: a `set_graph` since the reveal started, or a graph already shown with no load queued, so a stale graph never ends it early. A graph of another repo, or focus leaving the Workspace graph pane, drops the reveal. While it is still pending, the same post-`schedule` / post-`apply` hook (`Interpreter::after_change`) asks for one older page (`queue_autoload`, the second half of `maybe_queue_autoload`) when the graph has more and no older page is on its way, up to `GRAPH_REVEAL_MAX_PAGES` (10) pages. Past that, or at the end of history, it warns `abc1234 is not in the loaded graph`, plus ` (graph focus on, O clears)` while a graph branch focus is set. The graph selection footer is the commit's details.

`A` opens the blame-actions menu (`AppState.blame_menu`, `InputMode::BlameMenu`, ranked right after the stash menu; `DialogKind::BlameMenu`). It goes through the same `blame_refusal` as the four actions, so it opens only on a committed blamed line and refuses with their copy otherwise (a root commit opens it; `c` then refuses). The header is the focused line's annotation from `painted_line_annotation`, the accessor the pane paints with. Rows are `BLAME_MENU_ROWS` (`tui/line_blame.rs`): `c` open commit changes, `p` open previous line change, `w` diff commit to working tree, `g` show commit in graph. A row key (Enter runs the first) closes the menu and dispatches that blame action, which runs its own gate; other keys do nothing and Esc / `q` close it. Opening it ends a drag text selection, which would hide the annotation. While it is open, keys and mouse input do not reach the panes, background ticks stay off (`overlay_blocks_background_ticks`), and a blame answer that lands does not close it. During a busy write its keys stay live (`BusyAction::Handle`): every row only reads git.

## Graph list

Graph rows come from `workspace-status-graph` `GraphModel::visible_rows`. Graph `o` (graph list or highlighted repo / worktree) can restrict the loaded window to ancestors of selected local branches (`git log <branches>` instead of `--all`); overlay Enter applies visible marks or the cursor row (hidden pre-marks do not leak through a filter). Unmarking every `[x]` then Enter, or `O`, restores `--all`. Stashes park immediately above `stash^1`. Pane `/` matches a graph row on subject, body, author, painted relative date or local `YYYY-MM-DD HH:MM`, UTC `YYYY-MM-DD HH:MM`, branch and tag names, and full or short sha (stash / worktree rows use those fields when present). Graph pane chrome: selection footer when height ≥ 3 (`graph_chrome_budget_for` / `selection_detail_lines` / `selection_detail_parts`; footer preferred, header drops first). The footer height is fixed: `graph_footer_request(commit_msg_expand, commit_msg_lines)` asks for the rule row plus the body: N + 2 rows expanded (N message rows, the meta row), 3 collapsed, never the selected message's line count, so moving between commits never changes the list height. `AppState::graph_chrome_in` and the `GraphWidget` (`.commit_msg_lines(N)`) both use that request, so layout and paint agree. `graph_chrome_budget_for` caps the rows under the rule at half the pane (never under 2) and adds the rule row on top, and it keeps at least one list row. By default (`commit_msg_expand`; `M` collapses) that footer wraps subject plus body (`selection_footer_parts`), and so does the commit-files footer. That footer sits at the bottom of the depth-2 left (commit-files) pane under the file list. It is fixed too (`AppState::commit_detail_footer_request`): expanded is title, meta, then N message rows (blank rows pad a short message; a long one clips with `…` on the last row), collapsed is title plus subtitle (2 rows). `commit_detail_footer_height` adds the rule row on top of `commit_detail_footer_request` (N + 3 expanded, 3 collapsed), and draw and layout size the footer with it, and the list keeps at least one row; a click on it does not pick a file (`LayoutHit::files_list_height`). The graph footer's meta row stays on its bottom row and a short message leaves blank rows above it. The wheel over an overflowing graph footer scrolls the message (`commit_msg_scroll`, `LayoutHit::graph_footer_*`; `graph_footer_line_count` only sizes that scroll) without moving the graph cursor; a 1-column footer scrollbar shows, and while lines are hidden below, the last message row ends with a muted `<more-below><K>` (`GlyphSet::more_below`: U+F103, `v<K>` in ASCII). Graph list rows stay one line. Bodies come from git `%b`, capped at 8 KiB. Uncommitted: `Working tree clean` / `Uncommitted changes` + HEAD commit ref chips, or `worktree · not a commit` when HEAD has none. Spacer: `…` + `connector · not selectable`. Stash: subject + `stash@{n} ·` hash `·` date. Commit: subject + ref chips (or `(no refs)`) `·` hash `·` parents (`parent <id>`, `parents <id> <id>` in git order for a merge, or `root commit`) `·` author `·` date. Empty: `no selection`. Footer chips use the same `LabelKind` palette as the row (HEAD / default / feature / remote / tag), not a flat wash. Graph PageUp/PageDown move in painted list space (`visible − 1` painted lines, snap to selectable); `j`/`k`, click, and vertical wheel stay on selectable `visible_rows`. The viewport keeps the focused row near the vertical middle. The 1-column scrollbar thumb is painted whenever the list overflows, at the top too; the horizontal bar only after the viewport leaves the left edge. Both are mouse-draggable through the same `hit_split` / `SplitDrag` stack as the pane and in-diff splitters (`SplitDrag::GraphScrollbar` / `GraphHScrollbar`); a track click jumps toward that position without moving the graph cursor. File-diff horizontal thumbs use that stack too (`SplitDrag::DiffHScrollbar`) and do not move `diff_cursor`. Tree and commit-file lists pan with the wheel and keys only; they do not paint an h-bar. Horizontal mouse wheel (and Shift-wheel) pans the pane under the cursor without changing keyboard focus (SGR `66`/`67`).

Same-checkout graph reloads (`set_graph`, including a watch HEAD move) keep the focused row by `graph_row_id` (commit sha, stash ref, worktree path, or uncommitted). If that row is gone, the cursor clamps to `min(old_index, n-1)`. A different checkout, a first load, or graph `o` / `O` (new log window) reset cursor and scroll to the top. Branch pickers, the stash menu, Quick Open, and the graph-focus overlay open at row 0. Those lists are new overlays, not in-place watch reloads. Commit-file and compare lists restore by path; a gone path clamps to `min(old_index, n-1)`. File-diff viewports stay on the same identity. A new path or commit-file resets to the origin.

See [git-graph-topology.md](./git-graph-topology.md) and [graph.md](./graph.md).

## Actions and gates

`tui/action.rs` is the single source of truth for which actions exist. `tui/tty.rs` enables mouse (click + button-event + any-event DECSET 1003 + SGR) and decodes TTY SGR reports (`66`/`67` → `ScrollWheel { horizontal: true }`; motion-bit wheel `96`–`99` decodes as the plain wheel; buttonless motion → `PointerMove`). The live loop handles `PointerMove` before busy gating and dispatch: it stores `AppState::pointer`, arms or drops the icon peek timers, and redraws only when the hovered tab `[✗]` or the hovered icon changes. `dispatch(PointerMove)` is a no-op that keeps `g` / `z` chords. `m` clears the pointer. `tui/keys.rs` maps crossterm events to `Action`. `<` / `>` are `Action::ResizeTree(-1 / 1)`: `split::step_tree_fraction` moves the session `tree_fraction` by 5% of the terminal width with the divider drag's clamp. A left press with Ctrl held is `Action::CtrlClick { col, row }`; every other mouse report keeps its action (Ctrl+drag is still `Drag`). `CtrlClick` runs the same path as `Click` (`AppState::ctrl_click` calls `click` first), and opens a PR only when it lands on a painted PR badge; see **Pull request badge and open**. A right-button press is `Action::BackClick` in Normal and `V` modes; a pending `z` / `g` chord maps it like Esc (overlays drop every mouse event); dispatch runs `DiffVisualCancel` in highlight, otherwise `NavEsc`, and nothing while mouse capture is off. Highlight has no `GPending` mode: the second `g` of `gg` dispatches `ArmGChord`, which moves to the top while the first `g` is still pending; `;` then attaches the comment to that line span; on a working-tree file diff `s` / `u` stage / unstage the highlighted add/del lines (or the hunk covering that range) and do not whole-file stage. `x` builds a reverse patch of the highlighted unstaged lines, clears the highlight, and opens `PendingConfirm::RevertRange`; `y` emits `Effect::RevertPatch` (worktree only), `n` / Esc sets `revert cancelled`. On a commit / stash / worktree drill diff, `s` / `u` / `x` refuse with a breadcrumb (no `git apply`). On a compare diff `s` / `u` refuse, and `x` builds the reverse patch from the COMMITTED section (`PartialPatchKind::RevertCommitted`) and opens `PendingConfirm::CompareRevertRange` (see Compare tabs). Without highlight, `;` opens the stored span that covers the focused line (smallest inclusive span, then lowest start line, then key order). A compare diff line (or highlighted span) is keyed `CommitLine { repo, sha: <compare head>, path, line, end_line }` (`CommitFileSource::line_commit`): the new-side numbers are the head blob's, the same key a commit drill of that head uses, so the store format does not change. Delete-only rows fall back to the merge-base line number, as on a commit diff. After HEAD moves and the tab reloads, those comments stay in the store but no longer paint on that compare diff. On a compare tab the comment target, diff line marks, commit-file row marks, and `y` scope come only from the tab's checkout, file, and range (`AppState::open_diff_target` / `commit_drill_source`), never from the parked Workspace diff, so a Workspace worktree comment does not paint on a compare diff line with the same number. A compare file-list row has no line target (`no comment target`), the same as a commit-file row. Empty Enter deletes that span. Esc leaves highlight without commenting. `:` opens Quick Open commands over the range (see Keymap). Watch reload, split versus inline, or a painted-row change drops highlight. The diff gutter reserves a comment-mark column on every numbered cell so the line numbers do not shift when a comment appears. Open comments paint `ICON_COMMENT` (`"` / nf-fa-comment). Resolved comments paint `ICON_COMMENT_RESOLVED` (`'` / nf-fa-comment-o). Workspace, group, section, dir, file, and default-branch rows are not object-comment targets. If a repo has exactly one non-default branch, a comment that would have attached at repo scope attaches to that branch. A primary detached HEAD is a worktree path key. Graph rows paint the comment glyph when the row has an object comment or a file-line comment (resolved glyph when every comment on the row is resolved). Commit-file rows paint the same trailing mark when that file has a line comment. `y` copies live comments as markdown after GC for the **focused** tree / graph / commit-file / diff row and descendants under that row (a file copies that path only; a folder copies files under it). Unrelated siblings stay out. The workspace row copies every live comment. A family row copies Worktree object comments for every checkout of those identities, plus comments keyed by the identity path. A linked-worktree row copies Worktree comments keyed by that family identity and by this checkout path. Branch and commit comments keep identity matching. Matching uses `repo_identity` and snapshot checkout paths, not a path prefix. Unrelated repos stay out. Family and linked-worktree comment marks use the same rule. Resolved comments stay in that copy and carry `[resolved]`. A line comment with a newline stays one markdown bullet. Continuation lines are quoted. Confirm-mode `y` is still revert-yes. `'` copies a pasteable entity reference for the focused tree / graph / commit-file / numbered-diff row. Status is `copied` when the copy succeeds. Status is `copy failed` when OSC 52 and the host tool both fail. No overlay. No comment store write. Search still types `'`. `;` is unchanged.

Visual-line `x` bypasses it too and confirms `Effect::RevertPatch`. Section headers take every dirty file on that side of the checkout; dirs under a section stay on that side. Family containers, workspace, and group yield no files. Write scope for bulk git (`f` / `p` / `P` / `d`): primaries on workspace/family rows; a linked worktree only when that row is focused; hidden ignored-list paths omitted even if focused. When ignored repos are shown (`.` / `-a`), they follow the same primary / focused-worktree rule. Background fetch uses `background_fetch_targets` and skips hidden ignored repos.

Independent checkouts run fetch / pull / push in parallel (`FETCH_CONCURRENCY` = 10) on the per-gitdir remote queue in `tui/effect.rs`. Occupy key is `primary_repo` when set, else the checkout path. A second `f` / `p` / `P` enqueues. Pending jobs coalesce on that checkout. `Fetch` / `Pull` / `Push` / `FetchTick` are `BusyAction::Handle`. ## Pull request badge and open

`Action::OpenPullRequest` (`gx`, palette Open PR) and `Action::CtrlClick` on a badge share one target rule and one effect. `AppState::pr_target_for_focus` (`tui/state/pull_request.rs`) returns the checkout path and branch to look up:

- Tree: the focused `NodeKind::Repo` or `NodeKind::Checkout` row with a branch (primary or linked). A repo row that groups several checkouts (`chrome.is_family`) has no target.
- Graph: the focused `GraphRow::Worktree` row with a branch.
- No target: a commit, stash, uncommitted, dir, file, workspace, or group row, commit files, a diff, a file or compare tab, and a detached or unknown HEAD. The status is `no PR for this row` (warn) and nothing runs. The same text covers a Ctrl+click on a badge whose checkout no longer has a branch.

A target becomes `Effect::OpenPullRequest { repo, branch }`. A Ctrl+click on a badge returns `Effect::Batch([<click effect>, OpenPullRequest])`, so the right pane still follows the selected row; it also clears `last_click`, so a second Ctrl+click opens again instead of drilling. The badge cells are icon hits (`LayoutHit.icon_hits`, `IconTarget::PullRequest(checkout)`), read as `PrBadgeHit { y, x, width, repo }` through `LayoutHit::pr_badge_hits`: each frame clears the list first, and the tree and graph painters push one entry per painted badge, so a hit is always a badge on screen. Ctrl+click off every hit is a plain click and pins no popover; a plain click on a badge selects the row and pins its popover (see **Icon popovers**). A file tab paints no badge, so both clicks behave alike there.

The PR cache (`PrCache` in `AppState`) holds, per checkout path, the branch it was looked up for and the remote URL the worker resolved, and, per (remote URL, branch), the forge's answer: a PR that counts, no PR, or a failed lookup. The remote URL is not in the snapshot, so it exists only after the worker answered. `AppState::pr_badge` gives a badge only for a ready answer that belongs to the checkout's current snapshot branch. In flight, failed, no PR, closed-unmerged, or another branch's answer: no badge.

The cache also holds the PR popover detail per (remote URL, branch): `PrDetailState::Loading`, `Ready(PullRequestDetail)`, or `Failed`. `request_popover_pr_details` marks a detail loading and returns `Effect::LookupPullRequestDetail { repo, branch, remote, number, request }` for each PR the open popover shows that has no detail yet; `request` is a new id per request, kept in `Loading(request)`. It runs when a peek opens (`expire_peek_with_details`, called by the event loop's `peek_remain` arm) and when a popover pins (a click on an icon, a click inside a peek, `gh`); a watch or fetch tick never calls it, so each PR is asked once and later hovers and pins read the cache. A failed detail is not asked again until it is dropped. The detail is dropped when the checkout leaves the branch (pruned with the answer), on `r` and on a full reload, when the checkout vanishes, and when a new badge or `gx` answer for the branch differs from the cached one (`PrCache::set_answer`). `apply_pr_detail` drops a result whose checkout is on another branch, was forgotten, resolves another remote, whose answer names another PR, or whose detail no longer waits for that request id. So after `r`, a late answer to the old request (a hung CLI that times out) cannot replace the answer to the new one. When a detail lands under a pinned popover, the focus stays on the line it was on (same section, same field label or action title), since the new fields push Open PR and the URL down. A pin picks its landing line after the request, so it counts the `loading…` line.

A badge lookup is due (`due_pr_lookups`) when a checkout shows a branch it has no record for: first sight, or a changed branch. It is not due for the same branch on a watch tick, which keeps `gh` / `glab` out of the 3 s poll. `r` (`ReloadRepo` for the focused repo) and a full reload (`ReloadSnapshot`) forget the records, so the next applied status looks up again. A lookup for a branch the checkout has left is dropped on arrival. Detached checkouts and hidden ignored repos are not looked up. A background lookup never writes `status`. `gx` and Ctrl+click always run a fresh lookup in the open job, then update the cache, and set one status: `opened PR #<n>` (ok), `no PR for <branch>` (warn), `could not look up PR for <branch>` (error), or `could not open PR` (error). Worker rules: [tui-rust.md](./tui-rust.md) → **Pull request jobs**. Forge calls: [git-operations.md](./git-operations.md) → **Pull request lookup**.

## Icon popovers

Model and content: `tui/popover.rs`. State, keys, and clicks: `tui/state/popover.rs`. Paint: `render::draw_popover`.

- **Hit registry.** `LayoutHit.icon_hits` holds one `IconHit { y, x, width, kind: IconKind, target: IconTarget }` per painted icon. Each frame clears it. Tree paint records every segment with a catalog tag (`TextSeg.icon`, set by `tree.rs`: on workspace, repo, checkout, and group rows every glyph and indicator, `ChangeCount` and `WorktreeCount` included; the PR badge in `with_pr_badge`, after the merge mark); graph paint records the `GraphWidget::render_with_icon_spans` icons (node cells, the comment mark, the uncommitted and worktree glyphs, spacer worktree marks, ref chips on spacers and in the selection footer, the sync header, the footer more-lines hint) and the worktree PR badge. `IconTarget::TreeRow(row id)`, `IconTarget::CommitFileRow(row id)`, `IconTarget::GraphRow(graph_row_id)` (nodes, uncommitted glyph, comment mark), `IconTarget::GraphWorktree(path)` (worktree glyph on a row or a spacer mark), `IconTarget::GraphChip { row, chip }` (a ref chip, mark run, `[HEAD]`, or `[+N]` painted for row `graph_row_id`; `chip` is the graph crate's `PartTarget`), `IconTarget::GraphSync` (the sync header), `IconTarget::GraphMoreLines(graph_row_id)` (the footer hint), or `IconTarget::PullRequest(checkout)`. One hit can open more than one section: `popover::icon_targets` turns a checkout mark run that also holds the sync mark into a checkout section and a sync section. A span is the glyph columns only, clipped to what is on screen.
- **`PopoverState`** (`AppState.popover`): `origin` (`Peek` / `Pinned`), `targets` (one `(IconKind, IconTarget)` per section, in paint order), `anchor` (icon cells; `None` from `gh` hangs it from the first painted icon of its targets, else the focused row), `focus_line` (index into the flat lines of all sections), and `owner` (`PopoverOwner`: active tab, `list_focus_target`, focused tree row id, focused commit-file row id, or the focused graph row's `graph_row_id`: `uncommitted`, `commit:<id>`, `stash:<id>`, or `worktree:<path>`). The commit-file row id makes a cursor move in a commit-file or compare file list close the popover. The graph row id makes a cursor move, or a reload that leaves another row under the cursor, close it; a reload that keeps the cursor on the same row keeps it.
- **Content** is rebuilt every frame (`popover::popover_sections`), so it follows watch ticks and a section whose icon went away drops. A builder is a pure function of `AppState` and one target. A tree or commit-file target's section exists while its row still paints that kind (a sync mark stands for every sync kind, a merge mark for both, a status letter for every letter, and a comment mark for open and resolved, so a tick that flips the mark keeps the section). `IconTarget::CommitFileRow(id)` names a row of the shown commit-file or compare file list; its sections use the same file-level builders as a workspace file row. A graph chip section exists while its row is visible and its commit still holds the refs the chip names (the uncommitted row's footer chips are HEAD's); a ref chip's kind follows the refs. A `[+N]` target holds the hidden chips from its last paint (`PartTarget::Overflow`); its section lists only the ones still present (`[HEAD]` only while HEAD is detached) and goes when none is. One `popover_sections` call builds the commit-file rows and the graph's `visible_rows` at most once, however many sections read them. The sync header section follows `GraphModel::sync`; the more-lines section follows `AppState::graph_footer_lines_below` and the focused row. Comment sections read `comments::tree_row_comments` / `commit_file_row_comments` (the same match as the mark). Fields read the row chrome, the snapshot row (`changes`, `local_branches`, `default_tip_ref`), and the tree node (family checkouts, No updates children). `PopoverSection { icon, role, target, lines }`; `PopoverLine::Text` (the catalog meaning, not focusable), `Field { label, value, role }` (`role` is the `SegRole` the value paints in, `File` when the pane gives it no colour), `Action(&PaletteCommand)` (from `command_palette::command_for`, which takes the plain row over a highlighted-lines row such as `Stage highlighted lines`).
- **Peek.** `set_pointer` arms a dwell for a new hovered icon (`PEEK_DWELL_MS` = 400) and a leave grace when the pointer is off both the peek and its icon (`PEEK_GRACE_MS` = 250). The event loop sleeps on `peek_remaining_ms` and calls `expire_peek`. A peek does not change `input_mode`. `sync_popover_with_layout` (paint) drops a peek whose icon no longer paints at the same cells or while an overlay is open; `m` drops it.
- **Pin.** A click on an icon hit runs the plain click (`click_at`, which selects the row), clears `last_click` (so it never counts toward a double-click), then pins. A click inside a peek selects the peek's row and pins it. `Action::PopoverOpenFocused` (`gh`, or the `:` palette row Icon popover) pins one section per icon of the focused row, read from the row's painted segments (`tree::painted_row_segments`, or `AppState::commit_file_row_paint_segments` on a commit-file or compare list row, so a clipped icon still lists) or, on a graph row, its node, comment mark, label glyph, PR badge, spacer worktree marks, and spacer ref chips (`LabelPart::icon` over the row's painted lines); no icon sets `no icons on this row`. Ctrl+click on a PR badge pins nothing.
- **`InputMode::Popover`** while a pinned popover's owner matches the focus (`popover_pinned`). `input_mode` ranks it after help and before the search prompt. `overlay_blocks_background_ticks` lets watch and fetch ticks run under it. Keys: `j` / `J` / Down → `PopoverMove(1)`, `k` / `K` / Up → `PopoverMove(-1)` (field and action lines only, stops at the ends), Enter → `PopoverRun`, `y` → `PopoverCopyLine` (`Effect::CopyClipboard`: a field's value, an action's title), Esc and right-click → `PopoverClose`. Any other key maps to `Action::None`. Mouse events keep their actions.
- **Run.** `PopoverRun` checks `palette_disabled_reason` for the line's palette row: a reason goes on the status line and the popover stays. Otherwise the popover closes, then `dispatch_palette_action` runs the line's own `Action` through every gate, the same path as a Quick Open row (Fold subtree runs `FoldToggle` then `FoldToggleSubtree`, like `zz`; Fold row arms no `zz`). No new `Effect`. While a write runs, `classify_busy_dispatch` classifies Enter as that action (`AppState::popover_run_action`), and a left release on an action line (not a drag) as that line's action (`AppState::popover_release_action`), so a click cannot start a write that the key would not.
- **Mouse while pinned.** A press inside the box arms a `TextSelection` on its text area and focuses the line under it; the release runs an action line unless the press became a drag (the drag copies instead). A press outside closes it and does nothing else.
- **Close.** `PopoverClose`, a click outside, an owner mismatch (another row, pane, or tab; the row went away), or a dialog that opens (`chrome::open_dialog`, for example a picker that loads after the key or a confirm from an effect). Paint drops a stale popover.

## Editor

- **Detached GUI** (`cursor`, `code`, `code-insiders`, `codium`, `gvim`, including `--wait`): spawn detached while the TUI stays mounted. Fold, focus, scroll, search, and `show_ignored` stay in `AppState`. File-status updates come from the live watch poll.
- **TTY editor** (default `vim`): leave the alternate screen, spawn with inherited stdio in the file's repo cwd, restore raw mode, re-enter the alternate screen. Resume drains leftover bytes so the next keypress does not need an extra Enter.

`E` (`Action::ExternalDiff`) uses the same detached-name list. vimdiff takes the TTY like vim. Blob/temp prepare is `spawn_blocking`. Each `E` uses its own `$TMPDIR/workspace-status-ext-diff/<pid>-<nanos>/` directory. Detached tools wait for the child on a side thread and delete only that session. Cursor / VS Code samples use `--wait` so that child stays until the diff tab closes.

Any further edit or highlight move cancels that wait. The rest of this paragraph is commands mode (`tui/command_palette.rs`, `CommandPaletteState`; `AppState::command_palette()` is `Some` only in commands mode). Other overlays never open Quick Open. Text overlays (search, help search, comment, create-branch, branch picker, compare picker, graph-focus picker, stash menu, blame menu) still treat `:` as typed text, and so does Quick Open itself once open. Comment still maps Ctrl-k to the textarea. Help, confirm, and comment-export swallow `:`, Ctrl-p, and `F`. From visual-line highlight `:` opens the palette over the range (the vim `:'<,'>` model): the anchor stays, and Esc returns to highlight with the same range. Opening a file from files mode while a range is highlighted drops the range. The overlay is picker-shaped (rounded box, prompt + list; breadcrumb stays), not the 3-column help wall. Catalog rows map to existing `Action` values. The HIGHLIGHT group paints first: Stage / Unstage / Revert highlighted lines (`s` / `u` / `x`) and Exit highlight (Esc). Each row has a `CommandScope`: `Highlight` rows run only while a range is highlighted, `NoHighlight` rows only without one, and `Any` rows (Comment, Copy entity reference, Cycle theme, Toggle mouse) in both. Keymap help is `NoHighlight`: opening help clears the highlight; `?` in highlight mode opens help the same way. On open and on each filter change the cursor lands on the first enabled landing row, else the first landing row (`CommandPaletteState::landing_rows`): the landing rows are the in-scope rows the filter matches by title, key chips, or group; a row matched only by an alias lands only when no such row exists (`pull` lands on Pull behind, not on Open PR through its `pull request` alias; `exit` outside a highlight lands on Quit); ↑/↓, Ctrl-n / Ctrl-p, and Ctrl-j / Ctrl-k still move over disabled rows. Every printable key types into the query (`j` / `k`, `:`, `<`, and `>` too); only Esc closes Quick Open, the same rule as every picker. The filter matches title, key chip, group, and `PaletteCommand::aliases` (`exit` → Quit, `compare` → Diff … in new tab and the Blame: open … rows, `blame` / `gitlens` → the Blame: rows and Line blame on / off, `previous revision` → Blame: open previous line change, `reveal` / `details` → Blame: show commit in graph, `discard` / `restore` → Revert, `checkout` / `switch` → Branch picker, `reload` → Refresh, `yank` → Copy …). MOVE also lists Next / Previous match (`n` / `N`; off with `no search — press / first`), Fold subtree (`zz`: runs `FoldToggle` then `FoldToggleSubtree`, so the row and its descendants fold or open together; off on the graph or a diff with `z folds tree rows`), Other pane (Tab; runs `FocusLeft` while the right pane has focus), and Next / Previous tab (`gt` / `gT`; off with `only the Workspace tab is open`, which `gt` also says). VIEW has Narrow tree / Widen tree (`<` / `>`; aliases `resize`, `pane width`, `widen diff` / `narrow diff`) and ends with Quit (`q`). GIT has Open PR (`gx`, right after Refresh; aliases `pull request`, `merge request`, `browser`, `github`, `gitlab`; `NoHighlight`). It runs `Action::OpenPullRequest` after the palette closes. Rows with no key (Blame: …, Diff … in new tab) paint no chip. `palette_disabled_reason` takes the row and checks, in order: compare-tab refusal (`compare_refusal`, so highlighted Stage / Unstage on a compare tab show the compare copy, not the range patch refusal), the blame gate (`blame_refusal`), scope (`exit highlight first (Esc)` or `highlight diff lines first (V)`), the range patch refusal for highlighted stage / unstage / revert, then the action gate. The gate copy comes from `gates::dispatch_noop_reason` (the same text a key press puts on the status line) and names the way back and the action: `focus the tree (Tab) to stage`, `Esc back to the tree to pull`, `focus the left pane (Tab) to stash`, `focus the tree or graph (Esc) to stash`, `focus a graph commit`, `focus a graph stash row`. Enter closes Quick Open (`quick_open = None`) then `AppState::dispatch` of the highlighted enabled command, so range writes run with the anchor still set. Disabled rows stay visible, dimmed, with their reason at the row's right edge when it fits (the highlighted row also repeats it in the footer), when the current gate would no-op (including Push off a repo or checkout row, fetch / pull / default-branch on a group, graph-focus, full-file context, and visual highlight when those actions cannot run); Enter on one keeps the palette open and puts the reason on its status line; closing the palette clears that reason. Confirm-gated revert / merge / worktree-remove stay enabled when the row is valid so the boxed confirm can open after the palette closes. Quick Open Actions: `ToggleQuickOpen(QuickOpenEntry)`, `QuickOpenMove`, `QuickOpenChar`, `QuickOpenBackspace`, `QuickOpenSubmit`, `QuickOpenCancel`. While an exclusive write or default-branch switch is in flight, palette Enter classifies as that mapped Action (`classify_busy_dispatch` in `tui/event_pump.rs`). Palette Fetch / Pull / Push stay Handle and enqueue on the per-gitdir remote queue. Palette Stage / Unstage / Revert (whole-file and highlighted) and Edit stay Ignore. Help / search from the palette stay Handle. Palette nav / typing stay Handle. `input_mode` ranks Quick Open after confirm / stash / blame menu / comment / create / branch / graph-focus and before help / search / chords.

`Ctrl-f` opens the search-in-files dialog (`InputMode::SearchFiles { results }`, `AppState.search_files`, `tui/search_files.rs`; dispatch in `tui/state/dispatch_search_files.rs`) from Normal / `ZPending` / `GPending` / `DiffVisual`, so from a file or compare tab too; inside the dialog Ctrl-f closes it. Text prompts and pickers keep Ctrl-f as their own key, and other overlays drop it. Ctrl-Shift-F maps the same (it is the same byte without the kitty protocol); Alt, Super, Hyper, or Meta never match, and plain `f` stays fetch. The scope is `AppState::quick_open_scope()` at open, the same rule as Quick Open files mode, and the title is `Search · <checkout leaf>` or `Search · all repos`. Tab flips `SearchFilesState::widened` (all repos) for this dialog only: a Tab that changes the scope drops the hits and reloads the index, and with focus already on the workspace it does nothing. Esc and Ctrl-f close the dialog and park it in `search_files_parked`. Restore rule: on the next Ctrl-f, a parked dialog whose focused scope equals the new focused scope and whose results belong to it (`parked.scope() == focused`, so not left widened) comes back as it was (query, options, index, hits, highlighted row, `scroll`; the zone goes back to the query), and only work it had not finished runs again (an index still loading reloads; a search that was due or running starts again as a new generation). Otherwise the dialog opens fresh in the new focused scope with the parked query and options, loads a fresh index, and searches once it lands, so no hit from another scope shows. `widened` always starts false. Zones (`SearchZone`): the dialog opens in the query zone, where every printable key without a command modifier types and Backspace edits; ↑/↓, Ctrl-n / Ctrl-p, Ctrl-j / Ctrl-k (`list_overlay_move`) and PgUp / PgDn (the painted results height less one) move the highlight and switch to the results zone. There `j` / `k` also move and `e` edits; any other printable key or Backspace returns to the query zone and applies there. In both zones Enter opens, Tab toggles all repos, Alt-c / Alt-w / Alt-r toggle case / whole word / regex, and Esc closes. A query edit validates the query at once (`search_files::query_error`; an invalid regex shows `invalid regex: <error>`, keeps the previous list, and arms nothing), then arms the 150 ms debounce (`SearchFilesState::due`); an empty query drops the hits and stops the search. Option toggles, Tab, a restore with unfinished work, and the `#` hand-off search with no debounce. Enter (`SearchFilesSubmit`) parks the dialog and calls `AppState::open_file_tab_at_line(checkout, rel, line - 1, search)`: it opens or focuses the hit's file tab with its cursor on the hit line (a new tab keeps that cursor until `apply_file_tab` clamps it to the loaded body). A literal search arms the tab's in-file search on the text the shown hits came from (`search_active`, `search_query`, `SearchPane::File`, `search_hit` on the hit line), so `n` / `N` step it. That search keeps the file tab's own rule (trimmed, case-insensitive substring), so the case and whole-word options do not carry over. A regex search arms nothing and clears a search the tab already had. `e` (`SearchFilesEdit`, results zone only) parks the dialog and returns `Effect::EditFile { line: Some(line) }`, the path `e` takes on a file tab. Enter or `e` with no hit keeps the dialog open and warns `no matches` (`search_files::NO_SEARCH_MATCHES`), unless a search is still due or running, or will run once the loading index lands (a non-empty query that compiles); a query, option, or scope change, or a search chunk with hits, clears that warning. Search-in-files Actions: `ToggleSearchFiles`, `SearchFilesChar`, `SearchFilesBackspace`, `SearchFilesMove`, `SearchFilesPage`, `SearchFilesToggleScope`, `SearchFilesToggleOption(SearchFilesOption)`, `SearchFilesCancel`, `SearchFilesSubmit`, `SearchFilesEdit`. The dialog only reads files, so all of them stay Handle while an exclusive write runs (`classify_busy_dispatch`), Enter included; `SearchFilesEdit` classifies like `Action::Edit`. Enter and `e` in the results zone do not repeat when held. Mouse events inside the dialog do nothing, as in Quick Open, and `overlay_blocks_background_ticks` holds watch and fetch ticks while it is open. `input_mode` ranks it right after Quick Open. Index, chunked search, cancel, debounce, and preview data flow: [architecture.md](./architecture.md).

Quit is a double **Ctrl-c** chord (`tui/ctrl_c_exit.rs`). First press paints `Press Ctrl-c again to exit` for `CTRL_C_EXIT_MS` (2s); second within that window exits. Overlay pickers (stash / branch / create-branch / Quick Open / search in files) show the copy inline; otherwise it is a pinned chrome row, never a breadcrumb toast. The chord is handled before overlay modes, so it does not close a picker. `q` also quits immediately (Rust extra), except while an exclusive write or default-branch switch runs: then `q` arms the same window with `git write running · press q again to exit`, and a second `q` or Ctrl-c quits. Quit drops remotes that have not started. In-flight git is unchanged. Esc never quits.
