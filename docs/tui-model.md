# TUI model

Pure data under `crates/workspace-status/src/tui/` (tree, fold, flatten, keymap, live refresh). The event loop is `Action` → `AppState::dispatch` → `Effect`. `tui/effect.rs` turns that `Effect` into Scheduler jobs and applies results. Autoload, commit-files, commit-diff, stash / branch / graph-focus picker, and compare-picker jobs carry a generation plus an immutable target. Compare picker uses `request_prepare_compare`, separate from `b` / `o` branch gens. Compare-file diffs keep a latest request id per tab (`CompareTab.diff_req`). Autoload captures `GraphIdentity` (repo + head) at enqueue; the others capture at spawn (`(repo, source)`, `(repo, source, path)`, or focused checkout / picker request). Apply drops a result when that gen is stale or the live drill / identity / focused checkout no longer matches, the same way a right-pane load drops a stale `req_id` or target. A right-pane Graph replace bumps the autoload generation and clears `graph_loading_older`, so a late older page cannot merge into the new window when repo+HEAD are unchanged (graph `o` / `O`). Esc Diff→Files bumps the commit-diff generation so a late result cannot reopen Diff. The live TTY loop (`tui/event_loop.rs`) spawns those jobs on a `JoinSet`.

## Node kinds

`NodeKind` in `tui/tree.rs` is a seven-member enum. Five of them are structural; `Group` and `Section` are chrome.

| Kind        | Id                           | Children                    | Notes                                                                                                                                                                                                                                                          |
| ----------- | ---------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Workspace` | `workspace` (literal)        | repos + at most one group   | Single root. Carries `change_count` and `sync_summary`. Root label is rendered as provided (natural case), not uppercased.                                                                                                                                     |
| `Repo`      | `repo:<repoPath>`            | dirs/files **or** checkouts | Flat when the primary has no linked worktrees (branch on the same row). With linked worktrees → **family container**: path + trailing `ICON_REPO` / `N wt` / change count; branch omitted; `merged_into_default: None`; sync is worst-of-family.                |
| `Checkout`  | `checkout:<repoPath>`        | dirs/files                  | Nested under a family container only. Primary uses `ICON_BRANCH` + branch (never `ICON_LINKED_WORKTREE`) and the merged-into-default check when HEAD is a strict ancestor of the default tip. Open-vs-default stays linked-only. Linked extras use `ICON_LINKED_WORKTREE` + branch (or short path when detached) + merge mark. Trailing chrome is sync / counts / comment / viewed only. Checkmark only when HEAD is a strict ancestor of the default tip; HEAD equal to that tip is open. Files live here, not on the container. |
| `Group`     | `group:no-updates` (literal) | repos                       | Holds every repo with **no** updates (clean worktree, default branch, up-to-date with upstream, no attention sync note). Only ever one, only present when at least one such repo exists.                                                                       |
| `Section`   | `section:<repoPath>:staged` / `section:<repoPath>:changes` | dirs/files for that side | Present when the checkout has any staged path (empty side omitted). `repo` is the checkout path; `file` is `None`. Paint is 1-col glyph + `Staged` / `Changes`. Not `Group` (`in_no_updates` stays false). Foldable. |
| `Dir`       | `dir:<repoPath>:<fullPath>`  | dirs/files                  | Tree mode only. Single-child chains are collapsed (`apps/web/packages/ui` as one node). Every Changes-section dir uses `dir:<repoPath>:<fullPath>#unstaged`. Staged dirs stay unsuffixed. `dir_path_from_id` strips `#unstaged` before the filesystem path. |
| `File`      | `file:<repoPath>:<path>`     | —                           | Leaf. Carries the originating `FileChange` (one git side when sections are on). MS dual rows keep this id under Staged and use `file:<repoPath>:<path>#unstaged` under Changes. Space-reviewed uses the snapshot `FileChange` (both git sides) so the mark survives reconcile; both dual ids light. |

`Group` exists so clean repos collapse into one line by default instead of padding the tree. `Section` splits a checkout's dirty files into Magit-style **Staged** then **Changes** trees when **any** path is staged. No staged paths → today's file/dir ids directly under the repo or checkout. Each section is a normal path tree (`t` still toggles tree vs flat inside it). Split `FileChange` clones keep only that side, so trailing badges are `S` / `A` / `M`, not `MS` on a split row. Anything that switches on `kind` — `node_segments`, fold walks, `has_children`, `repo_path_of` — must handle `Checkout` and `Section`. `repo_path_of` / graph drill: checkout → its path; family container → primary checkout path; file/dir/section → `repo`. Returns `None` for `Group` and `Workspace`, which is what makes `r` on either of them refresh the whole workspace. Section `r` reloads that checkout.

## Ids

Ids are stable path-derived strings, never indices. Three things depend on that:

- After a refresh the cursor is restored by id, so a new file appearing above the cursor does not shift the selection. When the focused id is hidden under a folded ancestor (typical: repo moved into folded `group:no-updates` after pull), ancestors are unfolded so the same entry stays selected. If the id is gone even after unfold (file committed/stashed, ghost expired), ancestor walk uses parent `dir:` prefixes then `repo:` / `checkout:` parsed from the id string.
- The fold set is a set of ids that survives tree rebuilds.
- `watch.rs` attributes file flashes with file node ids and op-row flashes with repo node ids. Chrome flashes walk the tree and skip file nodes — files stay on status+mtime signatures. Chrome identity includes path / branch / sync enum / **sync note** / **HEAD** / change count / fold, so a new local commit on a clean branch or ahead 2→3 is a real update (status, graph, and right pane reload without `r`). Graph and commit-file rows use separate identity maps (`{repo}#{kind}:{id}` and `{repo}#{source}#{row_id}`) so a repo switch is a new list, not a mass flash. Add/update/remove flash the same row only. Classification is `Add` (id in after only), `Update` (signature changed), or `Remove` (id in before only). Fetch / pull / push / default-branch chrome stamps `Update`. Removals keep a ghost row for the 800ms fade. Each kind uses its own four-step background ramp (`flash` / `flash_update` / `flash_remove`). Flash background wins over cursor and search. The cursor bar stays. Status letter colours stay. The live poll is due from the start of `WS_STATUS_WATCH_MS`, not after collect finishes.

## `build_tree` → flatten → `VisibleRow`

`build_tree` groups snapshots by `primary_repo` when set, otherwise `repo`. A sole primary → flat `Repo` (today). Primary + linked → family container with `Checkout` children (primary first, then linked by path). Family attention if **any** checkout needs attention; containers with linked children start **expanded**. Within each attention bucket, families sort by primary path.

The tree paints `visible_for_tree` (`visible_workspace_snapshot`). Hidden ignored stay out unless `.` / `-a` shows them, or a named filter names that checkout or names the primary (linked children included). Hidden ignored includes a linked worktree whose primary is in `ignoredRepos`, even when that linked row is `ignored=false`. They return with `.` / `-a` as a nested family, not a workspace-root orphan. A linked row whose primary is absent from the snapshot still paints (linked-only). A standalone ignored linked path stays hidden until shown.

A checkout needs attention when it has file changes, is not on its effective default branch (`main` / `master` / `develop`, or a sole `defaultBranches` override when configured), has a non-idle sync (`behind` / `ahead` / `diverged`), **or** has an attention sync note (`no commits yet` / `status failed`). Only default-branch checkouts that are clean, up-to-date with upstream, and free of those notes land under `group:no-updates`. Workspace `sync_summary` counts those attention notes (`N attention`) so an attention-only workspace is not reported as `all current`. Empty discovery yields `no repos` (not `all current`).

Per checkout (or flat repo), children are either flat file nodes or a directory trie (tree mode). When that checkout has any staged path, those children sit under `Section` nodes (`Staged` then `Changes`; hide empty) instead of directly under the repo or checkout.

Flatten walks depth-first, emitting a `VisibleRow` per node: `id`, `depth`, `node`, styled segments / trailing, and a plain `label` (used for pane `/` search). Children are omitted when the node's id is in `folds`.

## Fold state

Default folds: ignored repos with children + the `no-updates` group. Non-ignored repos with changes start expanded. `z` toggles immediately and arms a 400ms `zz` window. Second `z` applies that same fold to foldable descendants.

## ViewStack / Enter / Esc

`DrillView` in `tui/drill.rs` is the depth stack (`Graph` = 0, `Files` = 1, `Diff` = 2). `FocusPane` is left or right. Together they are the ViewStack.

| Depth | Left | Right |
| --- | --- | --- |
| 0, repo/dir focused | Workspace tree | Graph |
| 0, file focused | Workspace tree | Worktree `DiffPane` |
| 1 `Files` | Graph list | Commit-file tree |
| 2 `Diff` | Commit-file list + commit-details footer | Commit-scoped `DiffPane` |

`list_focus_target` (`tui/state/`) is the focused list: depth 0 left → tree; depth 0 right / depth 1 left → graph; depth 1 right / depth 2 left → commit files; depth 2 right (and depth 0 file diffs) → none (file-diff focused row). Compare left is commit files. Compare right is none (file-diff). `j`/`k`, `gg` / `G` / Home / End, fold, search, click, and vertical wheel follow that target, not a parked Workspace `drill`. The selected row on an unfocused list still paints a weaker marker (`▏` / `cursorBgInactive`); only keys follow `list_focus_target`. The viewport keeps the focused row near the vertical middle (same rule as the workspace tree). On a focused file diff, `gg` / `G` (and Home / End) move to the first / last row. On a focused commit-file list, `gg` / Home use the first file row (`commit_file_cursor_index` with no path), not flattened row 0 when that row is a directory. `G` / End stay on the last visible row. CSI-u key release does not move and does not clear the `gg` pending (`GPending`). Mouse horizontal wheel (and Shift-wheel) pans the pane under the pointer without moving the focused row. The workspace tree matches the right pane. Trackpad hscroll is SGR `66`/`67`. When a file diff has long lines, that report over the left pane pans the diff. Short tree paths still pan the tree when the painted diff fits. Click still selects. Unshifted `h` / `l` still fold the tree and a focused commit-file folder row (`AppState::hl_folds`).

| Focus / depth | Enter | Esc |
| --- | --- | --- |
| Left (any depth) | Focus right (same stack) | Pop one depth; stay on left (no-op at depth 0) |
| Right, depth 0 | Push commit files when a graph row can drill; stay on right | Unfocus → left |
| Right, depth 1 | Push commit diff; stay on right | Unfocus → left |
| Right, depth 2 (leaf) | No-op | Unfocus → left |

Enter that deepens the stack keeps **right** focus. Esc cancels visual-line highlight (`V`) first, then an armed search. Esc that pops a depth keeps **left** focus and sets no status. Esc never quits. Right-click is the same step back (`BackClick`).

The status row's Enter / Esc chips follow this table (`chrome::nav_chrome_hint_segments`). `Enter drill` shows only when `AppState::nav_enter_drills` holds: right focus, no compare tab, and a graph commit / stash / uncommitted row at depth 0 or a commit-file (not directory) row at depth 1. Esc reads `clear` while a search is armed, `← <left pane>` from the right pane, `↑ files` / `↑ graph` when it pops depth 2 / 1, and is absent where it does nothing.

`/` saves the bound pane's cursor, scroll, and folds (`SearchOrigin`). Esc while typing (`SearchCancel`) restores them; Enter keeps them until the jump has run, then drops them. The search steps with a direction `dir`. `dir == 0` (each typing keystroke, and Enter) anchors on the `SearchOrigin` cursor and takes the first match after it, so typing recomputes from the origin and never walks on; no hit leaves the cursor at the origin. `n` / `N` anchor on the pane's active cursor row: first match strictly after (`n`) or strictly before (`N`), skipping a cursor row that is itself a match. "After" follows the pane's search order: tree flatten order including folded rows, graph visible rows, commit-file painted order including folded folders, painted diff rows (compare-tab diffs too). Past the last or first match the step wraps and sets info `search wrapped to top` (forward) or `search wrapped to bottom` (backward); landing back on the only match counts as a wrap, and no matches at all say `no match` with no wrap notice. Both notices also show on the typing line before Enter. `AppState::search_match_position` gives the `3/7` count for the armed-search pill for the landed match.

## Compare tabs

Compare is a session tab, not a `DrillView` depth and not a `NodeKind`. `tui/tabs.rs` keeps a permanent Workspace tab plus compare and file tabs (`SessionTab`, see **File tabs**) in one creation order with one id counter. Identity is `(checkout_path, base_ref, head_ref)`. `head_ref` is `HEAD` (`COMPARE_HEAD_REF`) on a live tab (Diff vs default / branch / commit), which diffs against the checkout's HEAD at each load. A full commit id pins the head (Diff commit vs parent). The same base with another head is a second tab; the same triple focuses the existing tab. The strip label is `<checkout-leaf> ↔ <base-ref>` (bidirectional arrow; left is the checkout leaf, right is the base ref). `tabs::short_rev` shortens a leading 40- or 64-hex object id to 7 chars and keeps any suffix (`abc1234^`); branch names and `HEAD` pass through. The strip label, the range header and `short_label` (`main...HEAD`, or `abc1234^...abc1234` on a pinned tab), and the empty / error copy (`No committed changes vs …`, `Base ref not found: …`, `No merge base between … and …`) use it. Workspace cannot close. Click `[✗]` on a compare tab to close that tab. Workspace never paints a close control. Close activates the tab to the left. Tabs are session-only.

A compare tab is depth 0. Left is the committed `base...head` file list. Right is `DiffPane`. There is no graph and no nesting. Opening Diff vs * from a Files or Diff drill keeps that `drill` parked for Workspace restore. Workspace park also stores that session's commit-file folds and trie mode. Each compare tab stores its own folds and trie mode. The compare tab still paints DiffPane on the right. It does not persist `drill` on the tab and does not paint the parked Files view. New tab: left focus, first file selected, that diff loads. Enter left → right. Enter right is a no-op. Tab switches panes. After overlay cancel, Esc on compare right focuses left. Esc on compare left does nothing (the tab stays; close it with the `[✗]` click or `Ctrl-k` Close tab). Esc on Workspace while a compare-picker job is in flight (picker not open yet) abandons that job so a late result cannot open the overlay.

`CommitFileSource::Compare { base_ref, head_ref, base_tip, merge_base, head }` is the immutable load key. `base_ref` and `head_ref` are the tab key; `head` is `head_ref` resolved. `Effect::LoadCompareRange` and `Effect::ProbeCompareTab` carry `head_ref`, and `compute_compare_range` / `probe_compare_range` resolve it instead of a literal `HEAD`. An unborn live HEAD is `HEAD has no commit`; a pinned head that does not resolve is `Head ref not found: <short sha>`. File list and diff reuse the commit-file / `DiffPane` paint path (`E`, `Ctrl-o`, `/`, selection, external diff). The diff section label is `COMMITTED`. `e` / `E` / `Ctrl-o` on a compare tab use that tab's committed file only. They do not fall through to a parked Workspace dirty file. Empty list or a dir row: `focus a file to edit` / `focus a file to diff`. Space marks that committed file reviewed with the workspace-tree eye. The mark lives in session-only `CompareTab.reviewed` (path → merge base + HEAD). It never writes `viewed-files.json` and does not change Workspace marks. A new HEAD or merge base hides it. A moved base tip alone keeps it. Empty list or a dir row: `focus a file to mark reviewed`.

Palette commands (no key chip is painted; `Ctrl-k`, or `>` in `:`, only): Diff vs default in new tab, Diff vs branch in new tab…, Diff vs commit in new tab…, Diff commit vs parent in new tab, Close tab. The filters `vs default`, `vs branch`, `vs commit`, `vs parent`, `new tab`, and the alias `compare` find the open rows. Concrete checkout for Diff vs default / branch / commit: flat repo / checkout / section / dir / file, or the checkout that owns the active graph / drill, or the active compare tab. Not Workspace, No-updates, or a family container. Unborn HEAD disables all three. Missing default disables Diff vs default. Diff commit vs parent needs the graph pane to focus a commit row (`AppState::graph_commit_focused`); uncommitted, stash, and worktree rows, the tree, and a compare tab refuse with `focus a commit to diff`. A root commit refuses with `root commit has no parent`. It opens `<sha>^...<sha>` with the head pinned to `<sha>` on the repo that owns the loaded graph (the repo graph `b` / `m` act on), labelled `<checkout-leaf> ↔ abc1234^`. `^` is the first parent, so a merge shows its changes against its first parent. It never checks anything out and does not change Enter or the commit drill. One gate, `AppState::compare_refusal` (`tui/state/dispatch.rs`), refuses on dispatch and in the palette with the same copy. It checks the open commands above on every tab first, then refuses compare-tab actions. Stage and Unstage (whole file or highlighted lines) show `cannot stage a compare diff` / `cannot unstage a compare diff`. Fetch / pull / push, default branch, branch actions (including `BranchSubmit`, which also runs the picker create row), create-branch, the stash menu, graph writes and graph focus, and worktree remove show `Switch to Workspace tab`. `x` (whole file, or highlighted lines) reverts to the compare **merge base** in the worktree, and runs only while `AppState::compare_revert_target` holds: the tab and the open diff are loaded for the current range and path (`CompareTab::loaded_diff_path`, keyed by `CompareTab.content_for`, because `tab.path` moves when a diff load is queued), the snapshot HEAD of the checkout equals the compare head, and neither the file nor a rename's old path has a change against HEAD. A tab with a pinned head refuses first with `cannot revert a committed diff`. Otherwise `x` and both palette Revert rows show that reason (`compare diff still loading`, `compare is stale: HEAD moved`, `<path> has uncommitted changes`, `focus a file to revert`). Whole-file `x`, its hint chip, and the palette Revert row also refuse a status other than `M` / `A` / `D` / `R` (`cannot revert a <status> change`, `AppState::compare_file_revert_refusal`). Compare `x` also runs from the focused diff with no highlight (the open file), which Workspace `x` does not. It opens `PendingConfirm::CompareRevertRange` or `CompareRevertFile` (`y` confirms, Enter names the key that does, `n` / Esc cancels, `Y` keeps it open). Confirm `y` / `Y` on a compare tab accept only those compare-owned variants; any other pending confirm shows `Switch to Workspace tab`. A compare confirm that somehow reaches another tab is cancelled, not run. `y` emits `Effect::CompareRevertPatch` or `Effect::CompareRevertFile`; the write worker checks HEAD and cleanliness again with git before it writes (see [git-operations.md](./git-operations.md)). The compare diff does not change; the status points to the Workspace tab. The hint row on a compare tab reads the compare tab, not the parked Workspace tree row. Outside highlight it can show only `x` / `e` / `space` / `Ctrl-o` (`COMPARE_HINT_ACTIONS` in `tui/chrome.rs`), and `x revert to merge base` only while `AppState::compare_file_revert_refusal` is `None` (the compare gate, then a file status of `M` / `A` / `D` / `R`). The VISUAL row drops `s u` and shows `x revert to merge base` only while `AppState::highlight_revert_refusal` is `None`. `V` visual highlight, copy entity reference (`'`, with the range while highlighted), line comments (`;`, overlay Ctrl-r resolve), and comment export (`y`) are allowed and act on the compare tab's own file (see the comment paragraph below). Switching or closing a tab (keys, palette, or a mouse click on the strip) clears the visual highlight and any pending confirm, so neither follows onto another tab's diff. A late Workspace branch-picker or stash-menu prepare that finishes after a tab switch does not open.

`GPending` before `normal_key`: `g` → `MoveToStart`, `t` → `NextTab`, `T` → `PreviousTab`, `1`…`9` → `JumpToTab` (`1` is Workspace), Esc no-op. Bare `t` stays tree/flat. Bare `T` stays theme. `gg` stays start. Watch ticks, mouse move (`None`), and key Release do not clear `GPending`. A typeless CSI-u Press of the same `g` / `t` / `T` / `1`–`9` key inside a few milliseconds (`G_CHORD_PROTOCOL_ECHO_MS`) is the release of that tap and is dropped. VTE often reports that release as Press when event types are missing. A later typeless `g` (one CSI-u per tap), including a fast human `gg` under 80ms, completes `gg`. A completing `g` does not eat the next `g` of `gt` after that burst. A raw-byte second `g` also completes `gg`. When the `g` pending expires, the echo for that arming `g` is cleared. A real Release also clears the echo. That keeps `gt` / `gT` as tab actions on compare tabs. Tab actions are `BusyAction::Handle`. Bare `t` on a compare tab toggles that tab's commit-file trie and keeps the focused file row. It does not change the parked Workspace trie.

The compare picker is `InputMode::ComparePicker` (`AppState.compare_picker`, a `tabs::ComparePickerState`). Diff vs branch lists local + `origin/*`. It drops `origin/HEAD` and the current local branch. Empty copy is `No branches to compare` (no branches) or `no branch matches <filter>`. Diff vs commit lists HEAD's ancestors newest first, HEAD excluded, including merge-side ancestors, capped at the 10,000 newest (`git::COMPARE_PICKER_COMMIT_LIMIT`). Its title reads `Compare vs commit <checkout>`; rows paint `<short sha>  <subject>`. The filter is a case-insensitive substring of the full sha, short sha, or subject. Empty copy is `No commits to compare` (no ancestors, for example a root HEAD) or `no commit matches <filter>`. Enter opens or focuses a live tab with `base_ref` = the picked full sha and `head_ref` = `HEAD`, labelled `<checkout-leaf> ↔ abc1234`. Both kinds share the one overlay and its key rule (printable keys filter; ↑/↓, Ctrl-n / Ctrl-p, Ctrl-j / Ctrl-k move; Backspace edits; Enter submits). No create, checkout, or fetch. Esc sets `compare cancelled` (info). `Effect::PrepareComparePicker` carries the kind (`ComparePickerKind`); both kinds share `request_prepare_compare`, so a newer request drops an older result of either kind. Apply also requires `compare_picker_pending` to still match that checkout.

A background probe reloads a compare tab only when that tab already recorded both SHAs and the head or the base-tip SHA then changed. The probe resolves the tab's `head_ref`, so a pinned tab (head `<sha>`, base `<sha>^`) never reloads when HEAD moves. Missing SHAs (first load) and tabs still `loading` are not a change. Dirty-only ticks do not reload. **Refresh** forces. Apply is generation-safe and does not steal focus. A late compare-file diff whose request id is not that tab's latest is dropped. Queueing a file diff records that path on the tab so a return trip queues a new request. Workspace pane loads (`LoadRightPane`, graph autoload, commit-files apply) do not run while a compare tab is active. Write and merge completion do not recapture the right pane. Parked Workspace `drill` / graph stay until the Workspace tab is active again.

Left-pane `j`/`k`, click, vertical wheel, and search next/prev load the matching right pane through `Effect::LoadRightPane` (TTY: `spawn_blocking` + coalesced request id). Mouse horizontal wheel over the workspace tree pans without `LoadRightPane` (SGR `66`/`67`). Depth 1 graph rows load that commit / stash / worktree's files. Depth 2 file rows load that file's commit diff. A depth-2 or compare-tab directory row shows a folder summary in the right pane: every changed file under that folder (files under folded subfolders too), each with its status badge and `+added −deleted` line counts. Moving onto a file loads its diff. The file that was open before repaints with no reload. While a folder summary shows, keys that act on a file diff refuse with their existing copy (`e`, `E`, `Ctrl-o`, `V`, space, stage / unstage / revert, right-pane `;` / `'` / `y`). A background reload, or a right-pane `j` / `k` or `gg` / `G`, behind the summary resets the hidden diff to its first row. Esc/back and the depth stack stay unchanged. A focused-repo watch/status result that changes checkout or file identity enqueues `LoadRightPane` immediately — it does not wait for the rest of the workspace.

## File tabs

A file tab is the third tab kind (`SessionTab::File`, `tabs::FileTab`): a read-only viewer of one file of one checkout, opened from Quick Open files mode. Enter there opens the highlighted file in a new tab at the end of the strip, or focuses the tab that already shows it: identity is `(checkout, rel)` (`TabStrip::open_or_focus_file`). Compare and file tabs share the strip in creation order and one id counter, so a file tab between two compare tabs closes without moving them. The strip label is the file name; the pane title is `<checkout>/<rel>`, where `<checkout>` is the snapshot `repo` path (unique per checkout, so two checkouts that share a folder name stay apart). Close it with the `[✗]` click or `Ctrl-k` Close tab (`Action::CloseTab`, the same action that closes a compare tab); Esc does not close it. Closing activates the tab to the left, as for compare tabs. Opening a tab parks the active session first. A file tab keeps only its own search (`search_mode` / `search_active` / `search_query` / `search_hit`, bound pane `SearchPane::File`) plus its `cursor`, `scroll`, and `col_offset`; it never writes or takes the Workspace park, so closing it (or switching back with `gt` / `gT` / `g1`) restores Workspace focus, search, and diff viewport unchanged. The body loads on the blocking pool (`Effect::LoadFileTab` → `UserTag::QuickOpen` → `file_index::read_text_file`) and lands through `AppState::apply_file_tab`, which drops a result for a closed tab or an older load generation and clamps the cursor to the new line count. `r` reloads (new generation); `e` opens the file in the editor at the cursor line (`Effect::EditFile { line: Some(cursor + 1) }`, no line for a binary or too-large body) and a TTY editor that returns reloads the tab. Keys: `j` / `k`, PgUp / PgDn, Ctrl-u / Ctrl-d, `gg` / `G`, Home / End, and the vertical wheel move the line cursor; `h` / `l`, arrows, and the horizontal wheel pan (not while wrap is on); `\` toggles wrap (the shared `diff_wrap`, so a file tab opens wrapped by default); `/`, `n`, `N` search the lines (case-insensitive substring; like the other panes, a step lands on the first match after the cursor, `N` the last one before it, and wraps with `search wrapped to top` / `search wrapped to bottom`); `'` copies a file entity reference (`kind: file`); click focuses a line and a drag copies the selection. Esc clears an armed search and otherwise does nothing; Enter, Tab, `t`, `.`, `i`, `M`, `<` / `>` do nothing; `z` says `z folds tree rows`. Git writes, comments, highlight, diff-only keys (`E`, `Ctrl-o`, space) and the Diff … in new tab commands refuse with `Switch to Workspace tab` on a key press and in the palette (`AppState::file_tab_refusal`, checked before the compare gate). So do `y` / `Y` on a confirm that a late checkout or merge result opened over the file tab (`n` / Esc still close it). The palette also disables the Workspace view rows that do nothing on a file tab (Flat / tree, Show ignored, Inline / split, Narrow / Widen tree, Other pane, Collapse / expand commit message) with that copy. Wrap paint counts at most one screen of rows per line (`search::wrap_col_starts_capped`), so a 2 MiB single-line file stays O(viewport). A file tab's Quick Open scope is its checkout. Workspace pane loads, graph autoload, and write completion do not recapture the right pane while a file tab is active (`!tabs.is_workspace()`), as on a compare tab.

## App state

`AppState` in `tui/state/` holds restorable view state: cursor row id, folds, filter, diff mode (`viewDefaults` seed the launch values of `tree_mode`, `commit_tree_mode`, `diff_mode`, `diff_wrap`, `commit_msg_expand`, and `line_blame` once in `AppState::apply_view_defaults`, called from `run_tui` after `AppState::new`; `commit_tree_mode` is also kept as `TabStrip::commit_tree_default`, the mode each new compare tab opens in; toggles never write them back), `diff_wrap` (`\` soft word-wrap on file diffs; on by default, `viewDefaults.wrap` sets the launch state; the toggle changes this session only and nothing writes a pref file), `commit_msg_expand` (on by default, `viewDefaults.commitMessage` sets the launch state; session toggle only: the selected commit / stash message wraps in the graph footer and commit-files footer; `M` collapses; graph list rows stay one line), `line_blame` (`LineBlameState`: the `B` toggle, on by default, `viewDefaults.lineBlame` sets the launch state, session only; plus a cache of focused-line blame answers keyed by `BlameKey` (checkout, revision, path, line, content epoch), capped at 512 entries and cleared when the toggle goes off) and `commit_msg_scroll` (wheel over an overflowing graph footer; keyed by graph row identity, so another selection starts at the top), full-context ids, tree mode, mouse enabled, theme, nav (focus pane + drill depth), `diff_cursor`, `diff_col_offset`, `left_col_offset`, `right_col_offset`, session-only `tabs` (Workspace plus compare and file tabs, with per-tab compare reviewed marks and per-file-tab search, cursor, and scroll), session-only `quick_open` (`:` go to file / `Ctrl-k` commands overlay), session-only `diff_visual_anchor` (`V` visual-line highlight on a focused file diff), and the transient mouse `text_selection` (press in a pane body, drag, release copies; cleared by any press, a splitter drag, a modal open, `m`, and resize). The file-diff viewport (`diff_cursor` / `diff_scroll` / `diff_col_offset`) belongs to one view identity: a workspace `repo`+`path`, or a commit `repo`+source+`path`. A new identity resets those fields to the origin and clears highlight. A same-view reload keeps the viewport. Highlight also drops when the painted row list changes (watch reload, split/inline, resize). Graph window default is 300. Graph branch focus (`o` / `O`) is session-only (`graph_branch_focus`): a per-repo list of local names whose ancestors the graph shows, or `None` for `--all`. Fold, split ratios, pan offsets, theme cycle, graph focus, and Quick Open reset on the next launch. Tree mode, diff mode, diff wrap, and commit-message expand return to their `viewDefaults` (or in-app) values. Reviewed marks persist in `viewed-files.json`. Line and object comments persist in `comments.json` (`tui/comments/`, `WS_STATUS_COMMENT_STORE` overrides). Version 2 namespaces both files by workspace identity (SHA-256 hex of the canonical cwd). GC and save replace only the current workspace bucket. A version-1 file keeps its records under `__legacy__`. Load uses that map when the current workspace bucket is missing. GC of one cwd does not drop `__legacy__`. A missing store file starts empty. A present file that is not valid v1/v2 UTF-8 JSON is left unchanged and persist returns an error. A failed persist sets `comment save failed` or `viewed save failed` plus a short IO error on the breadcrumb trailing slot (never `comment saved` / `comment deleted`). Refresh GC uses snapshot `local_branches` and checkout paths (no git on apply or `;`). A primary detached HEAD is a worktree path key, not `HEAD (detached)` as a branch. Commit comments stay while that repo identity is still in the snapshot. Branch and working-tree line comments stay when `git status` fails (`status failed`, empty `local_branches`) only if every checkout of that identity has an empty counted list. A successful sibling's live names win. The GitHub Release startup prompt (`update_check.rs`) runs in the CLI **before** `AppState` exists; it is not session state. `status` is a `StatusMessage` (`tui/status.rs`): text plus a `StatusKind` (info / progress / ok / warn / error) that picks the color and the expiry (info / ok clear after `STATUS_TTL_MS`; the others stay until replaced). A plain `String` / `&str` assigned to it is info. A note that a reload or background job writes goes through `StatusMessage::offer_info`, which leaves a progress / warn / error in place. Set a refusal with `StatusMessage::warn(…)` and a git or IO failure with `StatusMessage::error(…)`.

Full-context membership means unlimited unified context (`FULL_DIFF_CONTEXT_LINES`) for that file id — toggled by `Ctrl-o`, cleared by `Esc` or a second `Ctrl-o`. After a full-file toggle, scroll recenters on the prior hunk/change anchor.

Current-line blame (`B`) asks git only for a focused line: the active file tab's cursor line, or the focused file-diff row while the right pane drives the diff (`ListFocusTarget::None`, no folder summary). Moves in the tree, graph, or file lists never blame. `AppState::line_blame_want` (`tui/state/line_blame.rs`) maps that line to a `BlameKey` per surface: a worktree diff context line blames the working tree, a deleted line in UNSTAGED the index (or `HEAD` when nothing is staged), a STAGED context or deleted line `HEAD`; an added line reads `You · uncommitted` / `You · staged` with no git call; NEW asks nothing. A commit drill blames the commit (new side) or `<sha>^` under the old path (deleted line); a stash `stash@{n}` / `stash@{n}^1`; a compare tab its head / merge base. The interpreter reads that key after every `schedule` and `apply` (`Interpreter::maybe_queue_line_blame`). A cache hit runs nothing. Otherwise the key goes into a latest-only slot and one `UserTag::LineBlame` job runs `git blame` on the blocking pool. While it runs, more cursor moves only replace the slot; the apply fills the cache for its key, marks a paint only when that key is still focused, and the hook then asks for the newest line. So at most one job is in flight and one waits. Toggling off clears the cache and drops late answers.

## Graph list

Graph rows come from `workspace-status-graph` `GraphModel::visible_rows`. Graph `o` (graph list or highlighted repo / worktree) can restrict the loaded window to ancestors of selected local branches (`git log <branches>` instead of `--all`); overlay Enter applies visible marks or the cursor row (hidden pre-marks do not leak through a filter). Unmarking every `[x]` then Enter, or `O`, restores `--all`. Stashes park immediately above `stash^1`. Pane `/` matches a graph row on subject, body, author, painted relative date or local `YYYY-MM-DD HH:MM`, UTC `YYYY-MM-DD HH:MM`, branch and tag names, and full or short sha (stash / worktree rows use those fields when present). Graph pane chrome: selection footer when height ≥ 3 (2 lines collapsed, up to 9 expanded; `graph_chrome_budget` / `selection_detail_lines` / `selection_detail_parts`; footer preferred, header drops first). By default (`commit_msg_expand`; `M` collapses) that footer wraps subject plus body (`selection_footer_parts`), and so does the commit-files footer. That footer sits at the bottom of the depth-2 left (commit-files) pane under the file list (title, meta, then message; clipped from the end), and the list keeps at least one row; a click on it does not pick a file (`LayoutHit::files_list_height`). The graph footer shows at most 8 message rows plus meta and at most half the pane; the wheel over it scrolls a taller message (`commit_msg_scroll`, `LayoutHit::graph_footer_*`) without moving the graph cursor. Graph list rows stay one line. Bodies come from git `%b`, capped at 8 KiB. Uncommitted: `Working tree clean` / `Uncommitted changes` + HEAD commit ref chips, or `worktree · not a commit` when HEAD has none. Spacer: `…` + `connector · not selectable`. Stash: subject + `stash@{n} ·` hash `·` date. Commit: subject + ref chips (or `(no refs)`) `·` hash `·` parents (`parent <id>`, `parents <id> <id>` in git order for a merge, or `root commit`) `·` author `·` date. Empty: `no selection`. Footer chips use the same `LabelKind` palette as the row (HEAD / default / feature / remote / tag), not a flat wash. Graph PageUp/PageDown move in painted list space (`visible − 1` painted lines, snap to selectable); `j`/`k`, click, and vertical wheel stay on selectable `visible_rows`. The viewport keeps the focused row near the vertical middle. The 1-column scrollbar thumb is painted whenever the list overflows, at the top too; the horizontal bar only after the viewport leaves the left edge. Both are mouse-draggable through the same `hit_split` / `SplitDrag` stack as the pane and in-diff splitters (`SplitDrag::GraphScrollbar` / `GraphHScrollbar`); a track click jumps toward that position without moving the graph cursor. File-diff horizontal thumbs use that stack too (`SplitDrag::DiffHScrollbar`) and do not move `diff_cursor`. Tree and commit-file lists pan with the wheel and keys only; they do not paint an h-bar. Horizontal mouse wheel (and Shift-wheel) pans the pane under the cursor without changing keyboard focus (SGR `66`/`67`).

Same-checkout graph reloads (`set_graph`, including a watch HEAD move) keep the focused row by `graph_row_id` (commit sha, stash ref, worktree path, or uncommitted). If that row is gone, the cursor clamps to `min(old_index, n-1)`. A different checkout, a first load, or graph `o` / `O` (new log window) reset cursor and scroll to the top. Branch pickers, the stash menu, Quick Open, and the graph-focus overlay open at row 0. Those lists are new overlays, not in-place watch reloads. Commit-file and compare lists restore by path; a gone path clamps to `min(old_index, n-1)`. File-diff viewports stay on the same identity. A new path or commit-file resets to the origin.

See [git-graph-topology.md](./git-graph-topology.md) and [graph.md](./graph.md).

## Actions and gates

`tui/action.rs` is the single source of truth for which actions exist. `tui/tty.rs` enables mouse (click + button-event + any-event DECSET 1003 + SGR) and decodes TTY SGR reports (`66`/`67` → `ScrollWheel { horizontal: true }`; motion-bit wheel `96`–`99` decodes as the plain wheel; buttonless motion → `PointerMove`). The live loop handles `PointerMove` before busy gating and dispatch: it stores `AppState::pointer` and redraws only when the hovered tab `[✗]` changes. `dispatch(PointerMove)` is a no-op that keeps `g` / `z` chords. `m` clears the pointer. `tui/keys.rs` maps crossterm events to `Action`. `<` / `>` are `Action::ResizeTree(-1 / 1)`: `split::step_tree_fraction` moves the session `tree_fraction` by 5% of the terminal width with the divider drag's clamp. A right-button press is `Action::BackClick` in Normal and `V` modes; a pending `z` / `g` chord maps it like Esc (overlays drop every mouse event); dispatch runs `DiffVisualCancel` in highlight, otherwise `NavEsc`, and nothing while mouse capture is off. Keyboard enhancement reports Shift-letter as the unshifted codepoint plus SHIFT; the keymap folds that to the uppercase binding (`O` / `S` / `E` / `/` capitals) so it matches a raw `'O'` byte. `E` is `Action::ExternalDiff`. `e` stays `Action::Edit`. `tui/state/dispatch.rs` routes `Action` to session updates and `Effect`. List keys live in `tui/state/dispatch_keymap.rs`. Pan / wheel live in `tui/state/pan.rs`. Enter / Esc live in `tui/state/dispatch_drill.rs`. Git writes live in `tui/state/dispatch_write.rs`. `mouse_pan` routes a long file-diff pan when the pointer is over the left pane and the painted diff can pan; otherwise the left list pans. Painted horizontal thumbs (graph and file-diff) drag through `hit_split` (`SplitDrag::GraphHScrollbar` / `DiffHScrollbar`). A track click jumps the pan offset. `tui/gates.rs` hides writes that the focused row / depth / pane must not run. `tui/ops.rs` resolves stage / unstage / revert file lists (`collect_write_files`) and bulk git targets (`op_targets` / `push_targets`).

`;` opens a boxed comment overlay on a numbered file-diff line (working-tree, commit, or compare) or on a commit / non-default branch / worktree row. The overlay is a multiline caret editor (`tui-textarea`): Shift-Enter inserts a newline; Enter saves; empty Enter deletes. Left / Right / Home / End move the caret (Home / End are the current line). Ctrl-a / Ctrl-e are line start / end. Ctrl-Left / Ctrl-Right move by word. Insert, Backspace, and Delete apply at the caret. Overlay Ctrl-r toggles resolved. Enter persists body and resolve state. A failed write sets `comment save failed` plus a short IO error on the breadcrumb trailing slot instead of `comment saved` / `comment deleted`. The idle status row is replaced. Hint chips do not paint inside the box. `V` on a focused file diff starts visual-line highlight; `j` / `k`, arrows, `gg` / `G` / Home / End, PgUp / PgDn, and Ctrl-u / Ctrl-d move the head (extend or shrink the range); `?`, `q`, `T`, `m` act as in normal mode; any other key sets warn `Esc exits highlight` (`Action::DiffVisualUnmapped`). Highlight has no `GPending` mode: the second `g` of `gg` dispatches `ArmGChord`, which moves to the top while the first `g` is still pending; `;` then attaches the comment to that line span; on a working-tree file diff `s` / `u` stage / unstage the highlighted add/del lines (or the hunk covering that range) and do not whole-file stage. `x` builds a reverse patch of the highlighted unstaged lines, clears the highlight, and opens `PendingConfirm::RevertRange`; `y` emits `Effect::RevertPatch` (worktree only), `n` / Esc sets `revert cancelled`. On a commit / stash / worktree drill diff, `s` / `u` / `x` refuse with a breadcrumb (no `git apply`). On a compare diff `s` / `u` refuse, and `x` builds the reverse patch from the COMMITTED section (`PartialPatchKind::RevertCommitted`) and opens `PendingConfirm::CompareRevertRange` (see Compare tabs). Without highlight, `;` opens the stored span that covers the focused line (smallest inclusive span, then lowest start line, then key order). A compare diff line (or highlighted span) is keyed `CommitLine { repo, sha: <compare head>, path, line, end_line }` (`CommitFileSource::line_commit`): the new-side numbers are the head blob's, the same key a commit drill of that head uses, so the store format does not change. Delete-only rows fall back to the merge-base line number, as on a commit diff. After HEAD moves and the tab reloads, those comments stay in the store but no longer paint on that compare diff. On a compare tab the comment target, diff line marks, commit-file row marks, and `y` scope come only from the tab's checkout, file, and range (`AppState::open_diff_target` / `commit_drill_source`), never from the parked Workspace diff, so a Workspace worktree comment does not paint on a compare diff line with the same number. A compare file-list row has no line target (`no comment target`), the same as a commit-file row. Empty Enter deletes that span. Esc leaves highlight without commenting. `Ctrl-k` (or `:` then `>`) opens Quick Open commands over the range (see Keymap). Watch reload, split versus inline, or a painted-row change drops highlight. The diff gutter reserves a comment-mark column on every numbered cell so the line numbers do not shift when a comment appears. Open comments paint `ICON_COMMENT` (`"` / nf-fa-comment). Resolved comments paint `ICON_COMMENT_RESOLVED` (`'` / nf-fa-comment-o). Workspace, group, section, dir, file, and default-branch rows are not object-comment targets. If a repo has exactly one non-default branch, a comment that would have attached at repo scope attaches to that branch. A primary detached HEAD is a worktree path key. Graph rows paint the comment glyph when the row has an object comment or a file-line comment (resolved glyph when every comment on the row is resolved). Commit-file rows paint the same trailing mark when that file has a line comment. `y` copies live comments as markdown after GC for the **focused** tree / graph / commit-file / diff row and descendants under that row (a file copies that path only; a folder copies files under it). Unrelated siblings stay out. The workspace row copies every live comment. A family row copies Worktree object comments for every checkout of those identities, plus comments keyed by the identity path. A linked-worktree row copies Worktree comments keyed by that family identity and by this checkout path. Branch and commit comments keep identity matching. Matching uses `repo_identity` and snapshot checkout paths, not a path prefix. Unrelated repos stay out. Family and linked-worktree comment marks use the same rule. Resolved comments stay in that copy and carry `[resolved]`. A line comment with a newline stays one markdown bullet. Continuation lines are quoted. Confirm-mode `y` is still revert-yes. `'` copies a pasteable entity reference for the focused tree / graph / commit-file / numbered-diff row. Status is `copied` when the copy succeeds. Status is `copy failed` when OSC 52 and the host tool both fail. No overlay. No comment store write. Search still types `'`. `;` is unchanged.

`stage` / `unstage` / `revert` resolve targets through `collect_write_files` (file / dir / section / checkout / flat repo). Visual-line `s` / `u` bypass that list and emit `Effect::ApplyCachedPatch`. Visual-line `x` bypasses it too and confirms `Effect::RevertPatch`. Section headers take every dirty file on that side of the checkout; dirs under a section stay on that side. Family containers, workspace, and group yield no files. Revert opens a counted confirm that offers only the keys `RevertScope` allows for the tracked / untracked mix: tracked only `y`; mixed `y` discards tracked only, `Y` also deletes untracked via per-file `remove_untracked_file`; one untracked file `y` deletes it; several untracked files `Y` deletes them. A key the box does not show keeps it open. `r` reloads one checkout unless the focused row is workspace or `group:no-updates`.

Write scope for bulk git (`f` / `p` / `P` / `d`): primaries on workspace/family rows; a linked worktree only when that row is focused; hidden ignored-list paths omitted even if focused. When ignored repos are shown (`.` / `-a`), they follow the same primary / focused-worktree rule. Background fetch uses `background_fetch_targets` and skips hidden ignored repos.

Independent checkouts run fetch / pull / push in parallel (`FETCH_CONCURRENCY` = 10) on the per-gitdir remote queue in `tui/effect.rs`. Occupy key is `primary_repo` when set, else the checkout path. A second `f` / `p` / `P` enqueues. Pending jobs coalesce on that checkout. `Fetch` / `Pull` / `Push` / `FetchTick` are `BusyAction::Handle`. Exclusive writes are Ignore only while exclusive write or default-branch is busy.

`InputMode::Confirm` maps `y` → `ConfirmYes`, `Y` → `ConfirmYesClean`, `n` / Esc → `ConfirmNo`, and Enter → `ConfirmEnter`, which writes nothing and names the accept key (`PendingConfirm::accept_key`). `d` whose targets hold more than one repo off default opens `PendingConfirm::SwitchToDefault`; its Yes emits the same `Effect::DefaultBranch`, and Confirm Yes keeps that overlay while any of those gitdirs is busy.

An exclusive write on an occupied gitdir still dispatches. Then `schedule` refuses with breadcrumb `busy`. Confirm Yes, stash create/apply/pop, and create-branch submit keep the overlay in that case. Branch-picker create from a new name keeps the picker. Status is `busy`. A free gitdir may write while other repos fetch. If `p` lands during an inflight fetch on that gitdir, Pull still queues when dispatch set `nothing behind to pull` or a diverged line. Diverged targets stay out of that Pull. Right-pane, compare, and drill `Effect::None` Pull do not follow.

Mixed kinds paint `Fetching 1 · Pulling 1…` or `Fetching 1/2 · queued 1`. After those ops finish, `status` is a count (`Fetched N repos`), with ` (N failed: <first repo> — <git reason>, +N more)` and ` (N skipped: dirty)` when they apply; a pull whose auto-stash conflicted leads with `<repo>: pulled, but restoring local changes conflicted — …`. Repos that worked are not listed.

Graph pane writes (`graphCheckout` / `graphCreateBranch` / `graphMerge` / stash apply / drop / pop) gate on graph-list focus (depth 0 right or depth 1 left). Graph `m` is `graphMerge` (always confirms). Graph `o` / `O` are view filters (focus branches / clear), not writes. They open from the graph list or a highlighted repo / worktree. Inside the `o` overlay `O` types; Ctrl-o clears. The tree `b` picker and the graph `b` picker share `BranchPickerState` (with `creates` set; the compare picker has none): a valid filter that is not an exact listed name adds a create row after the branches (`BranchPickerState::create_name` / `on_create_row`). `BranchSubmit` on it emits `Effect::CreateBranch` (tree: create and check out at HEAD) or `Effect::CreateBranchAt` (graph picker: at its commit, no checkout). The create-branch name prompt (`InputMode::CreateBranch`) is graph `c` only. Leftover branch/tag chips on a commit spacer: truncate the next name with `…` (keep brackets) when part of it fits; bold `[+N]` counts only chips fully hidden after that (omit `[+N]` when the last painted chip is merely truncated) so the row does not grow.

## Editor

- **Detached GUI** (`cursor`, `code`, `code-insiders`, `codium`, `gvim`, including `--wait`): spawn detached while the TUI stays mounted. Fold, focus, scroll, search, and `show_ignored` stay in `AppState`. File-status updates come from the live watch poll.
- **TTY editor** (default `vim`): leave the alternate screen, spawn with inherited stdio in the file's repo cwd, restore raw mode, re-enter the alternate screen. Resume drains leftover bytes so the next keypress does not need an extra Enter.

`E` (`Action::ExternalDiff`) uses the same detached-name list. vimdiff takes the TTY like vim. Blob/temp prepare is `spawn_blocking`. Each `E` uses its own `$TMPDIR/workspace-status-ext-diff/<pid>-<nanos>/` directory. Detached tools wait for the child on a side thread and delete only that session. Cursor / VS Code samples use `--wait` so that child stays until the diff tab closes.

## Keymap

`:` and `Ctrl-k` open Quick Open (`InputMode::QuickOpen`, `AppState.quick_open`, `tui/quick_open.rs`) from Normal / `ZPending` / `GPending` / `DiffVisual` only. `:` opens it in files mode with an empty query (`QuickOpenEntry::Files`); `Ctrl-k` opens it with `>` already typed (`QuickOpenEntry::Commands`). A query that starts with `>` is commands mode: the rest of the query, leading spaces trimmed, is the command filter (`quick_open::commands_filter`). Typing `>` first in files mode switches to commands; backspacing the `>` returns to files mode. Files mode lists the files of the scope picked on open (`AppState::quick_open_scope`): the active file tab's checkout; the active compare tab's checkout; else the focused row's checkout (`focused_checkout_path`: a family's repo row is its primary, a linked worktree row or anything under it is that worktree); else (workspace row, group) every primary checkout of the visible snapshot, each path prefixed with its snapshot `repo` path plus `/` (`clients/a/web/README.md` and `legacy/web/README.md`, never two `web/` prefixes). The index sorts by that display path and drops duplicates only within one checkout (an unmerged path lists once per index stage). The index (`Effect::LoadFileIndex`) and every score (`Effect::ScoreFiles`) run on the blocking pool (`UserTag::QuickOpen`, latest-only slots); the overlay keeps `index_gen` / `score_gen` and drops any older result (`apply_file_index` / `apply_file_score`). The index loads once per open: on open in files mode, or on the first edit that lands in files mode after `Ctrl-k`. Opening clears a leftover status (not the Ctrl-c quit prompt). In files mode the status row shows `status` only for text Quick Open set itself (`no file matches`) or the quit prompt (`quick_open::files_row_shows_status`), else `file_status_text`. Switching between files and commands clears the status the other mode set (the `no file matches` warning, or a commands disabled-row reason). Enter in files mode closes Quick Open and opens or focuses the highlighted file in a file tab (see **File tabs**); with no hit it warns `no file matches` and stays open. Enter that arrives while the index loads or the latest score is pending does not act on the old hits: it sets `QuickOpenState::submit_on_ready`, and the submit runs when that query's score is accepted (`apply_file_score` returns the follow-up `Effect::LoadFileTab`). Any further edit or highlight move cancels that wait. The rest of this paragraph is commands mode (`tui/command_palette.rs`, `CommandPaletteState`; `AppState::command_palette()` is `Some` only in commands mode). Other overlays never open Quick Open. Text overlays (search, help search, comment, create-branch, branch picker, compare picker, graph-focus picker, stash menu) still treat `:` as typed text. Comment still maps Ctrl-k to the textarea. Help, confirm, and comment-export swallow both keys. From visual-line highlight the palette opens over the range: the anchor stays, and Esc returns to highlight with the same range. The overlay is picker-shaped (rounded box, prompt + list; breadcrumb stays), not the 3-column help wall. Catalog rows map to existing `Action` values. The HIGHLIGHT group paints first: Stage / Unstage / Revert highlighted lines (`s` / `u` / `x`) and Exit highlight (Esc). Each row has a `CommandScope`: `Highlight` rows run only while a range is highlighted, `NoHighlight` rows only without one, and `Any` rows (Comment, Copy entity reference, Cycle theme, Toggle mouse) in both. Keymap help is `NoHighlight`: opening help clears the highlight; `?` in highlight mode opens help the same way. On open and on each filter change the cursor lands on the first enabled visible row (0 when none is enabled); ↑/↓, Ctrl-n / Ctrl-p, and Ctrl-j / Ctrl-k still move over disabled rows. Every printable key types into the query (`j` / `k`, `:`, `<`, and `>` too); only Esc closes Quick Open, the same rule as every picker. The filter matches title, key chip, group, and `PaletteCommand::aliases` (`exit` → Quit, `compare` → Diff … in new tab, `discard` / `restore` → Revert, `checkout` / `switch` → Branch picker, `reload` → Refresh, `yank` → Copy …). MOVE also lists Next / Previous match (`n` / `N`; off with `no search — press / first`), Fold subtree (`zz`: runs `FoldToggle` then `FoldToggleSubtree`, so the row and its descendants fold or open together; off on the graph or a diff with `z folds tree rows`), Other pane (Tab; runs `FocusLeft` while the right pane has focus), and Next / Previous tab (`gt` / `gT`; off with `only the Workspace tab is open`, which `gt` also says). VIEW has Narrow tree / Widen tree (`<` / `>`; aliases `resize`, `pane width`, `widen diff` / `narrow diff`) and ends with Quit (`q`). Rows with no key (Diff … in new tab, Close tab) paint no chip. `palette_disabled_reason` takes the row and checks, in order: compare-tab refusal (`compare_refusal`, so highlighted Stage / Unstage on a compare tab show the compare copy, not the range patch refusal), scope (`exit highlight first (Esc)` or `highlight diff lines first (V)`), the range patch refusal for highlighted stage / unstage / revert, then the action gate. The gate copy comes from `gates::dispatch_noop_reason` (the same text a key press puts on the status line) and names the way back and the action: `focus the tree (Tab) to stage`, `Esc back to the tree to pull`, `focus the left pane (Tab) to stash`, `focus the tree or graph (Esc) to stash`, `focus a graph commit`, `focus a graph stash row`. Enter closes Quick Open (`quick_open = None`) then `AppState::dispatch` of the highlighted enabled command, so range writes run with the anchor still set. Disabled rows stay visible, dimmed, with their reason at the row's right edge when it fits (the highlighted row also repeats it in the footer), when the current gate would no-op (including Push off a repo or checkout row, fetch / pull / default-branch on a group, graph-focus, full-file context, and visual highlight when those actions cannot run); Enter on one keeps the palette open and puts the reason on its status line; closing the palette clears that reason. Confirm-gated revert / merge / worktree-remove stay enabled when the row is valid so the boxed confirm can open after the palette closes. Quick Open Actions: `ToggleQuickOpen(QuickOpenEntry)`, `QuickOpenMove`, `QuickOpenChar`, `QuickOpenBackspace`, `QuickOpenSubmit`, `QuickOpenCancel`. While an exclusive write or default-branch switch is in flight, palette Enter classifies as that mapped Action (`classify_busy_dispatch` in `tui/event_pump.rs`). Palette Fetch / Pull / Push stay Handle and enqueue on the per-gitdir remote queue. Palette Stage / Unstage / Revert (whole-file and highlighted) and Edit stay Ignore. Help / search from the palette stay Handle. Palette nav / typing stay Handle. `input_mode` ranks Quick Open after confirm / stash / comment / create / branch / graph-focus and before help / search / chords.

Quit is a double **Ctrl-c** chord (`tui/ctrl_c_exit.rs`). First press paints `Press Ctrl-c again to exit` for `CTRL_C_EXIT_MS` (2s); second within that window exits. Overlay pickers (stash / branch / create-branch / Quick Open) show the copy inline; otherwise it is a pinned chrome row, never a breadcrumb toast. The chord is handled before overlay modes, so it does not close a picker. `q` also quits immediately (Rust extra), except while an exclusive write or default-branch switch runs: then `q` arms the same window with `git write running · press q again to exit`, and a second `q` or Ctrl-c quits. Quit drops remotes that have not started. In-flight git is unchanged. Esc never quits.
