# Ratatui TUI

`workspace-status` and `ws` from `crates/workspace-status` open a ratatui TUI when stdout is a TTY (or you pass `-i` / `--tui`) and you did not pass `--plain`, `--json`, `-v`, `-p`, or `-d`. Those headless flags still win over `--tui`.

A non-TTY run without those flags still prints `--plain`. Agents must pass `--plain` or `--json`.

Animated GIF clips of the daily views live in the [root README](../README.md#screenshots).
To rebuild those clips, run `./scripts/capture-demo-stills.sh` (see [demo.md](./demo.md)).

## Daily keys

One key spelling everywhere a key is shown (help, hint chips, palette, prompts, docs): modifier, hyphen, then the key as typed (`Ctrl-o`, `Ctrl-c`, `Shift-Enter`), and `Enter`, not `⏎`.

| Key | Action |
| --- | --- |
| `Ctrl-c` twice | Quit. First press paints `Press Ctrl-c again to exit`; second within ~2s exits. Overlay pickers show that copy inline |
| `q` | Quit immediately (Rust extra). While a git write or default-branch switch runs, the first `q` paints `git write running · press q again to exit`; a second `q` or Ctrl-c within ~2s exits |
| `?` | Help overlay (short list, not a wall of text) |
| `:` | Quick Open, files mode: fuzzy go to file in the focused scope (all repos on the workspace row; the focused checkout or worktree; the compare tab's checkout). The title names the scope (`Go to file · all repos` / `Go to file · <checkout>`). The file list loads and scores off the event thread. Type `>` first to switch to commands. Same overlay from Normal, pending `z` / `g`, and `V` highlight |
| `Ctrl-k` | Quick Open, commands mode (`>` already typed; backspace it for files). Named commands. Type to filter (every letter types, `j` / `k` too; aliases such as `exit`, `compare`, `discard`, `checkout` also match); `:` types too; ↑/↓, Ctrl-n / Ctrl-p, Ctrl-j / Ctrl-k move; Enter runs (closes first, then dispatches). Only Esc closes with no run, as in every picker. Rows sit under their group header (MOVE, GIT, …) and do not repeat the group; only rows whose header scrolled off the window keep a group label. Disabled rows paint their reason dimmed at the right edge when it fits. Compare open/close is palette-only: Diff vs default in new tab, Diff vs branch in new tab…, Diff vs commit in new tab…, Diff commit vs parent in new tab, Close tab (no key chip). Other overlays never open Quick Open. Text prompts still type `:`. `?` / `/` / `p` / `P` stay. Not Ctrl-p |
| `j` / `k` or arrows | Move the focused list or file-diff row. Hold repeats (terminal key-repeat). After a drill, the right pane follows the left row (graph → commit files, commit-file → diff, commit-file folder → folder summary). The viewport keeps the focused row near the vertical middle |
| `z` | Toggle fold on this row. On the graph or a file diff it says `z folds tree rows` and arms no `zz` |
| `zz` | First `z` toggles this row immediately and arms a 400ms pending. Second `z` in the window applies that same fold to foldable descendants (no extra toggle of this row). A late second `z` is a new single toggle |
| `t` | Toggle directory tree / flat paths. On the workspace tree this is `tree_mode`. In a commit-files or commit-diff drill this is an independent commit-file tree mode (default tree). Status is `Directory tree` / `Flat paths` |
| `h` / `l` or left / right | Tree or a commit-file folder row focused: close / open fold. Hold repeats. Shift-Left / Shift-Right pan the focused pane (tree, graph, commit-files, or diff). Graph, a commit-file file row, or file diff focused: `h` / `l` pan. Horizontal mouse wheel (and Shift-wheel) pans the pane under the cursor without changing keyboard focus. Trackpad hscroll is SGR `66`/`67`. When a file diff has long lines, that report over the left pane pans the diff. Space does not fold |
| `.` | Show or hide ignored repos |
| `/` | Search the focused pane (workspace tree, graph, commit-file list, or file diff). Enter arms the query. Esc while typing clears it and puts the cursor, scroll, and folds back where `/` found them. Armed, the status row shows `/query 3/7 · graph` (match position, count, bound pane; `-/7` off a match) and `Esc clear` / `n N next / prev` chips (the search chip after the row's actions, so it is the first to go on a full row); Esc clears the armed search. When `?` help is open, `/` opens a help query: characters (including `n`/`N`) append; highlight only; rows stay visible. Esc clears the query (help stays). No Enter-arm and no `n`/`N` next/prev while help search is open. `?` / `q` / Esc with no query still close help |
| `n` / `N` | Next / previous match on the pane bound at `/` (previous is `N`, not `p`). A step past the last (or first) match starts over and says `search wrapped`. With no armed search they say `no search — press / first`. While help search is open these keys append to the query instead |
| `g` / `G` | `gg` (second `g` within ~400ms) moves to the start of the focused list or file-diff. On a commit-file list (compare or drill), start is the first file row, the same index as a new compare load, not a directory. Lone `g` expires with no move. Key release does not move and does not cancel the pending. A typeless CSI-u echo of `g` inside a few milliseconds is ignored. A later typeless `g` (one CSI-u per tap), including a fast human `gg` under 80ms, completes `gg`. A raw-byte second `g` also completes `gg`. Pending expiry clears a stale arming-`g` echo. `G` is the end. Home / End also jump to start / end. The viewport follows |
| `gt` / `gT` / `g1`–`g9` | Next tab / previous tab / jump to tab. `1` is Workspace. A missing index is a silent no-op. Bare `t` stays flat/tree. Bare `T` stays theme. A typeless CSI-u echo of the same key does not fire bare `t` / `T`. Pending expiry must not turn a later `gt` / `gT` into bare `t` / `T` |
| `Ctrl-u` / `Ctrl-d` | Move the focused list or file-diff ±5 rows. The viewport keeps that row near the vertical middle. PageUp / PageDown stay one viewport |
| `Ctrl-o` | Toggle unlimited `-U` context when the right pane is already a file diff. Fires from a left-focused workspace file or commit-file as well as from the right pane. A second press restores the previous context. No-op on tree, graph, or a commit-file list. Over a folder summary it says `focus a file diff` |
| `s` | Stage dirty files in the focused scope (file, dir, section, checkout, or flat repo). Workspace and family-container rows are a no-op. On a `V` highlight of a working-tree file diff, stage only that add/del range (`git apply --cached`), not the whole file. On a commit / stash / worktree drill diff, refuse with a breadcrumb (no `git apply --cached`). A compare tab refuses with `cannot stage a compare diff` |
| `u` | Unstage dirty files in the focused scope. Workspace and family-container rows are a no-op. On a `V` highlight of a working-tree file diff, unstage only that staged range (`git apply --reverse --cached`). On a commit / stash / worktree drill diff, refuse with a breadcrumb (no `git apply --cached`). A compare tab refuses with `cannot unstage a compare diff` |
| `x` | Revert dirty files in the focused scope. Workspace and family-container rows are a no-op. The confirm shows only the keys that apply: `y` discards tracked and keeps untracked, `Y` (when untracked is in scope) also deletes untracked, `y` deletes a sole untracked file, and several untracked files with nothing tracked take `Y` only. On a `V` highlight of a working-tree file diff, discard only the highlighted unstaged add/del lines from the worktree (`git apply --reverse`) after a `y` / `n` confirm. The index does not change. Refuses a new file. On a compare tab, `x` on a file row or the open diff restores that file from the compare merge base in the worktree (added file: deleted), and `x` in a highlight reverts those lines to the merge base; both need a clean file with HEAD still at the compare head |
| `e` | Edit the focused workspace file, commit-file row, or commit-file diff (config `editor`, `$VISUAL`, or `$EDITOR`). While a folder summary shows, it says `focus a file to edit` |
| `E` | Diff the focused workspace file, commit-file row, or commit-file diff (config `diffTool`, default vimdiff). While a folder summary shows, it says `focus a file to diff` |
| `f` | Fetch visible targets. Workspace fans out to primaries. No-updates group is a no-op |
| `p` | Pull visible targets that are behind. Workspace / repo / checkout only — on a file or dir row it says `focus a repo or checkout to pull`. No-updates group is a no-op |
| `d` | Switch visible targets that are off the default branch. More than one repo asks first (`Switch N repos to their default branch?` · `dirty repos are skipped`, `y` / `n`); one repo switches at once. Already-default is a no-op (does not pull). Same kinds as `p` — on a file or dir row it says `focus a repo or checkout to switch to default`. No-updates group is a no-op |
| `P` | Push the focused visible repo or checkout when it is ahead, diverged, or has no upstream. In-sync is a no-op |
| `S` | Stash menu. Left-pane only (right-focused graph says `focus the left pane (Tab) to stash`). Tree dirty file or repo is create-only (`s`). A tree row on a clean checkout with stashes offers apply / pop of the latest. Graph commit or uncommitted (left-focused, e.g. commit drill) offers apply / pop of the latest stash; drop needs a focused stash row (`a` / `p` / `D`) |
| `Enter` | Left: focus right (same stack). Right: drill down and stay on the right (graph → commit files → commit diff). No-op at the depth-2 leaf. Compare left → right. Compare right is a no-op. The `Enter drill` chip shows only where Enter drills (not on a file diff, a commit-file directory, or a compare tab) |
| `Esc` | Right: move focus to the left pane (same depth). Left: pop one depth and stay on the left (no-op at depth 0). Compare right → left. Compare left does nothing (the tab stays; close it with the `[✗]` click or palette Close tab). Esc never quits. Visual-line highlight (`V`) cancels first, then an armed search. The chip names the effect: `Esc ← tree` / `← graph` / `← files` (focus left), `Esc ↑ files` / `↑ graph` (pop a depth), `Esc clear`; no chip where Esc does nothing. A pop sets no status |
| `a` / `p` / `D` | Apply / pop / drop the focused graph stash row. Drop asks `y` / `n` |
| `b` | Tree: local branch picker (list, filter, checkout; a `+ create branch <name>` row creates at HEAD and checks out). Graph commit: checkout refs on that commit (one name checks out, several open a name picker). Dirty tree refuses (`Dirty worktree — commit or stash first`). Origin out-of-sync confirm only for a selected `origin/…` name |
| `c` | Graph commit: create a branch at that commit (`git branch -- name commitId`). No checkout. No-op when a graph commit is not focused |
| `o` / `O` | Graph list or highlighted repo / worktree: focus local branches / restore the full graph. `o` opens an overlay (filter, space to mark, Enter applies). While focus is on, the graph is only ancestors of those tips. `O` clears |
| `m` | Graph commit: merge that ref into the checkout's current HEAD after a boxed confirm. Fast-forward when possible, otherwise a merge commit (no rebase). Dirty tracked worktree refuses (`Dirty worktree — commit or stash first`). Conflicts stay uncommitted. Tags use the commit they point at. Linked worktrees only when that checkout row is focused. Tree / stash / uncommitted `m` still toggles mouse capture |
| `r` | Reload the focused checkout. Workspace row or No-updates group reloads the whole workspace |
| `space` | Mark a dirty workspace-tree file as reviewed (depth 0 only; off a file it says `focus a file to mark reviewed`, and in a graph or commit-file drill `reviewed marks are for workspace-tree files · Esc back to the tree`). Does not flip reviewed after a commit drill. On a compare tab, marks the focused committed file (session-only per tab; a new HEAD or merge base hides it) |
| `;` | Comment overlay on the focused numbered diff line, or an object comment on a commit / non-default branch / worktree. Without highlight, `;` opens the stored span that covers that line (smallest span, then lowest start). Empty Enter deletes that span. While the overlay is open, Shift-Enter inserts a newline. Left / Right / Home / End move the caret (Home / End are the current line). Ctrl-a / Ctrl-e are line start / end. Ctrl-Left / Ctrl-Right move by word. Insert, Backspace, and Delete apply at the caret. Ctrl-r toggles resolved. The idle status row is replaced. Workspace and default-branch rows are not object-comment targets unless the repo has exactly one non-default branch (then the comment attaches to that branch). Persist under `comments.json`. |
| `V` | Visual-line highlight on a focused file diff (working-tree, commit, or compare). `j` / `k`, arrows, `gg` / `G` / Home / End, PgUp / PgDn, and Ctrl-u / Ctrl-d extend or shrink the range. `?`, `q`, `T`, `m` work as in normal mode; any other key says `Esc exits highlight`. `;` opens the comment overlay on that line span. On a working-tree file diff, `s` / `u` stage / unstage the highlighted add/del lines. `x` discards the highlighted unstaged lines after a confirm. On a commit / stash / worktree drill diff, `s` / `u` / `x` refuse with a breadcrumb (no `git apply`). On a compare diff `s` / `u` refuse and `x` reverts the highlighted lines to the compare merge base after a confirm. `Ctrl-k` (or `:` then `>`) opens Quick Open commands over the range (HIGHLIGHT rows run on it; rows that would drop it show `exit highlight first (Esc)`). Esc leaves highlight without commenting. Watch reload, split/inline, or a painted-row change drops highlight. No-op on the tree, graph, or a commit-file list. Over a folder summary it says `focus a file diff`. |
| `y` | Copy comments for the focused tree / graph / commit-file / diff row and its descendants as markdown (after GC) and show them in an overlay. The overlay header shows the copy result (`copied to clipboard` / `copy failed …`) and the status reads `copied` / `copy failed` like `'`. With no comments in scope it copies nothing, opens no overlay, and says `no comments here`. Resolved comments stay in the copy and carry `[resolved]`. A line comment with a newline stays one markdown bullet. Continuation lines are quoted. A file copies that path only; a folder copies files under it. A family row copies Worktree object comments for every family checkout. A linked-worktree row copies Worktree comments keyed by that family identity and by this checkout path, not sibling worktrees. Matching uses `repo_identity` and snapshot checkout paths, not a path prefix. Confirm-mode `y` is still revert-yes |
| `'` | Copy a pasteable entity reference for the focused tree / graph / commit-file / numbered-diff row. A file or dir on a compare tab also includes `base:` (the other branch). A compare diff `source:` is `compare <base>...<head>`, not `worktree`. Status is `copied` when the copy succeeds. Status is `copy failed` when OSC 52 and the host tool both fail. No overlay. No comment store write. Search still types `'`. `;` is unchanged |
| `W` | Remove the focused linked worktree after a boxed confirm (`y` / `n`). Unshifted `w` is not this action. Other rows refuse with `Focus a linked worktree to remove` |
| `Tab` | Focus the other pane |
| click | Select a tree, graph, or commit-file row, or focus the right pane. Click the fold chevron to toggle that row's fold |
| double-click | Same as Enter / drill on the clicked cell. A chevron double-click still folds (once; it does not Enter) |
| right-click | Same as Esc: one step back (or leave `V` highlight); in a pending `z` / `g` chord it is swallowed like Esc, with no step back. Overlays ignore it. Off with mouse capture |
| `m` | Toggle mouse capture except on a focused graph commit (merge, above). Off ignores click / drag / wheel |
| drag | Resize the tree / right pane split, or the in-diff side-by-side RULE. Drag a graph scrollbar thumb or a file-diff horizontal thumb to scroll / pan; click the track to jump. Drag inside a pane body to select its text; release copies it |
| `i` | Toggle inline / split on a file diff. Split needs a painted diff width of 100 columns (the right pane less its scrollbar column); below that the diff paints inline, the header reads `inline (too narrow)`, the status pill `split→inline`, and `i` says `split needs a ≥100-col diff pane (now N) — widen it with < or drag` |
| `<` / `>` | Narrow / widen the tree pane by 5% of the terminal width (the right pane takes the rest). Same clamp as a divider drag; at the edge it says `tree pane is at its narrowest` / `widest`. Session-only. Palette: Narrow tree / Widen tree |
| `\` | Toggle soft word-wrap on a file diff. Session-only (no pref file). Continuation rows use a blank gutter and sign. Horizontal pan is a no-op while wrap is on |
| `M` | Collapse / expand the selected commit / stash message. Expanded is the default; the toggle is session-only. Graph list rows stay one line. Expanded, the graph selection footer and the commit-files footer wrap subject plus body. The commit-files footer sits at the bottom of the depth-2 left (commit-files) pane under the file list, and the list keeps at least one row. A message taller than the graph footer scrolls with the mouse wheel over the footer (the list cursor stays put). Status is `msg on` / `msg off`. Graph `m` stays merge / mouse |
| `T` | Cycle the built-in colour theme. Wraps. Seed from `WS_STATUS_THEME`; the cycle stays in this session (there is no theme file). Graph gutter lanes use that theme's lane colours |

`-a` starts with ignored repos shown. `-f` starts a fetch after the first paint. First TUI paint does not wait on a git network fetch. A GitHub Release check may run **before** the TUI mounts (at most every 6 hours; `--plain` / `--json` / `--update` skip it).

`WS_STATUS_WATCH_MS` polls local git and refreshes the snapshot. Default is `3000`. `0` disables the poll. Fold, focus, and scroll stay put. File, graph, and commit-file rows flash (~800ms background fade) when that row's identity is added, updated, or removed. Add uses the green `flash` ramp. Update uses amber `flash_update`. Remove uses red/magenta `flash_remove`. File signatures use the git status letter **or** worktree `size:mtimeMs`, so an in-place save of an already-modified file flashes. Chrome rows flash when label / fold / repo path / `HEAD` / sync note / change count moves. A disjoint identity set (first paint, repo switch) seeds signatures and does not flash. Graph autoload of older commits skips add-flashes. Status colours stay; the flash is background only. Flash background wins over cursor and search so a focused file still shows the tint. The cursor bar (`▌`) stays. While a flash is decaying, the presenter ticks every `FLASH_TICK_MS` (120ms). Each checkout result applies as it finishes; a slow repo does not hold the others or the focused pane. An unchanged poll skips the right-pane `git log` / diff reload. The next tick is due from the start of the interval so a slow collect does not stretch the gap.

`WS_STATUS_FETCH_MS` runs `git fetch` on every snapshot checkout except hidden ignored repos, including linked worktrees. Default is `300000` (5 minutes). `0` disables it. The watch poll stays a separate timer. Shown ignored repos (`.` / `-a`) are included. Manual `f` stays focus-scoped: primaries on the workspace / family row, and a linked worktree only when that row is focused.

## What this TUI does

- Tree of repos, linked worktrees, and dirty files from the same snapshot builder as `--plain` / `--json`. Chrome: status letters on the right, Nerd file/folder/sync glyphs, file-oriented workspace header, branch-labeled linked checkouts
- Files sit in a directory trie by default. `t` toggles tree / flat on the workspace. Status is `Directory tree` / `Flat paths`. When a checkout has any staged path, that trie sits under **Staged** then **Changes** section headers (empty side omitted)
- Dir rows fold with `z` / `h` / `l`. First `z` toggles immediately and arms a 400ms `zz` window; second `z` applies that same fold to foldable descendants. A dir `s` / `u` / `x` writes files under that dir on that section side. Changes dirs always use a `#unstaged` id so a collapsed name that does not match Staged still stays on the unstaged side
- Tree / flat stays in this session. There is no session store on disk. Commit-file lists have their own `t` toggle and the same dir-trie collapse
- Right pane at depth 0: file diff when a dirty file is focused. Graph pane via `workspace-status-graph` when a repo or worktree is focused
- File diffs paint `{repo}/{path}  inline|split` (plus ` · full` / ` · pan N`; a long path wraps over at most half the pane) then STAGED / UNSTAGED / NEW labels and a line-number gutter. Cells clip and pad by display columns (`slice_cols` / `visible_width`) so emoji stay two columns and the split RULE stays on the context-row column. The comment mark column is reserved on every numbered cell so a `;` comment does not shift the numbers. Open comments paint `"`. Resolved comments paint `'`. After a commit drill to depth 2 the left pane is the commit-file list, so the header is the path. Syntax highlighting uses the file path (`tui/syntax.rs`) and paints token foregrounds on add/del row backgrounds. A compare tab uses the active compare file. Paint bounds highlight work to the visible viewport and starts a new parse stream at each hunk or section. The span cache keys on painted diff text, not the `DiffContent` address. Changed words on a paired modified line get `diffAddWordBg` / `diffDelWordBg` (`tui/word_diff.rs`).
- Hidden ignored repos stay out of the tree, search, stage / unstage / revert, and fetch / pull / push / default unless you show them. Linked worktrees of a hidden ignored primary stay out of the tree too and return with `.` / `-a`
- `/` searches the focused pane. Tree matches include folded rows and unfold ancestors. Graph search matches commit subject, body, author, painted (relative or local) or UTC time, branch and tag names, and sha (stash and worktree rows use the same fields when present). Commit-file search matches paths. Diff search matches painted line text. Matching tree, graph, commit-file, and file-diff rows paint the filter/search background with their text in the filter foreground (readable in every theme); on a diff every matching row is marked and the cursor bar sits on the current hit. An active flash wins over cursor and search. The cursor bar stays. When `?` help is open, `/` opens a help-local query (highlight only; rows stay visible; `n`/`N` append)
- `Ctrl-o` toggles unlimited unified context when the right pane is already a file diff, including from a left-focused workspace file or commit-file. A second press restores the previous context. No-op on tree, graph, or a commit-file list
- Fetch / pull / default do not fan out to linked worktrees unless the focused row is that worktree. `p` / `d` do nothing on file and dir rows but say why; `p` with nothing behind says `nothing behind to pull`, or `<repo> has diverged — pull it from a terminal` when a target diverged (it never merges a diverged branch); `f` still fetches the scoped checkout. The No-updates group is a no-op for `f` / `p` / `d`. Workspace `f` / `p` / `d` still targets visible primaries. The background fetch timer still includes linked worktrees (and shown ignored); it skips hidden ignored. Independent checkouts fetch / pull / push in parallel (`FETCH_CONCURRENCY` = 10) on a per-gitdir queue. A second `f` / `p` / `P` enqueues. Mixed kinds paint `Fetching 1 · Pulling 1…` or `Fetching 1/2 · queued 1`. While any of those (or `P`) runs, the breadcrumb trailing slot shows `Verb n/N…` and repaints as each repo **completes**. When the op finishes, that slot shows `Fetched N repos` / `Pulled N repos` / `Pushed N repos` / `Switched N repos`, with ` (N failed: <first repo> — <git reason>)` (`, +N more` when several failed) and ` (N skipped: dirty)` for a `d` that left a dirty repo alone. A pull whose auto-stash pop conflicted reads `<repo>: pulled, but restoring local changes conflicted — resolve, then check git stash list` instead (error; the stash entry is kept). Repos that worked are not listed. The background fetch timer paints neither line unless a repo fails.
- Tree writes (`s` / `u` / `x` / `f` / `p` / `P` / `d` / `b` / `W`) no-op at commit-files depth ≥ 1 (they must not write the hidden workspace-tree cursor). The same keys, plus `S`, no-op when the right pane is focused unless the allow-list matches: graph `b` / `c` / `m` / `a` / `p` / `D` (`GraphCheckout` / create / `GraphMerge` / stash apply-pop-drop), commit-file nav, and diff `e` / `E` / `Ctrl-o` / (`space` at depth 0 only). Tree `b` and `S` stay left-only. Compare `x` is the exception: it also runs from the focused compare diff
- `W` removes the focused linked worktree. Unshifted `w` does not. Workspace, repo family, file, and hidden ignored rows do not remove. Confirm is a boxed overlay (`y` / `n`, merge status, and `N changed files will be deleted permanently · branch <b> is kept` when dirty; a detached worktree has no branch part). A non-linked row sets `Focus a linked worktree to remove` instead of a silent no-op. Bind-mount aliases remap the same way as discovery
- `h` / `l` on a graph, a commit-file file row, or focused file diff pan long labels and lines. They still fold when the tree or a commit-file folder row is focused. Shift-Left / Shift-Right pan the focused pane, including the tree, without growing rows
- Stage / unstage / revert act on dirty files in the focused scope (file, dir, section, flat repo, or checkout). A file row stays single-file. A dir row writes the dir path and its children on that section side. A Staged / Changes header writes every dirty file on that side of the checkout. Workspace, No-updates group, and family containers are a no-op. Hidden ignored stay out unless shown. Revert asks in a boxed overlay with tracked/untracked counts and only the keys that apply: tracked only `y` / `n`; mixed `y` (keeps untracked) / `Y` (also deletes untracked) / `n`; one untracked file `y` (delete) / `n`; several untracked files `Y` (delete) / `n`. A key the box does not show does nothing. Stage and unstage do not confirm
- `e` uses config `editor`, then `$VISUAL`, then `$EDITOR`, then `vim` (git's order). It opens a focused workspace dirty file, a focused commit-file row, or a focused commit-file diff. On a compare tab it opens only that tab's committed file — never a parked Workspace dirty path. A TTY editor leaves the alternate screen and returns to the same fold, focus, and scroll. GUI editors (`cursor`, `code`) spawn without a remount; a spawn error shows `edit failed: <cmd>: <error>` instead of `opened <path>`. Resume drains leftover raw-mode keys
- `E` uses config `diffTool`, or `vimdiff` when omitted or blank. There is no `$EDITOR` fallback. It opens a diff of the same focused file as `e` (compare: merge-base LEFT, HEAD RIGHT). Blob bytes and temp files run on `spawn_blocking`; the loop then spawns the tool. vimdiff takes the TTY (leave alt screen, resume). Cursor / VS Code (`cursor --diff --wait`, `code --diff --wait`) spawn detached and stay mounted. Temps live in `$TMPDIR/workspace-status-ext-diff/<pid>-<nanos>/`. TTY tools delete that session after the child exits. Detached tools wait on a side thread and delete only that session. Without `--wait`, the Cursor / VS Code CLI exits in a few seconds and that cleanup removes the LEFT HEAD temp before the IDE opens it. The same `--wait` rule applies on macOS and on WSL2 with Windows Cursor. Later `E` does not delete other sessions' files.
- `P` pushes the focused visible repo or checkout only when it is ahead, diverged, or has no upstream. In-sync is a no-op (`nothing to push`). Workspace never fans out: `P` there says `focus a repo or checkout to push`. Hidden ignored stay out. Linked worktrees push only when that row is focused
- `S` on a dirty tree file or repo is create-only (`s stash`). `S` on a tree row of a clean checkout that has `stash@{0}` offers apply / pop of that latest stash (`a` / `p`); with no stash it says `nothing to stash`. Menu drop is labelled `D` like the graph key; `d` also drops. `S` is left-pane only: a right-focused graph says `focus the left pane (Tab) to stash`. On a left-focused graph (commit drill) or when the menu is already open, a graph commit or uncommitted row offers apply / pop of the latest stash (`a` / `p`); drop stays off unless a graph stash row is focused. ## Layout

Left pane: workspace tree at depth 0. Clean default-branch repos sit under a folded `No updates` group. Depth 1 (commit files) puts the graph list on the left. Depth 2 (commit diff) puts the commit-file list on the left.

Right pane: graph for a repo or worktree at depth 0, a numbered file diff when a dirty file is focused, or the commit-file tree (depth 1) / that file's commit diff (depth 2). Commit files still loading with 0 rows paint muted `loading files…`; a loaded empty list paints muted `no files in this commit`. A focused repo whose graph is still loading paints `loading graph…`. A failed `git diff` paints `git diff failed: <reason>` instead of `(no diff)`, or as the last diff row when the other side loaded.

Pane chrome: titles are the plain pane name (`tree`, `graph`, `files`, `diff`) whether focused or not. Title text stays full-bright (`palette.heading`) on both panes. `borderDim` is borders only — not title text. Focus is dim-border-only: unfocused borders use `palette.borderDim`; focused borders use `palette.heading`. Body text stays full brightness and is not DIM because the pane is unfocused. The focused list paints the cursor bar (`▌` / `cursorBg`). An unfocused list still marks the selected row with a thinner `▏` marker and `cursorBgInactive` (darker than `cursorBg`). The selected row is never blank.

A file diff paints a path header (`{repo}/{path}  inline|split`, plus ` · full` when unlimited `-U` is on, ` · wrap` when soft-wrap is on, ` · pan N` when panned) then STAGED / UNSTAGED / NEW section labels and a line-number gutter. The comment mark column is reserved on every numbered cell so adding a comment does not shift the numbers. The focused row uses the same cursor bar as other lists. An unfocused file-diff keeps the thinner inactive marker on that row. `j` / `k` / wheel move that row. The viewport keeps it near the vertical middle. At depth 2 the left pane is the commit-file list, so that header is how the file path stays visible on the right. A path wider than the pane wraps over several rows by display columns, at most half the pane height; the extras follow on its last row. Syntax highlighting uses the file path and paints token foregrounds. A compare tab uses the active compare file. Paint bounds that work to the visible viewport and resets parse state at hunk and section rows. The span cache keys on painted diff text, not the `DiffContent` address. Add/del rows keep `diffAddBg` / `diffDelBg`. The `+` / `-` signs stay `added` / `deleted`. Changed words on a paired modified line get the stronger `diffAddWordBg` / `diffDelWordBg` (see [diff-rendering.md](./diff-rendering.md#word-highlight)). Destructive confirms are boxed overlays. A 1-column position scrollbar tracks the diff whenever it overflows the pane (its column stays reserved when hidden); a 1-row horizontal bar tracks pan after the view leaves the left edge. The horizontal thumb is mouse-draggable (`hit_split` / `SplitDrag::DiffHScrollbar`, same stack as the graph bars). A track click jumps pan without moving `diff_cursor`. Compare tabs use this same `draw_diff` paint.

Graph commits and stashes paint two lines: subject on the node row; refs / `stash@{n}`, short hash, date (relative through 3 hours, then local `YYYY-MM-DD HH:MM`), and author on the spacer beneath. Narrow spacers truncate the next leftover **branch or tag** name with `…` (brackets stay) when part of it still fits; `[+N]` counts only chips that are fully hidden after that (bold heading accent, not muted meta; omit `[+N]` when the last painted chip is merely truncated). The footer lists every full branch/tag (HEAD commit refs on the working-tree row). The spacer stays within the pane width so the row does not grow with extra refs. The gutter is capped (`≤30%` of the pane, ≥24 columns for refs+subject) and clipped with one left-aligned window per paint so rails stay column-aligned when the subject or spacer meta clips. PageUp/PageDown keep the focused row near the vertical middle (`visible − 1` overlap). A 1-column position scrollbar tracks the graph list whenever it overflows, at the top too; a 1-row horizontal bar tracks pan after the viewport leaves the left edge. Both thumbs are mouse-draggable (`hit_split` / `SplitDrag::GraphScrollbar` / `GraphHScrollbar`, same stack as pane and in-diff splitters) and a track click jumps toward that position. The selected graph row uses `▌` plus `cursorBg` when the graph is focused (not reverse video). An unfocused graph keeps `▏` plus `cursorBgInactive`. Local and `origin/*` names stay visible on commit spacers (matching local+remote tips merge into one chip). The spacer is not a second cursor or search target — `j` / `k` / click / Enter / Esc still treat the commit or stash as one item. When the pane is narrow, meta drops hash, then date, then author, keeping refs / `stash@{n}`.

Graph history: `log --exclude=refs/stash --all --topo-order --date-order --skip --max-count` with a 300-commit window. Reaching the last loaded row fetches the next page and paints `loading older…`. Missing `stash^1` parents are loaded with `log --no-walk --ignore-missing` and sit after the log prefix so autoload skip stays on the window, not `commits.len()`. The working-tree row is always present on a loaded graph (`Working tree clean` / `Uncommitted changes`; dirty vs clean is the label only). The pane keeps a 2-line selection footer (footer before header when space is tight): uncommitted → HEAD commit ref chips, or `worktree · not a commit` when HEAD has none; spacer → `connector · not selectable`; stash → `stash@{n} ·` hash `·` date; commit → all ref chips or `(no refs)` `·` hash `·` parents (`parent <id>`, `parents <id> <id>` first parent first, or `root commit`) `·` author `·` date; empty → `no selection`. Footer chips reuse the row-chip `LabelKind` runs so tags, feature branches, the default branch, and HEAD stay distinguishable (`headMark` / `branchFeature` / `branchDefault` / `dir` / `modified`); hash / parents / date / author stay muted. Subjects paint stronger than hash/parents/date/author; branch chips, tag chips, HEAD, and the default branch use the palette (`headMark` / `branchFeature` / `branchDefault` / `dir` / `modified`). Each gutter cell uses its `color_lane` from `DEFAULT_LANE_COLORS`. Linked worktree nodes use `ICON_LINKED_WORKTREE` (`` / `L`), not the 2-column `🔗` emoji.

Below 46×12 (`MIN_TERM_COLS` × `MIN_TERM_ROWS` in `tui/split.rs`: the help overlay's narrowest readable width and the rows a graph list with its footer needs) the TUI paints only `terminal too small (W×H — need ≥ 46×12)`. Only Esc, `q`, Ctrl-c, and resize map; every other key and all mouse events are dropped until the terminal is large enough again, so a blind `s`, `P`, or hidden `y` does nothing. Esc closes any hidden overlay. `q` quits only when no text overlay is open; in a text overlay it types.

The tree / right split defaults to 40% tree. The in-diff RULE defaults to 50/50. Drag either splitter (3-column grab band). Drag a graph scrollbar thumb or a file-diff horizontal thumb (same `hit_split` / `SplitDrag` stack); a track click jumps toward that position. Neither pane or column can collapse to zero. Both ratios are session-only. Tree and commit-file lists pan with the wheel and keys only; they do not paint an h-bar.

A left press in a pane body (not a splitter, bar, or tab) also arms a `TextSelection` (`tui/selection.rs`) clamped to that pane's inner rect. Drag moves its head. `draw()` keeps a copy of the painted frame in `AppState::painted_frame`, then adds `Modifier::REVERSED` to the selected cells. Release reads the text from that copy, so it matches the screen even when drag and release arrive before the next frame. Rows run like a terminal stream, trailing spaces are trimmed, and a wide glyph is read once. A non-empty selection returns `Effect::CopyClipboard { announce: true }`.

Crossterm `Resize` is a first-class action. The live loop is one async `select!` (`tui/event_loop.rs`) with a dedicated input thread (`tty::poll_event` / `read_event_origin`) and a bounded input batch so keys cannot starve watch/fetch or worker results. On Unix the reader tags raw key bytes versus CSI-u so a human `gg` is not dropped as a typeless echo. It decodes SGR, X10, and 1015 mouse the same way as crossterm 0.28. A lone ESC waits one non-zero poll timeout with no further stdin before it becomes Escape. A 0 ms drain does not count as that wait. A hangup or 0-byte read is a read error and the input thread exits. Held nav (`h`/`j`/`k`/`l`, arrows, page) maps Repeat like Press and drops queued copies of that key after each move so a hold cannot flush as a burst after release. Keyboard enhancement reports Shift-letter as the unshifted codepoint plus SHIFT; the keymap folds that to the uppercase binding so `O` / `S` / `E` / `/` capitals match a raw `'O'` byte. `Terminal::resize` uses the event size (ioctl can still report the previous size). Pane widths, graph gutter cap, dialog sizes (help lays out at the box width, `dialog_width(chunks[1], Help)`), and list viewports recompute from the new area. Confirm / help / picker / command-palette overlays keep `y` / `n` / Esc; other keys are swallowed and do not start fetch or watch ticks. Graph autoload (`loading older…`) runs only after list movement (`j` / `k`, page, search next/prev, click, wheel), not after resize, mouse drag, or ignored overlay keys. `q`, Tab, Home/End, and family-row `b` stay. A small presenter draws only on the loop thread (dirty flag, ~16–33ms cadence, 120ms while flashes decay).

Fetch / pull / push of independent checkouts share the Scheduler JoinSet cap (`env_fetch_concurrency`, Ink `FETCH_CONCURRENCY` = 10). `RemoteQueue` occupies by `primary_repo` else checkout path. Eligible spawn skips an occupied gitdir. Pending jobs coalesce. Default-branch stays serial. Watch/status is discover, then per-checkout `process_repo`; each result replaces that repo immediately and keeps unfinished checkouts from the previous generation. Paths the new discovery omitted (removed worktree, deleted repo) drop immediately. The focused checkout is queued first; its pane reloads as soon as that identity changes. A watch tick during a collect latches one rerun. Generation ids drop stale collect / pane / autoload / commit-files / commit-diff / picker / compare-tab / compare-file-diff results. Compare picker gens (`request_prepare_compare`) stay independent of `b` / `o` branch pickers. Compare-file diffs keep a latest request id per tab. Esc Diff→Files bumps the commit-diff generation so a late result cannot reopen Diff. The draw loop stays live: nav, pane switch, cancel, and resize still apply. While an exclusive write or default-branch switch runs, `q` shows `git write running · press q again to exit` and arms the Ctrl-c window; a second `q` or Ctrl-c quits. A key drained as `Ignore` (including `y` on a confirm) sets warn `busy: <op> running` (`stage`, `revert`, `checkout`, …; `busy: a git write is running` while the job is still queued). Quit drops remotes that have not started. In-flight git is unchanged. Held nav Repeat dispatches while a worker runs (`BusyAction::Handle`). Remotes are not a workspace mutex. `Fetch` / `Pull` / `Push` / `FetchTick` stay Handle and enqueue on the per-gitdir remote queue. Exclusive writes (`s` / confirm-yes / stash / checkout / merge / …) and default-branch are Ignore only while exclusive write or default-branch is busy. An exclusive write on an occupied gitdir still dispatches. Then `schedule` refuses with breadcrumb `busy`. A free gitdir may write while other repos fetch. Command-palette Enter classifies as the highlighted catalog Action (`classify_busy_dispatch`). Palette Fetch / Pull / Push stay Handle. Palette Stage / Revert / Edit stay Ignore. Help / search from the palette stay Handle. Palette nav / typing stay Handle. Git itself is started with stdin `/dev/null` and `GIT_TERMINAL_PROMPT=0` so a credential prompt cannot deadlock the TUI. Follow-up pane git (`git log` / file `diff`) is another worker job, coalesced by request id and target. An unchanged watch poll (tree signatures and checkout `HEAD` / sync note / dirty set) skips the pane reload. The next tick is due from the start of the interval (default 3s, 500ms floor; this is not inotify). Graph autoload (`loading older…`) is the same pool. `tty_event_loop_must_not_call_sync_pane_git` fails CI if pumps or loop-thread git return. Search, help, and mouse drag stay in-memory. A TTY editor pauses the input thread, unmounts the alternate screen, then resumes; after it returns, that checkout + pane reload on workers. `E` prepares LEFT/RIGHT on `spawn_blocking` (`blob_bytes` / temps) and only then spawns the tool on the loop. `cargo test` includes `snapshot_contract.rs` and `tui_tty_e2e`.

Bottom chrome is always the breadcrumb, the pinned Ctrl-c quit row while that prompt shows, and the status row. Dialogs are centered, fixed-height boxes that paint last, over the panes, after a `Clear` (`chrome.rs` `dialog_rect` / `dialog_width` / `dialog_height`). The panes never shrink for a dialog. A dialog is the pane area less 4 columns wide, at most `DIALOG_MAX_WIDTH` (96) columns except help, and a box taller than the pane area is clamped to it. The height is fixed per dialog and never follows a result count, so the input row (the first inner row) stays in place while the list changes. A list dialog (picker or Quick Open) is 17 rows: the query row, up to 12 list rows (`LIST_OVERLAY_MAX_ROWS`) that scroll around the cursor inside the box, a reserved status row, and the footer. A footer wider than the box drops chips from the left and always keeps its `Esc` chip. Help lays its columns out at the box width. When the columns are taller than the box, the body scrolls under the pinned group-title row with `j` / `k`, arrows, and PgUp / PgDn, and the footer adds `j/k scroll`. Stash, picker, create-branch, and comment-export boxes paint `status` inside the box. The status row stays blank while any dialog is open, except the comment box, which has no status row and leaves `status` on the status line (the stash box opens with no status: its op rows list the keys); the branch and graph-focus pickers show their filter only in the title. The breadcrumb mirrors the drill (`workspace › repo › hash`) and marks the right-focused segment with `[brackets]`. At depth 0 it always names the focused row's repo, on a file row too (`workspace › app`). Trailing op-status / toasts sit on that row. While a multi-repo `f` / `p` / `P` / `d` is in flight, that slot shows `Fetching n/N…`, `Pulling n/N…`, `Pushing n/N…`, or `Switching n/N…` and the TUI repaints as each repo completes (fetch / pull / push overlap on the per-gitdir queue). Mixed kinds paint `Fetching 1 · Pulling 1…` or `Fetching 1/2 · queued 1`. After the op, that slot shows `Fetched N repos` / `Pulled N repos` / `Pushed N repos` / `Switched N repos` (` (N failed: <first repo> — <reason>, +N more)`, ` (N skipped: dirty)`); a pull whose auto-stash conflicted shows `<repo>: pulled, but restoring local changes conflicted — …`. A failed local write (stage, unstage, revert, stash, worktree remove, create branch) shows `<op> failed: <git reason line>` (one line). A compare `x` that the worker refuses shows `revert aborted: HEAD moved` / `revert aborted: <path> has uncommitted changes` as a warn, without that prefix. The background fetch tick paints no progress or summary; it writes the slot only when a repo fails. Every status carries a `StatusKind` (`tui/status.rs`) that sets its color: info and progress muted, ok `added`, warn `modified`, error `deleted`. Info and ok clear 4 s (`STATUS_TTL_MS`) after they first show in the slot; progress, warn, and error stay until replaced. While an overlay echoes its own text into `status` (search, pickers, palette, comment), nothing expires. While `?` help is open the clock restarts, so a result gets its full time once help closes. A loaded commit-file list says `1 file in 49b9717` / `N files in <hash>` (`stash@{n}`, `<base>...HEAD`, `N uncommitted files`) once, on first load; a reload of an open view (watch, pane reload after a fetch or write) never replaces a progress, warn, or error. `loading older…` puts back the message it replaced. In-flight copy reads as progress (`reverting foo…`, `checking out main…`). A key that does nothing says why as a warn: a tree key from the right pane or a drill (`focus the tree (Tab) to stage` / `Esc back to the tree to pull`, the same reason the palette row shows), `gt` / `gT` with no compare tab (`only the Workspace tab is open`), `S` in a file-diff drill, `p` / `d` on a file row, `space` off a file, unarmed `n` / `N`, `z` on the graph or a diff (no `z…` pending), and an unmapped key in `V` highlight (`Esc exits highlight`). Held nav keys never repaint a refusal. The status line is mode pills (`tree`/`flat`, then the diff layout `inline` / `split` / `split→inline` only while the right pane shows a file diff), an armed-search `/{query} 3/7 · <pane>` pill, `? help` (or `z…` while a `zz` chord is pending), and contextual hint chips. Enter / Esc (labelled by their effect) come first, then the row's actions, the armed-search chip `n N next / prev`, and extras `;` / `y` / `Tab`. When they do not fit, the tail is cut and a muted `…` (text, not a chip) marks the cut; `q quit` always paints last. `/` typing replaces the bar with a SEARCH prompt. Confirms are rounded boxed overlays, not a status-line `y/n` prompt. The chip row shows the accept key (`y`, plus `Y` where it applies) and `n` `Esc` cancel. Enter never confirms; it sets info `press y to confirm · n or Esc to cancel` (`Y` when only `Y` accepts). The origin out-of-sync checkout box reads `Check out <b> and fast-forward to origin/<b> (no fetch)?` with `local is A ahead, B behind origin/<b>` when git can count (`· cannot fast-forward` when A > 0). `?` opens a 3-column overlay (MOVE / GIT / VIEW). Extras `q`, Tab, graph `c`, stash `a p D`, and Home/End stay in those columns. Each column stacks its own entries (rows are not aligned across columns), so the overlay is as tall as its tallest column; `help::help_column_widths` gives a long column (VIEW) width from a short one (MOVE) to keep that column short, and every column keeps a 2-column gutter on its right. Within a column the key chips take the width of its widest chip set, so descriptions line up. A description sits beside the chips only with at least 12 columns there (`HELP_MIN_DESC_WIDTH`) and when that paints no more rows; otherwise the chips take their own line and the description wraps under them at the full column width. On a compare tab `help::help_groups` paints COMPARE in place of GIT: the keys that act on the compare diff (`V`, `;` (Ctrl-r resolves inside the comment box), `y`, `'`, `x` and its condition, `Ctrl-o`, `space`, `e` / `E`, tab close) and the keys that need the Workspace tab (`s u`, `f p P d`, `b c W`, `S a p D`, `o O`); `r` refresh also works there. The help dialog height (`help_status_lines` at the box width) follows the columns that paint, so a compare tab sizes the box for COMPARE; a shorter box scrolls. On a compare tab the hint chips read the compare tab, not the parked Workspace tree row: only `x` / `e` / `space` / `Ctrl-o` can show, and `x revert to merge base` shows only while compare `x` would run. The overlay footer shows the Cargo package version (`CARGO_PKG_VERSION`, same string `ws --update` compares to GitHub release tags) in the lower-right, outside the keymap. Help `/` is query-append highlight-only: characters including `n`/`N` append; Esc clears the query; no Enter-arm and no next/prev wrap in help. `:` / `Ctrl-k` open Quick Open, a list dialog instead of that help wall. Its title is the scope in files mode (`Go to file · …`) and `Commands` in commands mode. The query row shows the raw query with a `▏` caret (the `>` stays visible; an empty files query shows `type a file name…`). File rows cut a long path from the left behind `…` so the file name stays, and paint the matched characters bold in the accent color. The status row shows `status`, else in files mode `indexing…`, `N files` (`(first 200000)` at the cap), `no file matches`, or the index error. Footers: files `↑↓ move · Enter open · > commands · Esc close`; commands `Enter run · Esc close`.
