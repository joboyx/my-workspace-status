# Configuration

## `.workspace-status-config.json`

Read from the workspace root (the cwd the script runs in), by `loadWorkspaceStatusConfig` in `src/config.ts`. A missing file means nothing is ignored and discovery uses the default depth.

```json
{
  "ignoredRepos": ["notes"],
  "maxDepth": 3,
  "defaultBranches": {
    "opella/opella-main": "develop"
  },
  "editor": "vim"
}
```

| Key               | Required                   | Default                   | Meaning                                                                                        |
| ----------------- | -------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------- |
| `ignoredRepos`    | yes (when the file exists) | `[]` when file is missing | Repo paths relative to the workspace root to skip                                              |
| `maxDepth`        | no                         | `3`                       | Walk depth for primary `.git` dirs/gitfiles (dot dirs skipped; linked via `git worktree list`) |
| `defaultBranches` | no                         | `{}`                      | Map of workspace-relative repo path → sole default branch for that repo                        |
| `editor`          | no                         | unset (`vim` at resolve)  | Command string for TUI `e` (same shape as `$EDITOR`). Overrides `$EDITOR` / `$VISUAL`.         |

### `ignoredRepos`

Entries are repo paths relative to the workspace root (`dotfiles`, `services/api`, `apps/web/packages/ui`). On load they are trimmed, path-normalized (strip leading `./`, trailing `/`, unify `\` to `/`), de-duplicated, and sorted — so `notes/`, `./notes`, and `notes` all match discovered `notes`. A malformed file throws rather than being ignored — a typo silently dropping repos from a status report is worse than a crash.

Ignored repos are skipped by discovery (the ignored path and everything under it), so they are excluded from status, fetch, pull, and default-branch switching. Ignoring a primary also drops its linked worktrees under that path; a linked path can be listed on its own in `ignoredRepos`. The TUI still discovers ignored repos so `.` can show them. Workspace-level `f` / `p` / `P` / `d` and background fetch skip those paths while they are hidden. When ignored repos are shown (`.` or launch `-a`), they follow the same primary / focused-worktree rule as other visible rows.

### `maxDepth`

Discovery has two stages:

1. **Directory walk** — under the workspace root, any directory with a `.git` directory or gitfile (some submodules / non-dot linked checkouts) counts as a **primary** repo, up to `maxDepth` path segments. Dot directories (e.g. `.worktrees/`) are **not** entered by the walk.
2. **Linked worktrees** — for each primary, `git worktree list --porcelain` adds other checkouts whose paths sit under the workspace cwd (typical layout: `app/.worktrees/<branch>`). Those rows get `checkoutKind: 'linked'`, a `🔗` marker, and optional merge-into-default marks (`✅` / `🌱`). The verbose dirty/clean column is **Files** (not “Worktree”).

| `maxDepth`    | Finds (walk)                | Example                |
| ------------- | --------------------------- | ---------------------- |
| `1`           | direct children only        | `dotfiles`             |
| `2`           | children + grandchildren    | `services/api`         |
| `3` (default) | through great-grandchildren | `apps/web/packages/ui` |

Nested repos under a parent repo are still discovered when depth allows (e.g. both `apps/web` and `apps/web/packages/ui`). Intermediate non-repo directories (like `packages`) are walked through. Values must be a positive integer; omit the key to keep the default of 3. Linked paths from `git worktree list` are not capped by `maxDepth` beyond “must be under cwd”.

### `defaultBranches`

Optional object mapping workspace-relative repo paths to a single default branch name (e.g. `"opella/opella-main": "develop"`). Keys are normalized like `ignoredRepos` (trim, strip `./`, unify separators). When a repo has an entry:

- Classification, summary Branches section, verbose ordering, and TUI branch markers / attention grouping treat **only** that branch as default (so `main` is non-default if the override is `develop`).
- `--default-branch` and TUI `d` switch to that branch (not `origin/HEAD`).

Repos without a key keep prior behaviour: classification still treats `main` / `master` / `develop` as default; switch target still comes from git (`origin/HEAD`, then those names).

### `editor`

Optional command string for TUI `e`, same shape as `$EDITOR` (`"vim"`, `"nvim"`, `"cursor"`, `"cursor --wait"`, `"code --wait"`). Not a closed list of names. `"cursor"` already opens at `path:line` via `-g`.

- Omit the key, or set `"editor": "vim"`, for **vim** (the default when `$EDITOR` / `$VISUAL` are also unset). vim takes the TTY (Ink unmounts, then remounts with the same session).
- `"editor": "cursor"` opens Cursor IDE without changing the shell `$EDITOR`. Cursor / VS Code stay mounted, so fold, focus, and scroll do not rebuild.
- Non-blank config `editor` overrides `$EDITOR` / `$VISUAL`. Blank / whitespace-only is treated as unset (fall through). Non-string values throw.

| Override              | Effect                                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `-a` / `--all`        | `ignoredRepos` is replaced with `[]` for that run; `maxDepth` / `defaultBranches` / `editor` from config are kept                                                                                            |
| Positional repo paths | Only those repos are processed, and they bypass `ignoredRepos` entirely. Naming a primary includes its linked children under cwd; naming a linked path (e.g. `app/.worktrees/feat`) includes only that path. |

The two overrides differ in the TUI. `-a` replaces the ignored list before `runTui` sees it, so the ignored set is empty and the surfaced repos render and fold like any other repo — expanded, no muted name, no ignored glyph. Positional paths leave the loaded config intact, so a named repo that is also in `ignoredRepos` renders with a muted name plus the ignored glyph and starts collapsed.

## Environment variables

| Variable                  | Default                                                 | Effect                                                                                                                                                                                            |
| ------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WS_STATUS_GLYPHS`        | unset                                                   | `ascii` replaces every Nerd Font glyph with a one-column ASCII marker (`icons.ts`, read once at module load). Any other value is ignored.                                                         |
| `WS_STATUS_WATCH_MS`      | `3000` (`DEFAULT_WATCH_MS`)                             | Live-refresh poll period. `0` disables the poll loop. Values below `MIN_WATCH_MS` (500) are clamped up. Non-numeric, negative, or empty falls back to the default.                                |
| `WS_STATUS_FETCH_MS`      | `300000` (`DEFAULT_FETCH_MS`)                           | Background `git fetch` period for the TUI. `0` disables. Values below `MIN_FETCH_MS` (30000) are clamped up when enabled. Non-numeric, negative, or empty falls back to the default.              |
| `WS_STATUS_THEME`         | `tokyo-night`                                           | Built-in TUI theme id: `tokyo-night`, `monokai`, `dracula`, `gruvbox-dark`, `catppuccin-mocha`. Unknown values fall back to `tokyo-night`.                                                        |
| `EDITOR`                  | unset                                                   | Fallback editor for `e` when config `editor` is omitted or blank. Blank values are ignored. May include fixed args (`code --wait`, `nvim -p`); simple quoting is supported for paths with spaces. |
| `VISUAL`                  | unset                                                   | Used when config `editor` and `EDITOR` are unset or blank (same argv parsing as `EDITOR`).                                                                                                        |
| _(editor fallback)_       | `vim`                                                   | When config `editor`, `EDITOR`, and `VISUAL` are all unset/blank, `resolveEditor` returns `vim`.                                                                                                  |
| `WORKSPACE_STATUS_GIT`    | `/usr/bin/git` if present, else `git`                   | Git binary. Exists to avoid a Windows `git.exe` shadowing the Linux one on WSL2, and as a test seam.                                                                                              |
| `WORKSPACE_STATUS_SCRIPT` | the repo's own `workspace-status.sh`                    | Test-only: point the E2E suite at a different script path.                                                                                                                                        |
| `KEEP_E2E_WORKDIR`        | unset                                                   | Test-only: `1` keeps each temp scenario on disk for debugging.                                                                                                                                    |
| `WS_STATUS_VIEWED_STORE`  | `$XDG_STATE_HOME/my-workspace-status/viewed-files.json` | JSON store for TUI space-reviewed marks (identity = repo path + file path; fingerprint = status + worktree bytes). Tests should set this to a temp file.                                              |

`WS_STATUS_GLYPHS` is captured at import time (`export const asciiGlyphs = …`), so changing it mid-process has no effect.

**Graph UI (P3) + commit files (P4):** focusing a repo/dir at depth 0 shows the multi-branch commit graph in the right pane; depth 1 left is the same graph list and depth 1 right is commit meta + file tree; depth 2 is commit files | diff. Graph lane colours follow the active built-in theme (`T` cycles); no new env var. Autoload window size is `SessionState.graphWindow` (default 300), not user-configurable. Commit file trees default to directory tree via dedicated `commitTreeMode` (independent of workspace `treeMode`).

## Nerd Font requirement

The TUI needs a patched **Nerd Font**. File-type devicons and the git/folder glyphs all live in the Unicode private-use area; without one they render as tofu boxes. Recommended: **MesloLGM Nerd Font Mono**.

Use the **Mono** variant. The proportional build renders icons roughly two columns wide, which breaks the layout arithmetic — `visibleWidth` counts private-use codepoints as width 1 and every pane width is computed from that assumption. For the same reason, `src/tui/icons.ts` must never gain emoji or CJK codepoints; those are double-width. Plain-report badges (`badgeForChange` in `src/changes.ts`) stay emoji, because the report is not laid out in columns.

`WS_STATUS_GLYPHS=ascii` is the escape hatch when no Nerd Font is available.

VS Code and Cursor resolve the terminal font on the client, independently of the system terminal. Set it in **User Settings**, not the WSL Machine settings:

```json
"terminal.integrated.fontFamily": "'MesloLGM Nerd Font Mono', monospace"
```

A missing Nerd Font only affects glyphs. It does not change which keys the terminal sends.

## Alternate screen

The TUI uses the terminal alternate screen (DEC 1049) while it is mounted. Normal quit writes leave sequences and shows the cursor. Process `beforeExit` and `exit` hooks do the same on abrupt exit. `SIGKILL` (`kill -9`) cannot run those hooks. After SIGKILL, reset the terminal if the primary buffer stays hidden.

## PageUp and PageDown on macOS

PageUp and PageDown page the focused pane when the terminal sends the key to the process. The parser accepts Ink `pageUp` / `pageDown` flags and CSI `ESC [5~` / `ESC [6~`. It also accepts the form after Ink strips the leading ESC.

On many macOS setups there is no dedicated PageUp key. `Fn+Up` and `Fn+Down` often scroll the terminal scrollback and never reach the TUI. Use `Ctrl-u` / `Ctrl-d` (±5 rows) when PageUp does not arrive.

Split falls back to inline below 100 columns (`NARROW_SXS` in `diffSplit.ts`); the status line then reads `inline (too narrow)`. Drag the in-diff RULE to resize columns for the rest of the session (resets on next launch).

Graph ref chips: default-branch names use `palette.branchDefault` (distinct from `muted`). Checkout / detached marks use per-theme high-contrast `palette.headMark` (Nerd Font crosshairs / `[HEAD]`). Synced chips put Nerd Font exchange before the branch name. Marks are PUA icons so MesloLGM keeps 1-cell metrics.

Mouse (when enabled): left-click any list row the keyboard can select (workspace tree, graph, commit files) to focus that pane and select it; **click the diff** to focus the right pane; click a fold chevron to toggle fold; double-click a list row (not the chevron) to run Enter (focus right / drill); wheel over a list moves that list's cursor (±1); wheel over the diff scrolls (±3). Drag the divider to resize.

Search (`/`) matches against a row's plain `label` (case-insensitive substring) and jumps the cursor; it does **not** hide or filter rows. Match rows get a search background highlight. `n` / `N` wrap through matches; `Esc` clears the search while leaving the cursor in place.

**Right-pane reset:** when the right pane loads a new view / rows / dataset, it starts at the top instead of keeping a stale scroll or active row. Identity is repo + pane kind + graph contents (commit-id window) + commit-file list key. A new graph dataset (repo switch, first paint, or commit-id change that is not an autoload suffix) resets `graphCursor` to the first selectable row. Same-view rebuilds (width/theme re-segment, autoload older commits, identical window) keep the nearest index. Commit-file cursor already resets on a new list key / repo / `commitTreeMode`. Diff scroll resets when `focusRepo` / `focusPath` changes; `Ctrl-o` still uses `pendingScrollAnchorRef` to keep the hunk in view. The left workspace tree still restores by stable id (`focusIdRef`).

While the `?` help overlay is open, `/` is scoped to that overlay: it starts a help-local query (`helpSearchQuery`) that highlights matching help entries (every wrapped line of keys + description) with the same search background, without arming pane `searchMode`. `Esc` clears the help search first; a subsequent `Esc` (or `q` / `?`) closes help.
