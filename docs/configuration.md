# Configuration

## `.workspace-status-config.json`

Read from the resolved workspace root (CLI `-C` / `--workspace` > env `WS_STATUS_WORKSPACE` > process cwd), by `load_workspace_status_config` in `crates/workspace-status/src/config.rs`. A missing file means nothing is ignored and discovery uses the default depth.

`--plain` and `--json` read one workspace snapshot. See [snapshot.md](./snapshot.md).

```json
{
  "ignoredRepos": ["notes"],
  "maxDepth": 3,
  "defaultBranches": {
    "acme/acme-main": "develop"
  },
  "editor": "vim",
  "diffTool": "vimdiff"
}
```

| Key               | Required                   | Default                       | Meaning                                                                                        |
| ----------------- | -------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `ignoredRepos`    | yes (when the file exists) | `[]` when file is missing     | Repo paths relative to the workspace root to skip                                              |
| `maxDepth`        | no                         | `3`                           | Walk depth for primary `.git` dirs/gitfiles (dot dirs skipped; linked via `git worktree list`) |
| `defaultBranches` | no                         | `{}`                          | Map of workspace-relative repo path → sole default branch for that repo                        |
| `editor`          | no                         | unset (`vim` at resolve)      | Command string for TUI `e` (same shape as `$EDITOR`). Overrides `$VISUAL` / `$EDITOR`.         |
| `diffTool`        | no                         | unset (`vimdiff` at resolve) | Command string for TUI `E`. No `$EDITOR` / `$VISUAL` / `$GIT_EXTERNAL_DIFF` fallback.          |

### `ignoredRepos`

Entries are repo paths relative to the workspace root (`dotfiles`, `services/api`, `apps/web/packages/ui`). On load they are trimmed, path-normalized (strip leading `./`, trailing `/`, unify `\` to `/`), de-duplicated, and sorted — so `notes/`, `./notes`, and `notes` all match discovered `notes`. A malformed file throws rather than being ignored — a typo silently dropping repos from a status report is worse than a crash.

Ignored repos are skipped by discovery (the ignored path and everything under it), so they are excluded from status, fetch, pull, and default-branch switching. Ignoring a primary also drops its linked worktrees under that path; a linked path can be listed on its own in `ignoredRepos`. The TUI still discovers ignored repos so `.` can show them. While they are hidden (no `-a`, or after `.` hides), the tree also omits linked worktrees of an ignored primary even when that linked row is `ignored=false`. They return with `.` / `-a` as a nested family. Workspace-level `f` / `p` / `P` / `d` skip those paths while they are hidden; when ignored repos are shown (`.` or launch `-a`), they follow the same primary / focused-worktree rule as other visible rows. Background fetch (`WS_STATUS_FETCH_MS`) is not focus-scoped: it fetches every snapshot except hidden ignored (linked worktrees included; shown ignored included).

### `maxDepth`

Discovery has two stages:

1. **Directory walk** — under the workspace root, any directory with a `.git` directory or gitfile (some submodules / non-dot linked checkouts) counts as a **primary** repo, up to `maxDepth` path segments. Dot directories (e.g. `.worktrees/`) are **not** entered by the walk.
2. **Linked worktrees** — for each primary, `git worktree list --porcelain` adds other checkouts whose paths sit under the workspace cwd (typical layout: `app/.worktrees/<branch>`). Those rows get `checkoutKind: 'linked'`, a `🔗` marker, and optional merge-into-default marks (`✅` / `🌱`). `✅` is a strict ancestor of the default tip. HEAD equal to that tip is `🌱` (just created), not merged. The verbose dirty/clean column is **Files** (not “Worktree”).

| `maxDepth`    | Finds (walk)                | Example                |
| ------------- | --------------------------- | ---------------------- |
| `1`           | direct children only        | `dotfiles`             |
| `2`           | children + grandchildren    | `services/api`         |
| `3` (default) | through great-grandchildren | `apps/web/packages/ui` |

Nested repos under a parent repo are still discovered when depth allows (e.g. both `apps/web` and `apps/web/packages/ui`). Intermediate non-repo directories (like `packages`) are walked through. Values must be a positive integer; omit the key to keep the default of 3. Linked paths from `git worktree list` are not capped by `maxDepth` beyond “must be under cwd”.

### `defaultBranches`

Optional object mapping workspace-relative repo paths to a single default branch name (e.g. `"acme/acme-main": "develop"`). Keys are normalized like `ignoredRepos` (trim, strip `./`, unify separators). When a repo has an entry:

- Classification, summary Branches section, verbose ordering, and TUI branch markers / attention grouping treat **only** that branch as default (so `main` is non-default if the override is `develop`).
- `--default-branch` and TUI `d` switch to that branch (not `origin/HEAD`).

Repos without a key keep prior behaviour: classification still treats `main` / `master` / `develop` as default; switch target still comes from git (`origin/HEAD`, then those names).

### `editor`

Optional command string for TUI `e`, same shape as `$EDITOR` (`"vim"`, `"nvim"`, `"cursor"`, `"cursor --wait"`, `"code --wait"`). Not a closed list of names. `"cursor"` already opens at `path:line` via `-g`.

- Omit the key, or set `"editor": "vim"`, for **vim** (the default when `$VISUAL` / `$EDITOR` are also unset). vim takes the TTY. The TUI leaves the alternate screen and resumes the same fold, focus, and scroll.
- `"editor": "cursor"` opens Cursor IDE without changing the shell `$EDITOR`. Cursor / VS Code stay mounted, so fold, focus, and scroll do not rebuild.
- Non-blank config `editor` overrides `$VISUAL` / `$EDITOR` (order: config, `$VISUAL`, `$EDITOR`, `vim` — git's order). A detached GUI editor that fails to start shows `edit failed: <cmd>: <error>`. Blank / whitespace-only is treated as unset (fall through). Non-string values throw.

### `diffTool`

Optional command string for TUI `E`. Same argv shape as `editor`. Default is **vimdiff** when the key is omitted or blank. There is no `$EDITOR` / `$VISUAL` / `$GIT_EXTERNAL_DIFF` fallback. This is not `git difftool`. The TUI builds LEFT and RIGHT and runs the command.

Copy-paste samples:

```json
"diffTool": "vimdiff"
```

```json
"diffTool": "cursor --diff --wait"
```

```json
"diffTool": "code --diff --wait"
```

If the string contains `$LOCAL` or `$REMOTE` (git-difftool style), those tokens become LEFT and RIGHT. If neither placeholder is present, LEFT then RIGHT are appended after the parsed argv.

For a workspace-tree file, LEFT is `HEAD:path` when that path exists in HEAD. Untracked or newly added (not in HEAD): LEFT is an empty temp. Deleted worktree file: RIGHT is an empty temp. This is worktree vs HEAD even when the change is staged-only.

Commit and stash file rows: LEFT is the first-parent blob (`rev^:path`), or an empty temp if the path was added. RIGHT is the blob at that rev in a temp (not the worktree file).

- Omit the key, or set `"diffTool": "vimdiff"`, for **vimdiff**. vimdiff takes the TTY. The TUI leaves the alternate screen and resumes the same fold, focus, and scroll. Temps for that session are deleted after vimdiff exits.
- `"diffTool": "cursor --diff --wait"` and `"diffTool": "code --diff --wait"` spawn detached. Cursor / VS Code stay mounted. A worker waits for that child and deletes only that session's temps. `--wait` keeps the CLI process alive until the diff tab closes. Without `--wait`, Cursor and VS Code return in a few seconds. The worker then deletes the LEFT HEAD temp while the IDE still opens the files. The same `--wait` rule applies on macOS Cursor and on WSL2 with Windows Cursor. A later `E` does not delete files still open in another GUI.
- Temps live under `$TMPDIR/workspace-status-ext-diff/<pid>-<nanos>/`. A crash may leave a session directory. Later `E` does not sweep other sessions.
- Non-blank config `diffTool` is used as-is. Blank / whitespace-only is treated as unset (vimdiff). Non-string values throw.

| Override              | Effect                                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `-a` / `--all`        | `ignoredRepos` is replaced with `[]` for that run; `maxDepth` / `defaultBranches` / `editor` / `diffTool` from config are kept                                                                                |
| Positional repo paths | Only those repos are processed, and they bypass `ignoredRepos` entirely. Naming a primary includes its linked children under cwd; naming a linked path (e.g. `app/.worktrees/feat`) includes only that path. |

The two overrides differ in the TUI. `-a` replaces the ignored list before the TUI sees it, so the ignored set is empty and the surfaced repos render and fold like any other repo — expanded, no muted name, no ignored glyph. Positional paths leave the loaded config intact, so a named repo that is also in `ignoredRepos` renders with a muted name plus the ignored glyph and starts collapsed.

### Theme flash tokens

Each built-in palette keeps three four-step flash ramps. Accents mix toward `surface` so the row stays readable.

| Kind | Peak / ramp | Accent source |
| --- | --- | --- |
| Add | `flash` / `flash_ramp` | `added` |
| Update | `flash_update` / `flash_update_ramp` | `modified` |
| Remove | `flash_remove` / `flash_remove_ramp` | `deleted` |

`flash_bg(strength)` is the add ramp (compat). `flash_bg_for(kind, strength)` selects the ramp. Index 0 of each ramp equals that kind's peak. Fetch / pull / push / default-branch chrome uses update. Tokyo Night peaks: add `#516643` (`Rgb(81, 102, 67)`), update `#6d5942` (`Rgb(109, 89, 66)`), remove `#774152` (`Rgb(119, 65, 82)`).

### Version-1 persist upgrade

`comments.json` and `viewed-files.json` share one default path per machine. A version-1 file has a flat `entries` field. It has no workspace id. Persist writes version 2 and keeps those records under `workspaces.__legacy__`. Save of the current workspace inserts only that workspace bucket. It does not replace `__legacy__`. Load uses the current workspace bucket when that key exists. Otherwise it uses `__legacy__`. GC of one cwd does not drop `__legacy__`. Opening a second folder after upgrade must not delete or steal the first folder's comments or viewed marks.

**Graph + commit files:** focusing a repo/dir at depth 0 shows the multi-branch commit graph in the right pane; depth 1 left is the same graph list and depth 1 right is commit meta + file tree; depth 2 is commit files | diff. Left-pane movement at every depth reloads the right pane (`load_right`). Graph lane colours follow the active built-in theme (`T` cycles); no new env var. Autoload window size defaults to 300, not user-configurable. Commit file trees default to directory tree via dedicated `commit_tree_mode` (independent of workspace `tree_mode`).

## Nerd Font requirement

The TUI needs a patched **Nerd Font**. File-type devicons and the git/folder glyphs all live in the Unicode private-use area; without one they render as tofu boxes. Recommended: **MesloLGS NF** (romkatv/powerlevel10k-media). Do not use MesloLGM Nerd Font Mono in xfce4-terminal — VTE sizes cells off the widest Nerd glyph and letter-spaces ASCII.

`visible_width` counts private-use codepoints as width 1 and every pane width is computed from that assumption. For the same reason, icon tables must never gain emoji or CJK codepoints; those are double-width. Plain-report badges stay emoji, because the report is not laid out in columns.

`WS_STATUS_GLYPHS=ascii` is the escape hatch when no Nerd Font is available. Do not set it when MesloLGS NF is installed.

VS Code and Cursor resolve the terminal font on the client, independently of the system terminal. Set it in **User Settings**, not the WSL Machine settings:

```json
"terminal.integrated.fontFamily": "'MesloLGS NF', monospace"
```

A missing Nerd Font only affects glyphs. It does not change which keys the terminal sends.

## Alternate screen

The TUI uses the terminal alternate screen (DEC 1049) while it is mounted. Normal quit writes leave sequences and shows the cursor. `SIGKILL` (`kill -9`) cannot run those hooks. After SIGKILL, reset the terminal if the primary buffer stays hidden.

## PageUp and PageDown on macOS

PageUp and PageDown page the focused pane when the terminal sends the key to the process (crossterm `PageUp` / `PageDown`, including CSI `ESC [5~` / `ESC [6~`).

On many macOS setups there is no dedicated PageUp key. `Fn+Up` and `Fn+Down` often scroll the terminal scrollback and never reach the TUI. Use `Ctrl-u` / `Ctrl-d` (±5 rows) when PageUp does not arrive.

## Theme tokens

Built-in palettes live in `crates/workspace-status/src/tui/theme.rs`. `WS_STATUS_THEME` seeds the first paint. `T` cycles the same list in this session. There is no theme file.

Unfocused pane borders use `palette.borderDim`. That token is a near-surface dark gray. It is darker than that theme's `muted`. Focused pane borders use `palette.heading`. Pane body text stays full brightness. The TUI does not DIM body text because a pane is unfocused. The selected row on an unfocused list keeps a thinner `▏` marker and `palette.cursorBgInactive` (between that theme's surface and `cursorBg`). The focused list still uses `▌` / `cursorBg`.

The viewport keeps the focused row near the vertical middle. Graph scrollbar drag still scrolls the viewport without moving the cursor. File-diff horizontal thumb drag pans without moving `diff_cursor`. **horizontal wheel** (and Shift-wheel) pans the pane under the pointer without moving the focused row, including the workspace tree. Trackpad hscroll is SGR `66`/`67`. The live loop enables click, button-event, and any-event (DECSET 1003) tracking, rxvt 1015, and SGR (`tui/tty.rs`). Some terminals add the motion bit to wheel reports under any-event tracking; the Unix reader decodes those as the plain wheel. The Unix reader otherwise decodes SGR, X10, and 1015 the same way as crossterm 0.28. The compare-tab `[✗]` paints in `palette.tabClose`, a neutral dark gray darker than `muted`. Pointer motion over it paints `palette.tabCloseHover` (red, the theme's `deleted` color, bold). The TUI redraws only when that hover changes. When a file diff has long lines, that report over the left pane pans the diff; short tree paths still pan the tree when the painted diff fits. Keyboard `h` / `l` still fold the tree. Drag the divider to resize. Drag the graph scrollbar thumbs or a file-diff horizontal thumb to scroll / pan; click the track to jump toward that position (`hit_split` / `SplitDrag`, same stack as the pane and in-diff splitters). Tree and commit-file lists pan with the wheel and keys only; they do not paint an h-bar. Graph and file-diff vertical bars are shown only after the list leaves the top; horizontal bars only after the viewport leaves the left edge.

Drag inside a pane body to select text. The selection paints in reverse video and stays inside the pane where the press landed. It never takes the other pane, the box borders, the tab strip, or the status rows. Release copies the selected text: OSC 52 first, then `wl-copy`, `xclip`, or `pbcopy`, and the breadcrumb shows `copied`. Trailing spaces on each row are dropped. Only the visible text is copied; the pane does not scroll while you drag. A plain click selects nothing. A terminal that does not honor OSC 52 needs one of those host tools. Inside tmux, OSC 52 needs `set-clipboard on`. Native terminal selection still works with Shift-drag (Option+drag in iTerm2), or press `m` to turn mouse capture off.

Search (`/`) matches against a row's plain `label` (case-insensitive substring) and jumps the cursor; it does **not** hide or filter rows. Match rows get a search background highlight. `n` / `N` wrap through matches; `Esc` clears the search while leaving the cursor in place.

**Right-pane reset:** when the right pane loads a new view / rows / dataset, it starts at the top instead of keeping a stale scroll or active row. Identity is repo + pane kind + graph contents (commit-id window) + commit-file list key. A new graph dataset (repo switch, first paint, or commit-id change that is not an autoload suffix) resets `graph_cursor` to the first selectable row. Same-view rebuilds (width/theme re-segment, autoload older commits, identical window) keep the nearest index. A new commit-file list key / repo / source resets the file-list cursor and `right_col_offset`. A file-diff viewport (`diff_cursor`, `diff_scroll`, `diff_col_offset`) belongs to one view identity: workspace `repo`+`path`, or commit `repo`+source+`path`. Opening a different file, or a commit diff for the same path, resets vertical and horizontal offsets to the origin. A same-view reload keeps them. `Ctrl-o` still recenters on the prior hunk. The left workspace tree still restores by stable id.

While the `?` help overlay is open, `/` is scoped to that overlay: it starts a help-local query (`helpSearchQuery`) that highlights matching help entries with the same search background, without hiding rows and without arming pane `searchMode`. Characters including `n`/`N` append to the query. There is no Enter-arm and no next/prev wrap in help. `Esc` clears the help search first; a subsequent `Esc` (or `q` / `?` with no query) closes help.
