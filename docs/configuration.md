# Configuration

Precedence for a setting: CLI flag > environment variable > config file > built-in default.

The TUI theme has one more step: the last-used theme (kept in the UI-state file that Enter on a palette `Theme: <name>` row writes) sits between `WS_STATUS_THEME` and config `theme`. See [`WS_STATUS_UI_STORE`](#environment-variables). Then `themeMode` may swap the resolved theme for its light or dark twin at launch. See [`WS_STATUS_THEME_MODE`](#environment-variables).

An env value that the env parser accepts wins. An env value that it ignores (unset, blank, unknown, or non-numeric) falls through to the config value, then to the default. With no config keys set, each env var works as before. The binary resolves these settings once at startup, before the TUI-startup update check and the first git call (`crates/workspace-status/src/settings.rs`). `--plain` and `--json` use them too (`git`, `fetchConcurrency`).

## Config files

Two files use the same keys, except that `git`, `updateCheckStore`, `commentStore`, `viewedStore`, and `uiStore` are user file only (see [Env-backed keys](#env-backed-keys)). `load_workspace_status_config` in `crates/workspace-status/src/config.rs` reads both and merges them.

| File | Path | Role |
| --- | --- | --- |
| User file | `$XDG_CONFIG_HOME/my-workspace-status/config.json`. When `XDG_CONFIG_HOME` is unset or blank: `~/.config/my-workspace-status/config.json` | Your settings for every workspace |
| Workspace file | `.workspace-status-config.json` in the resolved workspace root (CLI `-C` / `--workspace` > env `WS_STATUS_WORKSPACE` > process cwd) | Settings for this workspace |

Merge rules:

- A missing file sets nothing. With neither file, nothing is hidden or ignored and discovery uses the default depth.
- A file that exists but cannot be read is an error in both files, not a missing file: `<file>: <io error>` (no permission, a directory), or `<file>: symlink target is missing: <io error>` for a dangling symlink.
- A user or workspace file that is not valid JSON, or whose top level is not an object, is an error: `<file> is not a valid JSON object: <parser message>`.
- The workspace file wins per top-level key. A key that the workspace file omits keeps the user file value.
- `viewDefaults` and `defaultBranches` merge per sub-key. The workspace sub-key wins.
- Arrays are replaced, not joined. A workspace `hiddenPaths` or `ignoredPaths` (also `[]`) replaces the user list of the same name.
- A `null` value, and a blank `editor` / `diffTool`, count as omitted, so the user file value applies.
- Both files are strict. An invalid user file fails the same way as an invalid workspace file. The error starts with the file: the full path for the user file, `.workspace-status-config.json` for the workspace file. Example: `~/.config/my-workspace-status/config.json maxDepth must be a positive integer` (with your real home path).
- `hiddenPaths` and `ignoredPaths` are optional in both files. An omitted or `null` key sets nothing. A wrong type is an error in both files.
- The old key `ignoredRepos` (any value, also `null`) is an error in both files. See [Migrating from `ignoredRepos`](#migrating-from-ignoredrepos).
- Nothing writes either file.

PTY e2e, desktop e2e, and `scripts/capture-demo-stills.sh` point `XDG_CONFIG_HOME` at a temp dir, so a user file cannot change their results. The PTY and desktop harnesses write a fixed baseline user file there (theme and `viewDefaults.background`, see [tui-tty-e2e.md](tui-tty-e2e.md)); the capture script leaves it empty unless its `WS_STATUS_STILLS_THEME` / `WS_STATUS_STILLS_BACKGROUND` knobs write `theme` / `viewDefaults.background` there (see [demo.md](demo.md)). CI guards those TTY spawn paths only: `tty_spawn_paths_isolate_user_config` in `crates/workspace-status/tests/release_watch.rs`. The CLI integration tests that run the binary (`snapshot_contract.rs`, `update.rs`, `seed_demo_workspace.rs`) also set `XDG_CONFIG_HOME`, but no CI guard checks them.

## `.workspace-status-config.json`

The keys below apply to both files. A missing file means nothing is hidden or ignored and discovery uses the default depth.

`--plain` and `--json` read one workspace snapshot. See [snapshot.md](./snapshot.md).

```json
{
  "hiddenPaths": ["notes", "dotfiles"],
  "ignoredPaths": ["tmp", "vendor/archive"],
  "maxDepth": 3,
  "defaultBranches": {
    "acme/acme-main": "develop"
  },
  "editor": "vim",
  "diffTool": "vimdiff",
  "viewDefaults": {
    "tree": "tree",
    "diff": "split",
    "wrap": "unwrap"
  },
  "theme": "dracula",
  "themeMode": "auto",
  "glyphs": "nerd",
  "watchMs": 3000,
  "fetchMs": 300000,
  "fetchConcurrency": 10,
  "updateCheck": true,
  "termProgress": true,
  "smoothScroll": true,
  "prPolling": true
}
```

User file only (a workspace file that sets these keys fails to load):

```json
{
  "updateCheckStore": "~/.local/state/my-workspace-status/update-check.json",
  "commentStore": "~/.local/state/my-workspace-status/comments.json",
  "viewedStore": "~/.local/state/my-workspace-status/viewed-files.json",
  "uiStore": "~/.local/state/my-workspace-status/ui-state.json",
  "git": "/usr/bin/git",
  "prTitleCommand": "~/bin/pr-title"
}
```

| Key               | Required                           | Default                      | Meaning                                                                                        |
| ----------------- | ---------------------------------- | ---------------------------- | ---------------------------------------------------------------------------------------------- |
| `hiddenPaths`     | no                                 | `[]` when no file sets it    | Paths relative to the workspace root whose repos are hidden until `.` or `-a`                  |
| `ignoredPaths`    | no                                 | `[]` when no file sets it    | Paths relative to the workspace root whose repos are never shown, unless named on the CLI      |
| `maxDepth`        | no                                 | `3`                          | Walk depth for primary `.git` dirs/gitfiles (dot dirs skipped; linked via `git worktree list`) |
| `defaultBranches` | no                                 | `{}`                         | Map of workspace-relative repo path → sole default branch for that repo                        |
| `editor`          | no                                 | unset (`vim` at resolve)     | Command string for TUI `e` (same shape as `$EDITOR`). Overrides `$VISUAL` / `$EDITOR`.         |
| `diffTool`        | no                                 | unset (`vimdiff` at resolve) | Command string for TUI `E`. No `$EDITOR` / `$VISUAL` / `$GIT_EXTERNAL_DIFF` fallback.          |
| `viewDefaults`    | no                                 | `{}` (in-app defaults)       | TUI launch view modes. See [`viewDefaults`](#viewdefaults)                                     |
| `theme`, `themeMode`, `glyphs`, `watchMs`, `fetchMs`, `fetchConcurrency`, `updateCheck`, `termProgress`, `smoothScroll`, `prPolling` | no | the env var default | Same settings as the env vars. See [Env-backed keys](#env-backed-keys) |
| `updateCheckStore`, `commentStore`, `viewedStore`, `uiStore`, `git`, `prTitleCommand` | no; user file or env only | the env var default | Same settings as the env vars. See [Env-backed keys](#env-backed-keys) |

### `hiddenPaths` and `ignoredPaths`

Both keys hold paths relative to the workspace root. Each entry is a repo folder (`dotfiles`, `services/api`) or a folder that holds repos (`tmp`). A repo matches when its path equals the entry or sits under it, by whole path segments: `tmp` matches `tmp` and `tmp/a/b`, never `tmpfoo`. A bare repo name is not matched at any depth.

On load, entries are trimmed, path-normalized (strip leading `./`, trailing `/`, unify `\` to `/`), de-duplicated, and sorted. `notes/`, `./notes`, and `notes` are the same entry.

An entry that starts with `/`, `\`, or `~`, starts with a drive letter (`C:`), or has a `..` segment fails startup:

```text
<file> <key> entries must be paths relative to the workspace root, without `..` (got "<entry>")
```

A value that is not a string array fails with `<file> <key> must be a string array`. A typo that silently drops repos from a status report is worse than a crash.

| Key | Repos at or under an entry | Shown by `.` / `-a` |
| --- | --- | --- |
| `hiddenPaths` | Discovered, but hidden by default. Out of the tree, `--plain` / `--json`, search, and workspace-level fetch, pull, and default-branch switching until shown. | Yes |
| `ignoredPaths` | Never discovered, shown, fetched, pulled, or switched, unless named on the command line. Linked worktrees at or under an entry are dropped too. | No |

When a path is under both lists, `ignoredPaths` wins. A repo named on the command line (`ws tmp/foo`) is shown even under either list.

Hidden repos behave like this:

- The TUI discovers them so `.` can show them. While hidden (no `-a`, or after `.` hides), the tree also omits linked worktrees of a hidden primary, even when that linked row is `hidden=false`. They return with `.` / `-a` as a nested family.
- Workspace-level `f` / `p` / `P` / `d` skip hidden paths. When hidden repos are shown (`.` or launch `-a`), they follow the same primary / focused-worktree rule as other visible rows.
- Background fetch (`WS_STATUS_FETCH_MS`) is not focus-scoped. It fetches every snapshot except hidden ones (linked worktrees included; shown hidden repos included).

Example with both keys:

```json
{
  "hiddenPaths": ["notes", "dotfiles"],
  "ignoredPaths": ["tmp", "vendor/archive"]
}
```

#### Migrating from `ignoredRepos`

Breaking change. The key `ignoredRepos` is removed. Any `ignoredRepos` key (also `null`) in the user file or the workspace file fails startup:

```text
<file> ignoredRepos is no longer supported: use hiddenPaths (hidden by default) or ignoredPaths (never shown)
```

- Rename `ignoredRepos` to `hiddenPaths`. Behavior is the same, except that entries now match by path segment and must be relative paths.
- Add `ignoredPaths` for folders whose repos must never show.
- `hiddenPaths` is optional. Omit it when nothing is hidden.
- `--json` snapshot version 2 renames `showIgnored`, `ignoredRepos`, and `ignored` to `showHidden`, `hiddenPaths`, and `hidden`. See [snapshot.md](./snapshot.md).

### `maxDepth`

Discovery has two stages:

1. **Directory walk** — under the workspace root, any directory with a `.git` directory or gitfile (some submodules / non-dot linked checkouts) counts as a **primary** repo, up to `maxDepth` path segments. Dot directories (e.g. `.worktrees/`) are **not** entered by the walk.
2. **Linked worktrees** — for each primary, `git worktree list --porcelain` adds other checkouts whose paths sit under the workspace cwd (typical layout: `app/.worktrees/<branch>`). Those rows get `checkoutKind: 'linked'`, a `🔗` marker, and optional merge-into-default marks (`✅` / `🌱`). `✅` is a strict ancestor of the default tip. HEAD equal to that tip is `🌱` (just created), not merged. The verbose dirty/clean column is **Files** (not “Worktree”).

| `maxDepth`    | Finds (walk)                | Example                |
| ------------- | --------------------------- | ---------------------- |
| `1`           | direct children only        | `dotfiles`             |
| `2`           | children + grandchildren    | `services/api`         |
| `3` (default) | through great-grandchildren | `apps/web/packages/ui` |

Nested repos under a parent repo are still discovered when depth allows (e.g. both `apps/web` and `apps/web/packages/ui`). Intermediate non-repo directories (like `packages`) are walked through. Values must be a positive integer; omit the key to keep the default of 3. Linked paths from `git worktree list` are not capped by `maxDepth` beyond “must be under cwd”.

### `defaultBranches`

Optional object mapping workspace-relative repo paths to a single default branch name (e.g. `"acme/acme-main": "develop"`). Keys are normalized like `hiddenPaths` (trim, strip `./`, unify separators). When a repo has an entry:

- Classification, summary Branches section, verbose ordering, and TUI branch markers / attention grouping treat **only** that branch as default (so `main` is non-default if the override is `develop`).
- `--default-branch` and TUI `d` switch to that branch (not `origin/HEAD`).

Repos without a key keep prior behaviour: classification still treats `main` / `master` / `develop` as default; switch target still comes from git (`origin/HEAD`, then those names).

### `editor`

Optional command string for TUI `e`, same shape as `$EDITOR` (`"vim"`, `"nvim"`, `"cursor"`, `"cursor --wait"`, `"code --wait"`). Not a closed list of names. `"cursor"` already opens at `path:line` via `-g`.

- Omit the key, or set `"editor": "vim"`, for **vim** (the default when `$VISUAL` / `$EDITOR` are also unset). vim takes the TTY. The TUI leaves the alternate screen and resumes the same fold, focus, and scroll.
- `"editor": "cursor"` opens Cursor IDE without changing the shell `$EDITOR`. Cursor / VS Code stay mounted, so fold, focus, and scroll do not rebuild.
- Non-blank config `editor` overrides `$VISUAL` / `$EDITOR` (order: config, `$VISUAL`, `$EDITOR`, `vim` — git's order). A detached GUI editor that fails to start shows `edit failed: <cmd>: <error>`. Blank / whitespace-only is treated as unset (fall through). Non-string values throw.

### `diffTool`

Optional command string for TUI `E`. Same argv shape as `editor`. Default is **vimdiff** when the key is omitted or blank. There is no `$EDITOR` / `$VISUAL` / `$GIT_EXTERNAL_DIFF` fallback. This is not `git difftool`. The TUI builds LEFT and RIGHT and runs the command.

Copy-paste samples:

```json
"diffTool": "vimdiff"
```

```json
"diffTool": "cursor --diff --wait"
```

```json
"diffTool": "code --diff --wait"
```

If the string contains `$LOCAL` or `$REMOTE` (git-difftool style), those tokens become LEFT and RIGHT. If neither placeholder is present, LEFT then RIGHT are appended after the parsed argv.

For a workspace-tree file, LEFT is `HEAD:path` when that path exists in HEAD. Untracked or newly added (not in HEAD): LEFT is an empty temp. Deleted worktree file: RIGHT is an empty temp. This is worktree vs HEAD even when the change is staged-only.

Commit and stash file rows: LEFT is the first-parent blob (`rev^:path`), or an empty temp if the path was added. RIGHT is the blob at that rev in a temp (not the worktree file).

- Omit the key, or set `"diffTool": "vimdiff"`, for **vimdiff**. vimdiff takes the TTY. The TUI leaves the alternate screen and resumes the same fold, focus, and scroll. Temps for that session are deleted after vimdiff exits.
- `"diffTool": "cursor --diff --wait"` and `"diffTool": "code --diff --wait"` spawn detached. Cursor / VS Code stay mounted. A worker waits for that child and deletes only that session's temps. `--wait` keeps the CLI process alive until the diff tab closes. Without `--wait`, Cursor and VS Code return in a few seconds. The worker then deletes the LEFT HEAD temp while the IDE still opens the files. The same `--wait` rule applies on macOS Cursor and on WSL2 with Windows Cursor. A later `E` does not delete files still open in another GUI.
- Temps live under `$TMPDIR/workspace-status-ext-diff/<pid>-<nanos>/`. A crash may leave a session directory. Later `E` does not sweep other sessions.
- Non-blank config `diffTool` is used as-is. Blank / whitespace-only is treated as unset (vimdiff). Non-string values throw.

| Override              | Effect                                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `-a` / `--all`        | `hiddenPaths` is replaced with `[]` for that run, whichever file set it; `ignoredPaths` is kept; `maxDepth` / `defaultBranches` / `editor` / `diffTool` / `viewDefaults` from config are kept                                                                                |
| Positional repo paths | Only those repos are processed, and they bypass `hiddenPaths` and `ignoredPaths` entirely. Naming a primary includes its linked children under cwd, except linked worktrees at or under an `ignoredPaths` entry; naming a linked path (e.g. `app/.worktrees/feat`) includes only that path. |

The two overrides differ in the TUI. `-a` replaces the hidden list before the TUI sees it, so the hidden set is empty and the surfaced repos render and fold like any other repo — expanded, no muted name, no hidden glyph. Positional paths leave the loaded config intact, so a named repo that is also under `hiddenPaths` renders with a muted name plus the hidden glyph and starts collapsed.

### Env-backed keys

These top-level keys set the same settings as the env vars in [Environment variables](#environment-variables). A valid env var wins over the key.

| Key | Env var | Value |
| --- | --- | --- |
| `theme` | `WS_STATUS_THEME` | one of `"tokyo-night"`, `"monokai"`, `"dracula"`, `"gruvbox-dark"`, `"catppuccin-mocha"`, `"slate"`, `"solarized-dark"`, `"nord"`, `"rose-pine"`, `"kanagawa"`, `"everforest"`, `"one-dark"`, `"github-dark-dimmed"`, or a light twin: `"tokyo-night-day"`, `"monokai-light"`, `"dracula-light"`, `"gruvbox-light"`, `"catppuccin-latte"`, `"slate-light"`, `"solarized-light"`, `"nord-light"`, `"rose-pine-dawn"`, `"kanagawa-lotus"`, `"everforest-light"`, `"one-light"`, `"github-light"` |
| `themeMode` | `WS_STATUS_THEME_MODE` | `"auto"` \| `"dark"` \| `"light"` |
| `glyphs` | `WS_STATUS_GLYPHS` | `"nerd"` \| `"ascii"` |
| `watchMs` | `WS_STATUS_WATCH_MS` | integer >= 0. `0` turns the poll off. `1` to `499` clamp up to `500`, like the env var |
| `fetchMs` | `WS_STATUS_FETCH_MS` | integer >= 0. `0` turns the background fetch off. `1` to `29999` clamp up to `30000`, like the env var |
| `fetchConcurrency` | `WS_STATUS_FETCH_CONCURRENCY` | integer >= 1 |
| `updateCheck` | `WS_STATUS_UPDATE_CHECK` | `true` \| `false`. `false` turns the TUI-startup release check off |
| `termProgress` | `WS_STATUS_TERM_PROGRESS` | `true` \| `false`. `false` turns the OSC 9;4 terminal progress off |
| `smoothScroll` | `WS_STATUS_SMOOTH_SCROLL` | `true` \| `false`. `false` makes Ctrl-d / Ctrl-u jump instead of glide |
| `prPolling` | `WS_STATUS_PR_POLL_MS` | `true` \| `false`. `false` turns PR polling off. The env var sets a period instead (`0` is off); a valid env value wins over this key |
| `updateCheckStore` | `WS_STATUS_UPDATE_CHECK_STORE` | path. User file or env only |
| `commentStore` | `WS_STATUS_COMMENT_STORE` | path. User file or env only |
| `viewedStore` | `WS_STATUS_VIEWED_STORE` | path. User file or env only |
| `uiStore` | `WS_STATUS_UI_STORE` | path. User file or env only |
| `git` | `WORKSPACE_STATUS_GIT` | path, or a command name without `/` (looked up on `PATH`). User file or env only |
| `prTitleCommand` | `WS_STATUS_PR_TITLE_CMD` | path, or a command name without `/` (looked up on `PATH`). User file or env only |

`updateCheckStore`, `commentStore`, `viewedStore`, `uiStore`, `git`, and `prTitleCommand` are allowed only in the user file (or the env var), because a workspace file can be committed to a repo and must not pick a program to run or a file to write. A workspace file that sets one fails to load: `.workspace-status-config.json git is only allowed in the user config file (<user file path>) or WORKSPACE_STATUS_GIT`. `null` counts as omitted and is allowed.

- Values are strict, like `viewDefaults`. A wrong type, an unknown value, a blank string, or a fraction is an error that names the file, the key, and the allowed values. Example: `.workspace-status-config.json glyphs must be "nerd" or "ascii"`. String values are trimmed, then matched case-sensitively.
- A path must be absolute or start with `~/`. `~/` expands with `$HOME`. A relative path is an error: `<file> commentStore must be an absolute path or a path that starts with ~/`. When `$HOME` is unset, a `~/` path is an error.
- `git` and `prTitleCommand` also accept a bare command name (`"git"`). A relative path with `/` (`"bin/git"`) is an error.
- `null` counts as omitted, so the user file value or the default applies.
- Env-only settings have no key: see the **Config key** column in [Environment variables](#environment-variables).

### `viewDefaults`

Optional object. It sets the TUI view modes at launch. Each key is optional. An omitted object or key keeps the in-app default. Toggle keys still change the current session only. Nothing writes this file.

```json
"viewDefaults": {
  "tree": "flat",
  "commitTree": "tree",
  "diff": "inline",
  "wrap": "unwrap",
  "commitMessage": "collapse",
  "commitMessageLines": 12,
  "lineBlame": "hide",
  "background": "terminal"
}
```

| Key                  | Values                 | In-app default | Session toggle               |
| -------------------- | ---------------------- | -------------- | ---------------------------- |
| `tree`               | `tree` \| `flat`       | `tree`         | `t` at workspace depth 0     |
| `commitTree`         | `tree` \| `flat`       | `tree`         | `t` at depth ≥ 1             |
| `diff`               | `split` \| `inline`    | `split`        | `i`                          |
| `wrap`               | `wrap` \| `unwrap`     | `wrap`         | `\`                          |
| `commitMessage`      | `expand` \| `collapse` | `expand`       | `M`                          |
| `commitMessageLines` | integer `1` to `20`    | `4`            | palette (no key); drag (saved) |
| `lineBlame`          | `show` \| `hide`       | `show`         | `B`                          |
| `background`         | `paint` \| `terminal`  | `paint`        | —                            |

- String values are trimmed, then matched case-sensitively.
- A string key with a value of the wrong type, an unknown value, or a blank value is an error: `<file> viewDefaults.<key> must be "<a>" or "<b>"`. `<file>` is `.workspace-status-config.json` for the workspace file, or the full path of the user file. A `viewDefaults` that is not an object is an error. An unknown key inside it is an error that names the key. A typo never falls back silently.
- `commitMessageLines` is the number of message rows in the expanded commit-message footer (graph pane and commit-files pane). It must be a JSON integer from 1 to 20. A string, a fraction (`8.5`, also `8.0`), a bool, `null`, or a number out of range is an error: `<file> viewDefaults.commitMessageLines must be an integer from 1 to 20` (same `<file>` label). No key sets it: the Shorter / Taller commit message palette rows change it for the session only. A mouse drag of the footer's top rule changes it and saves it to the UI-state file (`WS_STATUS_UI_STORE`, key `commitMessageLines`), never to this config file. Launch order: a valid saved value, then this key, then 4.
- `"viewDefaults": null` counts as omitted.
- The config loads before the CLI picks a mode, so an invalid `viewDefaults` also fails `--plain` and `--json`. Valid values do not change that output.
- `background` picks who paints the pane and chrome backgrounds. `paint` fills them with theme colours. `terminal` keeps boxed panes with no fills, so the terminal background shows through. Popups sit on the theme panel colour in both modes. There is no session toggle and no env var.
- `commitTree` sets the commit file list in commit drills and in each new compare tab. A `t` toggle changes the current tab only. The next compare tab opens in the `commitTree` mode again.
- `-a` / `--all` and positional repo paths keep `viewDefaults`.
- `diff: "split"` does not force side-by-side in a narrow pane. The split to inline fallback below `NARROW_SXS` still applies (see **Defaults**).
- There are no keys for mouse, hidden-repo visibility, pane widths, or folds.

## Environment variables

| Variable | Config key | Default | Effect |
| --- | --- | --- | --- |
| `WS_STATUS_WORKSPACE` | — (it picks the workspace file) | unset (process cwd)                                     | Pin the workspace root used for config, discovery, and comment/viewed identity. Absolute or relative (relative to process cwd, then canonicalized). Blank / whitespace-only is unset. CLI `-C` / `--workspace` overrides this. Missing or non-directory path: error on stderr, exit 1; no silent fallback. `--update` and `--help` do not require a valid workspace. PTY e2e, desktop e2e, and `scripts/capture-demo-stills.sh` must unset this so the fixture cwd wins. CI: `crates/workspace-status/tests/release_watch.rs`. |
| `WS_STATUS_GLYPHS` | `glyphs` | unset                                                   | `ascii` replaces every Nerd Font glyph with a one-column ASCII marker (`tui/icons.rs`); the `?` icon legend shows the same marker. `nerd` keeps Nerd Font glyphs. Any other value is ignored and falls through to config `glyphs`.                                                                               |
| `NO_COLOR` | — (standard env var, [no-color.org](https://no-color.org)) | unset | Any non-empty value turns no-colour on for the new visuals only: the remote spinner and the commit-activity sparkline paint in the terminal foreground, a toast paints in reversed terminal colours with no fade, and the backdrop behind an open dialog is the DIM modifier instead of a colour mix, and commented code keeps a plain underline (no curly coloured one). An empty value is off. It is not a full monochrome TUI: themes, status letters, and diff colours stay. |
| `COLORTERM` | — (set by the terminal) | unset | `truecolor` or `24bit` (any case) turns on the curly coloured underline (SGR `4:3` + `58`) under the code of a line with an open comment, in the diff pane and the file view. Any other value, `NO_COLOR`, or `WS_STATUS_GLYPHS=ascii` keeps the plain underline every terminal shows. Read once at launch. |
| `WS_STATUS_WATCH_MS` | `watchMs` | `3000` (`DEFAULT_WATCH_MS`)                             | Live-refresh poll period. `0` disables the poll. Values below `MIN_WATCH_MS` (500) are clamped up. Non-numeric, negative, or empty falls through to config `watchMs`, then the default. File, graph, and commit-file rows flash (~800ms background fade) on add/update/remove of the same row identity. Add is green (`flash` / `flash_ramp`), update is amber (`flash_update` / `flash_update_ramp`), remove is red/magenta (`flash_remove` / `flash_remove_ramp`). Flash background wins over cursor and search. The cursor bar stays. File signatures use status letter or worktree `size:mtimeMs`. Chrome identity includes `HEAD`, `sync_note`, and the force-push text so a new local commit or ahead 2→3 reloads status / graph without `r`. The active file of an Explorer tab reads again when its `size:mtimeMs` or its git status moved. A disjoint identity set (repo switch / first paint) seeds and does not flash. The TUI polls local git only (no fetch) and keeps fold, focus, and scroll. Unchanged polls skip the right-pane `git log` / diff reload. The next tick is scheduled from the start of the interval, not after collect finishes. The live loop applies each checkout as it finishes; keys cannot starve the tick. |
| `WS_STATUS_FETCH_MS` | `fetchMs` | `300000` (`DEFAULT_FETCH_MS`)                           | Background `git fetch` period for the TUI. `0` disables. Values below `MIN_FETCH_MS` (30000) are clamped up when enabled. Non-numeric, negative, or empty falls through to config `fetchMs`, then the default. Instances in one workspace share the tick: see [Shared background fetch](#shared-background-fetch). The tick paints no progress or summary line. ### Theme flash tokens

Each built-in palette keeps three four-step flash ramps. On a dark theme each step is `surface` mixed 42%, 28%, 16%, then 8% toward the accent, so the row stays readable. A light theme's darkened accents would make that mix muddy, so its peak is a light tint of the accent hue (for add and remove, `diffAddWordBg` / `diffDelWordBg`), and the steps are `surface` mixed 100%, 70%, 40%, then 15% toward that peak.

| Kind | Peak / ramp | Accent source |
| --- | --- | --- |
| Add | `flash` / `flash_ramp` | `added` |
| Update | `flash_update` / `flash_update_ramp` | `modified` |
| Remove | `flash_remove` / `flash_remove_ramp` | `deleted` |

`flash_bg(strength)` is the add ramp (compat). `flash_bg_for(kind, strength)` selects the ramp. Index 0 of each ramp equals that kind's peak. Fetch / pull / push / default-branch chrome uses update. A PR change into CI failed or closed uses remove on the rows that show the checkout's PR (tree row, graph worktree row; on closed, the rows whose badge just went away); into ready to merge or merged, add. Tokyo Night peaks: add `#516643` (`Rgb(81, 102, 67)`), update `#6d5942` (`Rgb(109, 89, 66)`), remove `#774152` (`Rgb(119, 65, 82)`). Ack toasts fade through the add ramp too: `repo` text on step 0 while the toast holds, then down the ramp over its last `FLASH_MS` (800 ms, `tui/toast.rs`). `repo` keeps a 3:1 contrast on every step of every theme (`toast_text_meets_floor_on_every_flash_step`). PR change toasts hold on `panel` instead, where their state colours and `muted` keep 3:1 (`pr_toast_colors_meet_floor_on_the_panel`), and fade toward `surface` over the same 800 ms.

### Version-1 persist upgrade

`comments.json` and `viewed-files.json` share one default path per machine. A version-1 file has a flat `entries` field. It has no workspace id. Persist writes version 2 and keeps those records under `workspaces.__legacy__`. Save of the current workspace inserts only that workspace bucket. It does not replace `__legacy__`. Load uses the current workspace bucket when that key exists. Otherwise it uses `__legacy__`. GC of one cwd does not drop `__legacy__`. Opening a second folder after upgrade must not delete or steal the first folder's comments or viewed marks.

**Graph + commit files:** focusing a repo/dir at depth 0 shows the multi-branch commit graph in the right pane; depth 1 left is the same graph list and depth 1 right is the commit-file tree; depth 2 is commit files (with the commit-details footer under the list) | diff, and a focused folder there shows a summary of its changed files with line counts. Left-pane movement at every depth reloads the right pane (`load_right`). Graph lane colours follow the active built-in theme (palette `Theme: <name>` rows); no new env var. Autoload window size defaults to 300, not user-configurable. Commit file trees default to directory tree via dedicated `commit_tree_mode` (independent of workspace `tree_mode`).

### Shared background fetch

Several `ws` instances can watch one workspace. The scheduled background fetch runs once for that workspace, not once per instance. No env var or config key controls this.

- A tick fetches only when `fetchMs` is not `0`, no overlay pauses background ticks, the instance wins a non-blocking lock on the workspace claim, and the last background fetch for the workspace started at least that instance's own `fetchMs` ago (less 1 s of timer jitter). The interval counts from when that fetch started, not from when it ended, so the timer does not skip every second tick. A failed fetch still counts. A process that dies releases the lock.
- The outcome (a generation count, a failed flag, and the start time) is stored per workspace in `$XDG_STATE_HOME/my-workspace-status/background-fetch.json` (else `~/.local/state/my-workspace-status/background-fetch.json`). The claim lock is a sibling `*.claim.lock` file for each workspace.
- The instance that ran a failing fetch keeps its own line (`Fetched N repos (K failed: …)`). The other instances show the error `fetch failed`. A later successful background fetch clears that failure on every instance while it is still the shown status.
- Each outcome applies once. An instance applies outcomes on its live-refresh poll, so with `WS_STATUS_WATCH_MS=0` it does not show outcomes from other instances. An instance does not show an outcome recorded before it started.
- With `fetchMs` `0` an instance never fetches in the background, but it still shows outcomes from other instances.
- Manual `f` and the fetch at launch do not use the claim and do not write the record. The live-refresh poll, compare probes, PR lookups, and the update check also stay per instance.
- If the state directory cannot be used for the lock, the tick fetches as before, without sharing.

## Nerd Font requirement

The TUI needs a patched **Nerd Font**. File-type devicons and the git/folder glyphs all live in the Unicode private-use area; without one they render as tofu boxes. Recommended: **MesloLGS NF** (romkatv/powerlevel10k-media). Do not use MesloLGM Nerd Font Mono in xfce4-terminal — VTE sizes cells off the widest Nerd glyph and letter-spaces ASCII.

`visible_width` counts private-use codepoints as width 1 and every pane width is computed from that assumption. For the same reason, icon tables must never gain emoji or CJK codepoints; those are double-width. Plain-report badges stay emoji, because the report is not laid out in columns.

`WS_STATUS_GLYPHS=ascii` is the escape hatch when no Nerd Font is available. Do not set it when MesloLGS NF is installed.

VS Code and Cursor resolve the terminal font on the client, independently of the system terminal. Set it in **User Settings**, not the WSL Machine settings:

```json
"terminal.integrated.fontFamily": "'MesloLGS NF', monospace"
```

A missing Nerd Font only affects glyphs. It does not change which keys the terminal sends.

## Doctor setup checkup

The `:` palette row `Doctor: setup checkup` (aliases `doctor`, `checkup`, `setup`, `health`) opens a dialog that checks the setup the TUI needs. Each row has a status (`ok` / `warn` / `fail`), a name, what was found, and, when there is one, a hint and a fix line. The head shows `<n> ok · <n> warn · <n> fail`, or `checking…` while the probe runs.

The Doctor only reports. It does not change a file, a setting, the config, the theme, the UI-state file, or the environment. The probe reads environment variables, `PATH`, the config and state files, and runs only `<git> --version`, `rustc --version` (dev build), `tmux show-options -gv <option>` (inside tmux), and, in each loaded checkout, the read-only remote lookups `git config --get branch.<branch>.remote`, `git remote`, and `git remote get-url <remote>`. The one write is `y`, which copies the focused row's fix line to the clipboard (the same path as Copy entity reference).

Keys: `j` / `k` or arrows move, PgUp / PgDn and Ctrl-u / Ctrl-d move 5 rows, `g` / Home and `G` / End go to the first / last row, `y` copies the fix line (`no fix to copy` when the row has none), `r` runs the probe again, Esc / `q` close. Ctrl-c keeps its quit chord; other keys and the mouse do nothing while it is open.

Fix lines use the OS form: `export NAME=value` on Linux and macOS, `$env:NAME = "value"` in PowerShell on Windows. A program counts as found when the app could start it by that name: a name with a path separator is checked as a path, a bare name is looked up on `PATH` (on Windows as `<name>.exe`).

## Alternate screen

The TUI uses the terminal alternate screen (DEC 1049) while it is mounted. Normal quit writes leave sequences and shows the cursor. `SIGKILL` (`kill -9`) cannot run those hooks. After SIGKILL, reset the terminal if the primary buffer stays hidden.

## Pointer shape

With mouse capture on, the TUI asks the terminal for a resize pointer while the pointer rests on a resize edge or drags one: a left / right arrow (OSC 22 `ew-resize`) on the tree / right pane divider and the side-by-side diff rule, and an up / down arrow (`ns-resize`) on the top rule of the expanded commit-message footer. Leaving the edge, `m` (mouse off), `$EDITOR` or a blocking diff tool, quit, Ctrl-C, and a panic on the TUI thread put the default pointer back (`ESC ] 22 ; default ESC \`). A session that never rests on an edge writes no OSC 22.

Terminals that take CSS pointer names in OSC 22 show the arrow: kitty 0.31 and later, foot 1.12 and later, and Ghostty. Terminals without OSC 22, for example GNOME Terminal and other VTE terminals, and Alacritty, ignore the sequence. xterm and iTerm2 implement OSC 22 with X11 cursor names, so the arrow may not show there. tmux drops the sequence, so a session inside tmux shows no arrow. tmux `allow-passthrough` does not help: it forwards only sequences an app wraps in a tmux passthrough (`DCS tmux;`), and the TUI does not wrap OSC 22. The edge highlight shows in every terminal. There is no setting for the pointer shape.

## PageUp and PageDown on macOS

PageUp and PageDown page the focused pane when the terminal sends the key to the process (crossterm `PageUp` / `PageDown`, including CSI `ESC [5~` / `ESC [6~`).

On many macOS setups there is no dedicated PageUp key. `Fn+Up` and `Fn+Down` often scroll the terminal scrollback and never reach the TUI. Use `Ctrl-u` / `Ctrl-d` (±5 rows) when PageUp does not arrive.

## Theme tokens

Built-in palettes live in `crates/workspace-status/src/tui/theme.rs`: 13 dark themes, then a light twin of each with its own slug. The first paint uses a known `WS_STATUS_THEME`, else the last-used theme, else config `theme`, else Slate. Then `themeMode` (`WS_STATUS_THEME_MODE`, default `auto`) may swap it for its twin to match the terminal background. The command palette (`:`) has one `Theme: <name>` row per theme, in the order of the tables below (the 13 dark rows, then the 13 light rows). Moving the cursor onto a row, or typing until it is focused, previews that theme across the whole TUI. Enter applies it and saves it to the UI-state file (`WS_STATUS_UI_STORE`). Esc, or any other way the palette closes, puts back the theme active when it opened and saves nothing. A row matches `theme`, `color`, `colour`, its slug, or a word of its name. There is no theme key. The config file is never written.

Besides `surface` (the right pane and the Explorer file pane), each theme has three background roles. A theme can set each one; otherwise the default rule applies. Each mix is per RGB channel, `surface + (target - surface) × percent / 100`, rounded to the nearest integer.

| Role | Background of | Default rule |
| --- | --- | --- |
| `palette.sidebar` | Left pane (tree, graph, files list) | `surface` mixed 22% toward black |
| `palette.chrome` | Tab strip, breadcrumb, ctrl-c prompt, and key-chip footer rows | `surface` mixed 38% toward black |
| `palette.panel` | Popups | `surface` mixed 5% toward white |

Every text role meets its contrast floor on `surface`, `sidebar`, `chrome`, and `panel` (`theme.rs` tests), on light themes too. Monokai, Dracula, and Gruvbox Dark set a smaller `panel` lift (4%, 3%, 2% toward white) because the 5% rule drops their popup text below the floor. The default rule darkens and lightens a dark surface, so every light theme sets `sidebar`, `chrome`, and `panel` itself. Graph lane colours keep a 3:1 contrast on `sidebar` and `surface` on every theme (`lane_colors_meet_floor_on_sidebar_and_surface`); the light twins darken their upstream lane hues as far as that floor needs.

Behind an open dialog (help, confirm, pickers, Quick Open and the command palette, search in files) every cell outside the box recedes: its fg and bg mix 50% toward `surface` by the same rule. This backdrop is meant to recede, so it has no contrast floor; a `theme.rs` test checks the mix visibly moves `muted`, `file`, `sidebar`, and `chrome` on every theme. A non-RGB fg gets the DIM modifier instead. Under `NO_COLOR` the backdrop is the DIM modifier only.

In a narrow list the title keeps at least 16 columns: the reviews column drops first, then the stack mark, then the `CI ` text (the CI mark stays). A failing CLI shows `! glab (gitlab.com): <reason>` above the groups, and the PRs of other hosts still list. Finished groups start folded when more than 12 PRs list.
- Detail (`PR`, a third of the width, at least 40 columns): the focused PR's popover lines, every checkout that shows it, its repository, and its keys. Under 100 columns only one pane shows: `Tab` switches list and detail, Esc goes back to the list.
- Keys: `j` / `k` and the other move keys move; Enter or `gx` opens the PR, `gc` its CI page, `y` copies its URL, `o` shows its checkout in the Workspace tree, `z` folds or unfolds the group under the cursor, `Z` every finished group, `r` looks every PR up again, `gh` pins its popover, `Ctrl-w` closes the tab. In the `:` palette, Go to line (`:42`) and the Refresh row say `Switch to Workspace tab`; Refresh PRs looks the PRs up again.

Drag inside a pane body to select text. The selection paints in reverse video and stays inside the pane where the press landed. It never takes the other pane, the box borders, the tab strip, or the status rows. Search (`/`) matches against a row's plain `label` (case-insensitive substring) and jumps the cursor to the first match after the row where `/` opened, like vim `/`; it does **not** hide or filter rows. Match rows (tree, graph, commit files, and every matching file-diff row) get the filter pill's background with its foreground on the text. `n` / `N` step from the pane's current cursor row (first match after / before it) and wrap past the last or first match (the breadcrumb says `search wrapped to top` going forward, `search wrapped to bottom` going back); `Esc` on an armed search clears it while leaving the cursor in place. `Esc` while still typing puts the cursor back where `/` started.

**Right-pane reset:** when the right pane loads a new view / rows / dataset, it starts at the top instead of keeping a stale scroll or active row. Identity is repo + pane kind + graph contents (commit-id window) + commit-file list key. A new commit-file list key / repo / source resets the file-list cursor and `right_col_offset`. While the `?` help overlay is open, `/` is scoped to that overlay: it starts a help-local query (`helpSearchQuery`) that highlights matching help entries: their key chips and descriptions get the filter pill's background with its foreground on the text, the same pair as pane match rows, without hiding rows and without arming pane `searchMode`. ### Pull request badges

A checkout row with a branch (tree) and a worktree row with a branch (graph) show a badge when the branch has an open or a merged PR (GitHub PR or GitLab merge request) in one of six states: CI failed `✕`, ready to merge `◉` (mergeable now, with no failed or running check), CI running `◐`, draft `◌`, in review `○`, or merged `✓` (`WS_STATUS_GLYPHS=ascii`: `x`, `A`, `r`, `d`, `P`, `m`). In the tree the badge is `<ref> <glyph>` (`#318` on GitHub, `!12` on GitLab) at the end of the row's right-aligned trailing icons, so every glyph sits in the last column; a tree narrower than 50 columns shows the glyph alone. In the graph the glyph sits flush right on the worktree row, and the graph's branch header ends with the PR chip of its checkout (`✕ #318 CI failed  ▸ fix CI`). The workspace row ends with the PR total (`8 PRs · 2 need you`); a click on it opens the PRs tab (`gp`), which lists every PR in groups. A closed PR that was not merged, no PR, and a first lookup of the branch that failed or is still running show no badge. A known badge stays while a later lookup of it runs, and when that lookup fails; once its last successful lookup is older than twice the planned poll period it paints muted (stale). Glyphs, colours, and layout are in [tui-rust.md](./tui-rust.md) **Pull request badge**.

- Lookups use `gh` for GitHub hosts and `glab` for GitLab hosts. Install and log in to the CLI yourself (`gh auth login`, `glab auth login`). The TUI never asks for a login, and never passes a token. Without a working CLI there is no badge, and `gx` says `could not look up PR for <branch>: <reason>` (for example `gh not found`, the CLI's first error line, or `timed out after 20 s`; without a reason the text ends at the branch).
- A remote whose host contains neither `github` nor `gitlab` gets no badge, and `gx` says `no PR for <branch>`.
- A badge lookup runs when a branch first appears or changes, on `r`, on a full reload, and on each PR poll. A watch tick on the same branch does not look again. `gx` and Ctrl+click always look up fresh. A poll, `r`, and a full reload keep the badge while they look again and when the lookup fails; only no PR from a forge that answered, or a branch change, clears it.
- **PR polling.** One cycle for the whole TUI looks up each pollable checkout again. A checkout is pollable when it is visible (not hidden, unless hidden repos show), on a local branch, its remote is on GitHub or GitLab, and either its answer is an open PR, or its branch has an upstream and no PR is known yet (so a PR opened later shows without `r`). A merged PR is not polled. The cycle runs every 60 s while a pollable PR has CI running or is ready to merge, else every 180 s. `WS_STATUS_PR_POLL_MS` sets one period for both; `0`, or config `prPolling: false`, turns polling off. The lookup at launch is the first cycle. A checkout whose lookup is still queued or running is not queued again. While an overlay (help, a picker, the palette, a confirm) is open, the cycle waits. A pinned popover does not pause it: a pinned PR popover shows the new answer when it lands.
- **Failures.** A poll cycle in which every lookup on a forge host (for example `github.com`) fails doubles the period of that host: 60 s, then 120 s, 240 s, and so on, at most 15 min. Several failures in one cycle count once. A failure in a cycle in which another lookup on the same host succeeded does not count, in either landing order, so one repository that keeps failing (renamed, or access lost) does not slow the other badges on that host. The next successful lookup on that host resets it. A failed lookup keeps the last answer and records the CLI's first stderr line. The answer is stale when its last successful lookup is older than twice the planned period (hot or calm, without the backoff).
- **Changes.** Each successful lookup is compared with the last one of the same checkout in this session. When the same PR (same number) moves into CI failed, ready to merge, or merged, or the PR goes away (closed) while the branch stays, the TUI records a change for an alert. The first lookup of a checkout and the first lookup after a branch change record none. While the forge still computes the merge state (GitHub `mergeStateStatus: UNKNOWN`; GitLab `detailed_merge_status` `checking`, `unchecked`, `approvals_syncing`, or `preparing`, or on a GitLab server that sends no `detailed_merge_status`, `merge_status` `unchecked`, `checking`, or `cannot_be_merged_recheck`; for an open MR the MR call decides, the list only fills a field it leaves out), ready to merge versus in review is not final: such an answer records no change and is not compared with later, so a PR that flips between the two does not alert.
- The PR popover (hover or click a badge, or `gh`) is headed `<glyph> PR · <state>` (`PR · CI failed`). From the badge answer it shows at once the ref (bold), the next step (`▸ fix CI`, `▸ merge #318 first`, or `merged 3h ago`), the PR it is stacked on (`after #318 (CI failed)`), the notes (`has conflicts`, `unresolved threads`, `changes requested`), when the PR was last checked (`12m ago`; after a failed lookup, in amber, `12m ago · last lookup failed: <the CLI's first error line>`), and the URL. It fetches the PR's title, state, review, author, branches, checks (GitLab: `pipeline <status>`), up to two failed or running check names (`+N more`), the review count (GitHub `reviews 1 approved · REVIEW_REQUIRED`; GitLab `approvals 1 of 2`, green once the approval rules are met), and update time once per branch, with the same CLI (`gh pr view`, or `glab api` on the MR). It shows `loading…` until the answer lands and `could not load details` when the CLI fails. Under a rule it lists Open PR (`gx`), the CI page (`gc`, named by what it opens: `Open failed check`, `Open running check`, `Open checks`, or `Open pipeline`), Copy URL (`y`), and, unless the PR is merged, Refresh this PR (`r`). The `:` palette rows `Copy PR URL` and `Refresh this PR` do the same for the focused row's PR (they show no key chip: outside the popover `y` and `r` copy comments and refresh), and `Refresh PRs` looks every visible checkout with a GitHub or GitLab remote up again now; each keeps its badge while it looks. `r` means two things here. On a tree row it reloads the repo (`r`, Refresh): that drops the detail, so the next popover fetches it again. Inside a pinned PR popover it is Refresh this PR: it looks that PR up again, keeps the badge and the detail on screen, and fetches the detail again when the answer lands; it says `PR lookup already running` when a lookup of it is already out. A new answer for another PR drops the detail too. A changed answer for the same PR keeps the detail on screen and fetches it again: at once when a popover shows it or the active PRs tab lists it (when the badge answer lands), else at the next peek or pin. A change while a fetch is out fetches again when that fetch lands. A failed new fetch keeps the old detail.
